## 1. 运行时基线

| 项 | 选择 | 说明 |
|----|------|------|
| Node.js（开发） | 20 LTS（≥20.11） | Electron 内置 Node 版本以 Electron 为准 |
| Electron | **31.x**（≥31.3） | 需要 `MessageChannelMain`、`safeStorage`、`utilityProcess` 稳定支持 |
| TypeScript | 5.4+，`strict: true` | `noUncheckedIndexedAccess` 建议开 |
| 包管理器 | pnpm（推荐）或 npm | better-sqlite3 需在 `onlyBuiltDependencies` 白名单 |
| 目标平台 | Windows 10/11 x64（一级）、macOS 12+（二级）、Linux（尽力） | — |
| 构建 | **electron-vite** | 与 `electron.vite.config.ts` 对齐 |
| 打包 | electron-builder | 见第 6 节 |

**为什么要 Electron 31+**：`MessageChannelMain` 用于给录音样本开零拷贝通道；`safeStorage` 用于加密 API Key；`utilityProcess` 用于把 ffmpeg 之外的 Node 重活（如 embedding 预处理）移出主进程。

## 3. Electron 安全配置（必须照抄）

```ts
// main/bootstrap/window-manager.ts
new BrowserWindow({
  webPreferences: {
    // 必须 .cjs（不是 .js）：package.json 是 "type": "module"，.js 会被按 ESM 解析，
    // 而 sandbox: true 的 preload 只有受限的 CJS require、没有 ESM 能力。
    // electron.vite.config.ts 因此把 preload 产物定为 [name].cjs。
    preload: join(__dirname, '../preload/index.cjs'),
    contextIsolation: true,      // 必须
    nodeIntegration: false,      // 必须
    sandbox: true,               // 必须；若某能力必须关闭，单独论证并记录 ADR
    webSecurity: true,           // 必须
    allowRunningInsecureContent: false,
    spellcheck: false,
    backgroundThrottling: false  // 录音/波形绘制需要稳定帧率
  }
})
```

```ts
// main/index.ts 全局硬化
app.on('web-contents-created', (_e, contents) => {
  contents.setWindowOpenHandler(({ url }) => {
    if (/^https?:$/.test(new URL(url).protocol)) shell.openExternal(url)
    return { action: 'deny' }          // 禁止开新窗口
  })
  contents.on('will-navigate', (e, url) => {
    if (url !== expectedAppUrl) e.preventDefault()   // 禁止导航离开应用
  })
  contents.on('will-attach-webview', (e) => e.preventDefault())
})
```

**CSP（渲染进程）**：`default-src 'self'; script-src 'self' blob:; worker-src 'self' blob:; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob: ns-media:; media-src 'self' blob: ns-media:; connect-src 'self'`

> **`script-src` 里的 `blob:` 不是可有可无的**：采集用的 AudioWorklet 处理器从
> `Blob → URL.createObjectURL` 加载（`useRecorder.ts` 的 `loadPcmWorklet`），
> 少了 `blob:` → `audioWorklet.addModule` 被拦截 → **录音永远"没有声音"**，
> 而 Chromium 报的是 `AbortError`（看起来像用户取消），界面上不会指向 CSP。
> 真机事故：9 个录音会话全部 0 时长被 abort（docs/91 §5.2.40）。
> `unsafe-inline` / `unsafe-eval` 仍然禁止，`object-src 'none'` 不变。

**自定义协议**（音频文件访问）：
```ts
protocol.registerSchemesAsPrivileged([
  { scheme: 'ns-media', privileges: { standard: true, secure: true, supportFetchAPI: true, stream: true, bypassCSP: false } }
])
// handler 内：解析并校验路径必须位于 projectRoot/{projectId}/ 之下，拒绝 .. 与绝对路径逃逸
```

## 4. 原生模块 ABI 处理（最常见的坑）

`better-sqlite3` 和 `onnxruntime-node` 是原生模块，必须与 Electron 的 ABI 匹配。

```jsonc
// package.json
{
  "scripts": {
    // ⚠️ 故意**没有** postinstall（原因见本节末「两条被否决的做法」）。
    //
    // ⚠️ `npm run rebuild` 在 Windows 上会走到 node-gyp **编译 C++ 源码**，
    //    需要 Visual Studio Build Tools + Python。**这不是必须的** ——
    //    better-sqlite3 为 Electron 发布了预编译包，只是 electron-rebuild
    //    不会去用它。请优先用下面这条：
    "fetch:native-prebuild": "node --experimental-strip-types scripts/fetch-native-prebuild.ts",
    "check:native":          "node --experimental-strip-types scripts/check-native.ts",
    "rebuild":               "electron-rebuild -f -w better-sqlite3,onnxruntime-node"
  },
  "pnpm": { "onlyBuiltDependencies": ["better-sqlite3", "onnxruntime-node", "electron"] }
}
```

**装机顺序（照这个来，不需要编译工具链）**

```bash
npm install                              # 只装依赖；electron 的 postinstall 会下载二进制
npm run ensure:electron                  # 补下载 Electron 二进制（node_modules 已存在时必需）
npm run fetch:native-prebuild            # 下载 Electron ABI 的预编译 .node（约 0.9 MB）
npm run check:native                     # 在 Electron 里真的 require 一次 —— 唯一权威验证
npm run dev
```

**为什么 `npm run rebuild` 会失败、而上面的路线不会**

| | `npm run rebuild` | `npm run fetch:native-prebuild` |
|---|---|---|
| 做什么 | `electron-rebuild` → `node-gyp` **从源码编译** | 从镜像取 **现成的 Electron 预编译包**并解包 |
| 需要什么 | VS Build Tools（C++ 工作负载）+ Python + 数分钟 | 只要能访问镜像 |
| 失败长什么样 | `✖ Rebuild Failed / node-gyp failed to rebuild` | 会打印实际 URL，便于手工兜底 |

预编译包命名约定（`v125` 就是 Electron 的 ABI 版本）：

```
${mirror}/better-sqlite3/v11.3.0/better-sqlite3-v11.3.0-electron-v125-win32-x64.tar.gz
```

Electron 31.7.0 的 ABI 是 **125**（由 `node-abi` 给出，不要靠记忆）。

### 为什么需要一个 sidecar 标记文件

`fetch:native-prebuild` 会在模块目录里写 `.novel-studio-abi.json`：

```json
{ "abi": 125, "electronVersion": "31.7.0", "asset": "better-sqlite3-v11.3.0-electron-v125-win32-x64.tar.gz" }
```

因为 **Electron 版和 Node 版的 `.node` 文件名完全一样**（都是 `better_sqlite3.node`），
只看文件存在无法区分。标记文件记录「我们放进去的是哪个 ABI」，重装依赖时会一起消失，语义正确。

### 两条被否决的做法（都试过，别再走）

**1. 读 PE 头判断 ABI —— 不可行。**
原以为 `NODE_MODULE_VERSION` 在 PE 可选头的 `MajorImageVersion`（偏移 +44）。
实测 prebuild 出来的二进制里那些字段全是编译器默认值：

```
+40 MajorSubsystemVer = 6
+44 MajorImageVersion = 0     ← 不是 ABI
+48 MajorOSVersion    = 6
```

真正的 ABI 校验发生在**加载时**，比较的是模块里编译进去的常量，PE 头里没有。

**2. 在 Node 里 `require()` 一下 —— 会被误导。**
实测：用 **Node（ABI 127）** 加载 **Electron 版（ABI 125）** 的二进制，
`require('./node_modules/better-sqlite3')` **成功返回**，没有任何报错。
因为 better-sqlite3 的入口带降级逻辑，原生绑定加载失败时不一定抛错。
如果在 Node 里验，就会得到「一切正常」的假结论。

**因此唯一可信的验证是 `check:native`** —— 它启一个真正的 Electron 进程，
在里面 `new Database(':memory:')` 并跑一条 `select sqlite_version()`，
把结果打印回来。这是端到端的事实，不是推断。

**排错清单**
| 现象 | 原因 | 处理 |
|------|------|------|
| `NODE_MODULE_VERSION` 不匹配 | 装的/解的是另一个运行时的二进制 | `npm run fetch:native-prebuild` 后 `npm run check:native` |
| `✖ Rebuild Failed / node-gyp failed` | 走了需编译的路线，且没有构建工具 | 改用 `npm run fetch:native-prebuild`（不需要工具链） |
| 渲染进程加载 DB 报错 | 原生模块不能在 sandbox 渲染进程用 | 只能在主进程使用（本设计已如此） |
| `npm run dev` 报找不到 electron | Electron 二进制未下载 | `npm run ensure:electron` |

### 关于 postinstall 钩子（已移除，别加回来）

本仓库曾经有 `"postinstall": "electron-rebuild …"`，造成两个连锁问题：

1. 把「可选的环境相关步骤」变成了 `npm install` 的必过门槛 ——
   它在受限环境失败会让**整个 `npm install` 非零退出**，而依赖其实已经装好了。
2. 更糟的是它掩盖了真正的问题：为了绕开这个失败而加 `--ignore-scripts`，
   会连带跳过 **electron 包自己的 postinstall（`node install.js`）**，
   于是 Electron 二进制根本没下载，而日志里只有一行 `command failed`。

现在的分工：`npm install` 只装依赖；原生模块二进制由 `fetch:native-prebuild` 显式获取。
| 打包后启动即崩 | 原生 `.node` 未被打入 asar | `asarUnpack: ["**/*.node"]` |
| macOS 崩溃 | 未签名/未公证 | 配置 `notarize` 或开发期用 ad-hoc |
| CI 与本地行为不一致 | Electron 版本不一致 | 锁死版本号（非 `^`） |

**打包必须解包的原生文件**
```jsonc
"asarUnpack": [
  "**/node_modules/better-sqlite3/**",
  "**/node_modules/onnxruntime-node/**",
  "resources/bin/**",
  "resources/models/**"
]
```

## 5. ffmpeg / 模型的分发

### 5.1 ffmpeg

| 阶段 | 策略 |
|------|------|
| 开发 | 用 `@ffmpeg-installer/ffmpeg` 定位二进制；允许通过环境变量 `NS_FFMPEG_PATH` 覆盖 |
| 生产 | 二进制放 `resources/bin/{platform}/{arch}/ffmpeg(.exe)`；打包为 `extraResources`；启动时探测并校验可执行（跑 `ffmpeg -version` 解析版本号） |
| 用户覆盖 | 设置页可指定自定义路径（优先于内置） |
| 缺省失败 | 禁用处理/导出，UI 顶部横幅提示 |

**必须验证的 ffmpeg 能力**（启动时用 `-filters` 输出检查）：`loudnorm`、`afftdn`、`deesser`、`equalizer`、`acompressor`、`alimiter`、`sidechaincompress`、`amix`、`concat`、`atempo`、`highpass`/`lowpass`、`loudnorm` 的 `print_format=json`。

### 5.2 模型（用户选择：随安装包内置）

```
resources/models/
├── whisper/
│   ├── ggml-base.bin            # 默认：中文可用的最小实用模型
│   ├── ggml-small.bin           # 可选：精度更高（若安装包体积允许）
│   └── models.json              # 名称/大小/SHA-256/语言/用途
└── embedding/
    ├── bge-small-zh-v1.5/
    │   ├── model.onnx
    │   ├── tokenizer.json
    │   └── config.json          # 含 dim=512、max_length、pooling=strategy
    └── models.json
```

**约束与处理**
1. **模型尺寸**：whisper `base` 约 142 MB，`small` 约 466 MB；embedding 小模型约 90~150 MB。务必在 `models.json` 中登记 SHA-256，启动时校验（校验在后台线程，不阻塞开窗）。
2. **安装包膨胀**：使用 electron-builder 的 `extraResources` 而非塞进 asar；提供两个构建目标：`lite`（不带模型，运行时提示放置）与 `full`（内置）。
3. **运行时路径解析**：开发期读 `resources/models/`；打包后读 `process.resourcesPath/models/`。统一封装 `infra/fs/model-paths.ts`，禁止各处拼路径。
4. **embeddings 维度以运行时为准**：`line_embeddings.dim` 存实际维度，换模型时必须按 `model_id` 隔离并全部重算（见 `06` 第 6 节）。
5. **合规**：模型许可是分发前提（bge 系列、whisper.cpp 权重各有其许可证），打包前逐项确认并列入 `docs/` 附录（`21-数据字典与SQL.md` 末尾登记模型清单）。

## 8. 版本锁定策略
