# 02 · 技术选型与依赖

> 上游：`01-系统架构.md`
> 目的：把「用什么、什么版本、为什么、怎么装」钉死，避免开发期反复横跳。

---

## 1. 运行时基线

| 项 | 选择 | 说明 |
|----|------|------|
| Node.js（开发） | 20 LTS（≥20.11） | Electron 内置 Node 版本以 Electron 为准 |
| Electron | **31.x**（≥31.3） | 需要 `MessageChannelMain`、`safeStorage`、`utilityProcess` 稳定支持 |
| TypeScript | 5.4+，`strict: true` | `noUncheckedIndexedAccess` 建议开 |
| 包管理器 | pnpm（推荐）或 npm | better-sqlite3 需在 `onlyBuiltDependencies` 白名单 |
| 目标平台 | Windows 10/11 x64（一级）、macOS 12+（二级）、Linux（尽力） | — |
| 构建 | **electron-vite** | 与 `electron.vite.config.ts` 对齐 |
| 打包 | electron-builder | 见第 6 节 |

**为什么要 Electron 31+**：`MessageChannelMain` 用于给录音样本开零拷贝通道；`safeStorage` 用于加密 API Key；`utilityProcess` 用于把 ffmpeg 之外的 Node 重活（如 embedding 预处理）移出主进程。

### 2.4 明确不引入（避免复杂度）

| 不引入 | 原因 |
|--------|------|
| Prisma / TypeORM / Drizzle | 用户明确要求裸 SQL + repository；桌面单机场景 ORM 收益低 |
| Redux / MobX | Pinia 足够 |
| 自建服务端 / Express | 本地优先，无服务端 |
| 实时协作（Yjs / CRDT） | 协作模型是「分工录制」而非「同时编辑」 |
| 完整 DAW 引擎（如 JUCE/Tone.js 全量） | 处理链交给 ffmpeg，实时只做监听与试听 |
| HNSW / FAISS 等向量索引 | 单项目角色数量在几十~几百，暴力余弦足够（见 `06`） |

```ts
// main/index.ts 全局硬化
app.on('web-contents-created', (_e, contents) => {
  contents.setWindowOpenHandler(({ url }) => {
    if (/^https?:$/.test(new URL(url).protocol)) shell.openExternal(url)
    return { action: 'deny' }          // 禁止开新窗口

  contents.on('will-navigate', (e, url) => {

  contents.on('will-attach-webview', (e) => e.preventDefault())
```

## 4. 原生模块 ABI 处理（最常见的坑）

`better-sqlite3` 和 `onnxruntime-node` 是原生模块，必须与 Electron 的 ABI 匹配。

```jsonc
// package.json
{
  "scripts": {
    "postinstall": "electron-rebuild -f -w better-sqlite3,onnxruntime-node",
    "rebuild": "electron-rebuild -f -w better-sqlite3,onnxruntime-node"
  },
  "pnpm": { "onlyBuiltDependencies": ["better-sqlite3", "onnxruntime-node", "electron"] }
}
```

**排错清单**
| 现象 | 原因 | 处理 |
|------|------|------|
| `NODE_MODULE_VERSION` 不匹配 | rebuild 未针对 Electron | 重跑 `npm run rebuild` |
| 渲染进程加载 DB 报错 | 原生模块不能在 sandbox 渲染进程用 | 只能在主进程使用（本设计已如此） |
| 打包后启动即崩 | 原生 `.node` 未被打入 asar | `asarUnpack: ["**/*.node"]` |
| macOS 崩溃 | 未签名/未公证 | 配置 `notarize` 或开发期用 ad-hoc |
| CI 与本地行为不一致 | Electron 版本不一致 | 锁死版本号（非 `^`） |

**打包必须解包的原生文件**
```jsonc
"asarUnpack": [
  "**/node_modules/better-sqlite3/**",
  "**/node_modules/onnxruntime-node/**",
  "resources/bin/**",
  "resources/models/**"
]
```

## 5. ffmpeg / 模型的分发

### 5.1 ffmpeg

| 阶段 | 策略 |
|------|------|
| 开发 | 用 `@ffmpeg-installer/ffmpeg` 定位二进制；允许通过环境变量 `NS_FFMPEG_PATH` 覆盖 |
| 生产 | 二进制放 `resources/bin/{platform}/{arch}/ffmpeg(.exe)`；打包为 `extraResources`；启动时探测并校验可执行（跑 `ffmpeg -version` 解析版本号） |
| 用户覆盖 | 设置页可指定自定义路径（优先于内置） |
| 缺省失败 | 禁用处理/导出，UI 顶部横幅提示 |

**必须验证的 ffmpeg 能力**（启动时用 `-filters` 输出检查）：`loudnorm`、`afftdn`、`deesser`、`equalizer`、`acompressor`、`alimiter`、`sidechaincompress`、`amix`、`concat`、`atempo`、`highpass`/`lowpass`、`loudnorm` 的 `print_format=json`。

### 5.2 模型（用户选择：随安装包内置）

```
resources/models/
├── whisper/
│   ├── ggml-base.bin            # 默认：中文可用的最小实用模型
│   ├── ggml-small.bin           # 可选：精度更高（若安装包体积允许）
│   └── models.json              # 名称/大小/SHA-256/语言/用途
└── embedding/
    ├── bge-small-zh-v1.5/
    │   ├── model.onnx
    │   ├── tokenizer.json
    │   └── config.json          # 含 dim=512、max_length、pooling=strategy
    └── models.json
```

**约束与处理**
1. **模型尺寸**：whisper `base` 约 142 MB，`small` 约 466 MB；embedding 小模型约 90~150 MB。务必在 `models.json` 中登记 SHA-256，启动时校验（校验在后台线程，不阻塞开窗）。
2. **安装包膨胀**：使用 electron-builder 的 `extraResources` 而非塞进 asar；提供两个构建目标：`lite`（不带模型，运行时提示放置）与 `full`（内置）。
3. **运行时路径解析**：开发期读 `resources/models/`；打包后读 `process.resourcesPath/models/`。统一封装 `infra/fs/model-paths.ts`，禁止各处拼路径。
4. **embeddings 维度以运行时为准**：`line_embeddings.dim` 存实际维度，换模型时必须按 `model_id` 隔离并全部重算（见 `06` 第 6 节）。
5. **合规**：模型许可是分发前提（bge 系列、whisper.cpp 权重各有其许可证），打包前逐项确认并列入 `docs/` 附录（`21-数据字典与SQL.md` 末尾登记模型清单）。

## 6. 构建与打包

### 6.1 electron.vite.config.ts 关键点

```ts
export default defineConfig({
  main: {
    build: {
      rollupOptions: {
        external: ['better-sqlite3', 'onnxruntime-node', 'electron-log']   // 原生/需 CJS 的模块不打包
      }
    },
    resolve: { alias: { '@shared': resolve('src/shared'), '@main': resolve('src/main') } }
  },
  preload: { build: { rollupOptions: { output: { format: 'cjs' } } } },     // preload 用 CJS 更稳
  renderer: {
    resolve: { alias: { '@': resolve('src/renderer/src'), '@shared': resolve('src/shared') } },
    plugins: [vue(), AutoImport({ resolvers: [ElementPlusResolver()] }), Components({ resolvers: [ElementPlusResolver()] })],
    worker: { format: 'es' }                                                 // 波形/embedding 用 Worker
  }
})
```

### 6.2 关键脚本

```jsonc
{
  "scripts": {
    "dev": "electron-vite dev",
    "build": "npm run typecheck && electron-vite build",
    "typecheck": "vue-tsc --noEmit -p tsconfig.web.json && tsc --noEmit -p tsconfig.node.json",
    "lint": "eslint . --ext .ts,.vue",
    "test": "vitest run",
    "test:e2e": "playwright test",
    "rebuild": "electron-rebuild -f -w better-sqlite3,onnxruntime-node",
    "dist:win": "npm run build && electron-builder --win --x64",
    "dist:mac": "npm run build && electron-builder --mac"
  }
}
```

### 6.3 electron-builder 要点

```jsonc
{
  "appId": "com.novelstudio.app",
  "productName": "Novel Studio",
  "directories": { "output": "release" },
  "files": ["out/**/*", "package.json"],
  "extraResources": [
    { "from": "resources/bin", "to": "bin" },
    { "from": "resources/models", "to": "models" }
  ],
  "asarUnpack": ["**/*.node"],
  "win": { "target": ["nsis"], "artifactName": "${productName}-${version}-setup.${ext}" },
```

**首启行为**：创建 `userData/projects/`、`userData/cache/`、`userData/logs/`、`userData/backups/`；跑迁移；校验模型；若模型缺失（lite 包）弹出明确的「放置模型」向导（给出目标目录 + 校验说明），而不是静默失败。

## 7. 目录与路径约定（跨平台）

| 用途 | 路径 | 解析方式 |
|------|------|----------|
| 数据库 | `{userData}/novel-studio.db` | `app.getPath('userData')` |
| 项目音频 | `{userData}/projects/{projectId}/` | 一律相对项目根存库 |
| 导出成品 | 用户设置；默认 `{userData}/exports/` 或「文档/NovelStudio」 | 设置页可改 |
| 缓存 | `{userData}/cache/` | 可安全删除 |
| 日志 | `{userData}/logs/` | 保留 14 天 |
| 备份 | `{userData}/backups/` | 保留 7 份 |
| 内置资源 | 开发 `resources/`；打包 `process.resourcesPath/` | `infra/fs/resource-paths.ts` |
| 临时文件 | `{userData}/projects/{projectId}/.tmp/` | 启动清理，但修复流程优先 |

**便携模式**：若应用目录下存在 `portable.flag`，则所有路径改为相对应用目录（便于 U 盘/离线机器使用）。

## 8. 版本锁定策略

- Electron、`better-sqlite3`、`onnxruntime-node` 使用**精确版本**（不加 `^`），因为 ABI 敏感。
- 其余依赖允许 `^`，但提交 `package-lock.json` / `pnpm-lock.yaml`。
- 升级 Electron 前必须：跑 `rebuild` → 跑 E2E（含录音与导出）→ 检查 `MessageChannelMain` 与协议注册行为无变化。
- 数据库 schema 版本与应用版本解耦，单独维护 `schema_version`（见 `03`）。
