## 2. 产品定义

### 2.1 一句话

> 把一本小说，变成一份**可下发给多人分角色录制的画本**，再把录回来的音频**自动对轨、处理、混音**
> 成**可分发的有声成品**。

再换一句对外定位：

> **novel-studio 是一个本地优先的「小说 → 画本 → 录音 → 对轨 → 混音 → 有声成品」一体化工作站。**
> 它把「谁说的话」这件事从人工判断变成可复算的语义判定，把「多人分角色录音」变成可下发、
> 可回收、可合并的工程流程。

### 2.2 它不是什么（写进文档，也写进边界判断）

- 不是在线阅读器（不负责排版阅读体验）
- 不是完整 DAW（不做 MIDI、不做宿主级多轨实时效果器链）
- 不是 TTS 生成工具（1.0 不生成人声，只录真人；TTS 见 3.0）
- 不是云端协作平台（1.0~2.0 靠文件包交换，不做实时协同编辑）

### 2.3 核心价值链

```
文本导入 ──▶ 画本（谁说的 / 什么情绪 / 停多久） ──▶ 录音（单人 or 多人分工）
                                                      │
成品分发 ◀── 混音导出（-16 LUFS / M4B） ◀── 处理（降噪 EQ 压缩） ◀── 对轨（时间线排布）
```

### 2.4 全系统第一铁律

> **画本行（`canvas_line`）是全系统唯一主轴，其余一切数据都必须能追溯到某一行画本。**

这条铁律决定：录音片段（`voice_segment`）、试录（`take`）、时间线项（`arrangement_item`）、
情绪与停顿标记、音色绑定，**全部挂在 `line_id` 上**。任何绕过 `line_id` 的旁路设计都是错的。

### 2.5 与市面工具的关键差异（写进 docs/README，用于约束设计取舍）

1. **画本是全局枢纽**：不是「文本 + 音频」两坨东西对不上，而是以 `canvas_line` 为唯一主轴。
2. **说话人判定走向量**：引号/正则只做粗筛，真正的归属由本地 ONNX embedding + 角色原型向量
   （centroid）余弦相似度判定，**离线可跑、可复算、可人工覆盖**。
3. **协作是一等公民**：支持「一台机器切画本 → 下发角色任务包 → 多名配音员各自录制 → 回收合并」闭环。
4. **离线优先**：ASR（whisper.cpp）、embedding、混音（ffmpeg）全部本地；云端 LLM（Dify）是可选增强，不是硬依赖。

## 3. 用户角色与主场景（需求必须覆盖这五类人）

| 角色 | 描述 | 关键诉求 | 主要功能域 |
|------|------|----------|-----------|
| **制作人 / 主播（P）** | 一个人搞定全部，通常是 UP 主、有声书爱好者 | 快、少手活、不要对不上号 | 导入、画本（AI 辅助）、录音、混音 |
| **配音导演（D）** | 负责分配角色、下发任务、验收音频 | 分工清楚、回收不混乱、能查错 | 画本、任务包 `.nst`、对轨、质检 |
| **配音员（V）** | 只录自己角色的人，可能不在同一台机器 | 打开就有得录、只看自己的词、录错能重录 | 录音（角色模式）、任务包 |
| **后期（E）** | 只做处理与混音 | 参数可存可复用、批量、可校验 | 处理、混音、导出 |
| **技术用户（T）** | 配置模型、API、路径 | 能改配置、能看日志、能降级 | 设置、AI Provider、日志 |

**三条必须写进文档并最终能在 UI 上走通的主场景**：

- **J1 · 单人全流程（P）**：导入 120 万字 GBK TXT → 自动分章 1643 章 → 第 1 章一键「AI 生成画本」
  （切旁白/对白 + 向量判定说话人 + 标情绪）→ 人工改掉 12 处判错 → 逐行录制 87 行 →
  自动对轨手动调 3 处重叠 → 套预设「男声旁白 + 轻 BGM」导出第 1 章 MP3 → 全书完成后一键导出整本 M4B。
- **J2 · 多人分工（D）**：建角色表（萧炎/药老/纳兰嫣然/旁白）→ 绑定配音员（一人可多角色）→
  导出 4 个 `.nst` 任务包 → 各配音员用角色模式录制 → 回收 4 个录毕包 → 按 `line_id` 自动归位，
  重复/缺漏进质检报告。
- **J3 · 返工（V）**：质检报告指出第 34 行削波、第 51 行漏录、第 77 行口水音 →
  V 只重录这 3 行 → 导出增量包回传。

**假设（写进文档，作为设计前提）**：用户有可用录音设备与耳机；用户理解画本是给人看的表演脚本、
愿意人工校对；目标作品以中文小说为主；单人配音员可能不具备技术能力，需要零配置体验。

### 4.2 工程基线约束（这些是有代价换来的，必须遵守）

- `"type": "module"`，`engines.node >= 22.6.0`。
- **`scripts/` 与 `tests/` 不引入 `tsx` / `ts-node` / `vitest`**：Node 22.6+ 原生支持 TypeScript
  类型剥离（`--experimental-strip-types`），脚本直接用 `node --experimental-strip-types xxx.ts` 跑。
  这是刻意的设计：**无外网环境也能跑测试与文档生成**。
- `src/shared/*.ts` 之间以及 `scripts/` 的 import **显式带 `.ts` 扩展名**（要被 Node 以 ESM 直接执行）。
  `tsconfig` 需开启 `allowImportingTsExtensions`；electron-vite 侧正常解析。
- **故意不设 `postinstall`**：`postinstall` 里跑 `electron-rebuild` 在受限环境会失败，
  导致整个 `npm install` 非零退出（依赖其实已装好），还会掩盖「Electron 二进制没下载」这个真问题。
  正确做法：`npm install` 只装依赖，原生模块 ABI 重建由需要的人显式跑 `npm run rebuild`。
- `tsconfig` 开启 `strict: true`；共享类型单一来源 `src/shared/types.ts`。

## 5. 架构与分层（铁律，代码必须长成这样）

### 5.1 三条硬约束（决定了整个切分方式）

1. **录音不能丢帧**：Web Audio 实时回调禁止任何同步 I/O 或重计算。采集到的 float32 块通过
   `MessagePort` 传给主进程，由主进程追加写入 + 定期 fsync。
2. **数据库必须串行**：`better-sqlite3` 是同步 API，多写者互相阻塞。数据库**只在主进程持有单例**，
   写操作经 repository 层串行化，**渲染进程永远不碰 SQL**。
3. **用户文本是资产**：所有业务数据落 SQLite（可查询、可迁移、可备份），音频落文件系统
   （**不走 BLOB**，避免数据库膨胀）。二元边界就是「结构化数据 vs 大二进制」。

### 5.4 数据所有权

| 数据 | 唯一权威位置 | 渲染进程如何拿到 |
|------|--------------|------------------|
| 书籍/章节/画本行/角色 | SQLite（主进程） | IPC 查询 |
| 录音音频文件 | `userData/projects/{id}/recordings/` | 只拿 `ns-media://` URL 读取 |
| 片段与对轨位置 | SQLite | IPC 查询 + 局部更新 |
| 处理结果 | 文件系统 + SQLite 指针 | 同录音 |
| 录音中的实时样本 | 渲染进程采集 → 主进程落盘 | 渲染进程不持久化 |
| UI 选择态/滚动位置 | 渲染进程（Pinia） | 本地 |
| 任务进度 | 主进程队列 | 事件订阅 |

**自定义协议**：注册 `ns-media://<projectId>/<relativePath>`，主进程 handler 做**路径规范化校验**
（必须落在该项目目录内，拒绝 `..` 与绝对路径逃逸），避免暴露任意文件读取。

### 5.5 主链数据流（必须按此实现）

```

[2] 画本生成  ipc: canvas.generate

              b. 抽取/加载角色表 → 计算角色原型向量
              c. 每行 embedding → 与原型向量余弦 → 归属 + 置信度
              d. （可选）标记情绪/语速：规则词表 + Provider
              e. 事务写 canvas_lines + line_embeddings
[3] 人工校对  ipc: canvas.updateLine（乐观 UI + 防抖落库）；确认后异步增量更新原型向量
[4] 录音      AudioWorklet 采集 float32 → MessagePort → 主进程 recorder
              追加写 .tmp WAV + 每秒 fsync + 记录样本数；停止 → 定稿头部 → session/take/segment
[5] 对轨      ipc: alignment.autoArrange → 取片段 → 按画本行顺序 + 留白 → 排布 → 重叠检测 → 写 arrangement_items
              拖动 → alignment.updateItem（非破坏，只存 offset）
[6] 处理      ipc: process.batchApply → 队列 → ffmpeg 滤镜链 → 派生 processed 文件 → 写 processed_path
[7] 混音导出  ipc: export.render（preview / chapter / book）
              队列：构建滤镜图（amix + sidechaincompress + loudnorm 两遍）→ 章节文件
                    → 全部完成 → concat + chapter metadata → M4B
```

### 5.6 IPC 契约

**三种模式**：

| 模式 | 用途 | 例子 |
|------|------|------|
| 请求-响应（`invoke`） | 所有查询与命令 | `book.list`、`canvas.updateLine` |
| 单向推送（`send`） | 高频、可丢弃的数据 | 录音电平 `record.meter`（每 50 ms 一帧） |
| 事件流（`webContents.send`） | 任务进度、状态变更、日志 | `task.progress`、`export.progress` |

**原则**：

1. **音频样本走 MessagePort，不走 `ipcRenderer.invoke`**。⚠️ 实测纠正：这条路径上
   ① 主进程**必须**调 `MessagePortMain.start()`；
   ② 发送侧**不能带 transfer 列表**（带了主进程收到的 `event.data` 恒为 `null`）；
   ③ 渲染进程建的 MessagePort **过不了 `contextBridge`**，必须由主进程侧建、经 preload 暴露。
   它**不是**零拷贝：每 50 ms 一次结构化克隆拷贝（约 9 KB），换来的是数据真的到得了。
2. **通道命名**：`<域>:<动作>[.<子动作>]`，域用小写单词、动作用小驼峰
   （`book:list`、`canvas:updateLine`、`export:m4b`）。
   ⚠️ `docs/01` 早期写的是「点分层级」（`canvas.generate`），**以 `src/shared/ipc.ts` 的冒号口径为准**——
   全仓 166 个通道都是冒号，文档与代码不一致时以契约为准并回头修文档。
   域集合：`app book chapter canvas character voiceActor record device take alignment process preset
   music mix export package settings task log db ns-media`；
   事件名 = `<域>:<名词>` + `:changed` / `:progress` / `:status`。
3. **全部参数运行时校验**：handler 入口用 Zod（或手写 guard）校验，防止渲染进程被 XSS 后乱调用。
4. **错误统一形状**：见 §11；契约层是
   `IpcResult<T> = { ok: true; data: T } | { ok: false; error: SerializedAppError }`。
5. **不传大对象**：画本行分页/按章拉取；波形传**降采样后的峰值数组**（如每 100 ms 一对 min/max），
   不传原始样本；音频一律传路径（`ns-media://` 或项目根相对路径），**不传二进制**。
6. **传输类型与领域类型分离**：IPC 只传可序列化的扁平 DTO（一律 camelCase、布尔用真布尔），
   不传带方法的类实例；领域类型在 `src/shared/types.ts`（camelCase），存储层 snake_case
   （0/1、JSON 存 TEXT），映射集中在 repository 的 `mappers.ts`。
7. **契约必须对称**：`src/shared/ipc.ts` 声明 **166 个通道、16 个事件、2 个单向通道**，
   每个通道都要有请求/响应类型，并由 `check:coverage` 验证「声明数 == handler 数」。
8. **preload 暴露面**（`contextBridge.exposeInMainWorld('api', …)`）只允许：
   `invoke / send / on(返回取消订阅函数) / attachRecordPort / sendRecordPcm / detachRecordPort /
   mediaUrl`。约束：① `invoke`/`send`/`on` 内部对 channel 做**白名单校验**，未注册直接抛错；
   ② **不暴露 `ipcRenderer` 本体，不暴露 `require` / `process` / `fs`**；
   ③ **不把 `MessagePort` 交给渲染进程**（端口由 preload 创建并转移给主进程）；
   ④ 渲染进程日志不新开通道，走 `console.*` → `console-message` → 主进程落盘。
9. **事件节流**（主进程侧，必须实现）：`task:progress` ≤10/s、`record:level` ≤20/s、
   `record:sliceProgress` ≤5/s、`canvas:progress` ≤5/s、`export:progress` ≤2/s。
   事件必须**幂等**（可能重复到达，按 `taskId+progress` 单调去重）；窗口重建后靠
   `task:list` + `record:status` 恢复；`task:finished` 不得丢终态（窗口不存在时落库，就绪后补发）。
10. **不重复报错**：已经通过 `invoke` 的 `{ok:false}` 返回给调用方的错误，**不要再推 `app:error`**
    （否则用户看两次）。

### 5.7 启动顺序（必须严格，顺序本身是正确性的一部分）

```
1.  app.requestSingleInstanceLock()          # 二次启动聚焦已有窗口
2.  解析 userData 与设置（含便携模式判断）
3.  初始化日志（含崩溃捕获）
4.  打开数据库 → 跑迁移 → integrity_check
5.  崩溃恢复：扫描 projects/*/recordings/*.tmp → 修复 WAV 头 → 生成 session 记录
6.  清理过期临时文件与孤儿缓存（带白名单保护）
7.  校验模型文件（异步、不阻塞）
8.  探测 ffmpeg（异步）
9.  注册自定义协议 ns-media://
10. 注册 IPC handlers（幂等）
11. 创建主窗口 → 加载渲染进程 → 就绪
12. 后台：自动备份、缓存清理、更新检查（可关）
```

**顺序理由必须写进文档**：3 必须在 4 之前（数据库出问题要留日志）；
5 必须在 6 之前——**不能把待修复的 `.tmp` 当垃圾删掉，这会直接导致用户录音丢失**。

### 5.8 关闭与崩溃语义

| 场景 | 行为 |
|------|------|
| 正常关闭 | 有进行中录音 → 阻止关闭并提示；有导出任务 → 询问「后台完成后退出 / 立即取消并退出」 |
| 强制关闭（任务管理器） | 下次启动走崩溃恢复；未完成任务标记 `interrupted`，提示「上次有 N 个任务被中断，是否重试」 |
| 渲染进程崩溃 | 主进程重建窗口并恢复路由；录音会话若在进行 → 提示素材已保存并可继续 |
| 数据库忙 | 所有写操作带 busy 超时（默认 5 s），超时后报可重试错误，**不静默丢数据** |

### 5.9 必须成文的 ADR（架构决策记录）

| ID | 决策 | 备选 | 理由 | 代价 |
|----|------|------|------|------|
| ADR-01 | 音频落文件系统，不入库 BLOB | BLOB 存 SQLite | 库体积可控、可流式读、可外部工具修复 | 需自管路径与清理 |
| ADR-02 | `better-sqlite3`（同步） | `node-sqlite3`（异步） | 主进程单线程下同步更快更简单 | 需 rebuild；禁长事务 |
| ADR-03 | 录音采集在渲染进程、落盘在主进程 | 全在主进程（native 采集） | 复用 Web Audio 设备/监听/处理能力，跨平台一致 | 需设计零拷贝通道与丢帧保护 |
| ADR-04 | 画本行是唯一主轴 | 文本与音频各自为主 | 一处真源，避免对不上号 | 所有功能必须挂 `line_id` |
| ADR-05 | 说话人判定 = 规则初筛 + 向量判定 + 人工兜底 | 纯 LLM / 纯规则 | 离线、可复算、成本可控；LLM 仅复核低置信 | 需维护角色原型向量 |
| ADR-06 | 非破坏性处理（派生文件 + 指针） | 就地覆盖 | 可回退、可对比、可换预设 | 占磁盘，需清理策略 |
| ADR-07 | AI 能力抽象为 Provider | 直接调 Dify | 需可换、可 Mock、可离线 | 多一层适配 |
| ADR-08 | 协作靠文件包（`.nst`），不做服务端 | 自建云服务 | 本地优先、零运维、可离线交换 | 冲突处理自己做 |
| ADR-09 | 对轨位置独立存储（`offset_ms` + `src_in/out`） | 直接改音频文件 | 可反复调整、可多方案 | 渲染时需正确计算 |
| ADR-10 | 响度用两遍法（measure → apply） | 单遍 `loudnorm` 动态模式 | 单遍逐章响度不齐；两遍线性增益才稳 | 渲染耗时 ×2 |

### 5.10 错误边界与降级策略（产品决策层）

| 故障 | 探测方式 | 降级行为 | 用户可见 |
|------|----------|----------|----------|
| ffmpeg 缺失/损坏 | 启动探测 + 首次调用失败 | 禁用处理/导出 | 顶部横幅 + 「重新指定路径」 |
| 音频设备被占用 | `getUserMedia` 抛错 | 允许「只读模式」查看已有录音 | 弹窗给出占用原因与重试 |
| 麦克风权限被拒 | 权限状态 | 禁用录音 | 引导到系统设置 |
| 模型文件缺失/校验不符 | 启动校验 SHA-256 | 向量判定降级为规则+人工 | 设置页提示 |
| Embedding 推理 OOM | 捕获异常 | 减小 batch，失败则降级规则 | 报告注明降级原因 |
| Provider 不可达 | 超时/网络错误 | 重试 2 次 → 降级本地规则 | 「AI 增强不可用」 |
| 数据库损坏 | `integrity_check` 失败 | 只读模式 + 引导恢复备份 | 阻止写入 |
| 磁盘写满 | 写入抛错 | **立即停止录音并保住已写数据** | 高优先弹窗（数据安全事件） |
| 单片段处理失败 | 逐条捕获 | 跳过该片段继续 | 报告列表 |
| 渲染进程崩溃 | `render-process-gone` | 重建窗口、恢复路由与选中章节 | 「已恢复」 |
| 主进程崩溃 | Electron 退出 | 启动扫 `.tmp` 修 WAV、标记任务 `interrupted` | 启动报告 |

**核心原则**：**录音链路上任何错误，第一优先是保住已采集数据，其次才是提示用户。**

### 5.11 与外部程序的集成

| 外部 | 调用方式 | 并发策略 | 超时 |
|------|----------|----------|------|
| ffmpeg | `child_process.spawn`，参数以**数组**传递（不经 shell） | 按 CPU 核数限制（默认 `min(4, cores-1)`） | 无固定超时，靠进度/stall 检测 |
| whisper.cpp | 独立进程/工作线程，模型常驻 | 串行（模型不可并发） | 按音频时长动态计算 |
| ONNX embedding | 主进程内 `onnxruntime-node` | 小批量并发，batch 自适应 | 单批 30 s |
| LLM Provider | HTTP（`fetch`/`undici`） | 默认并发 2，可配置 | 默认 60 s，流式空闲超时 30 s |

**ffmpeg 进度解析**：统一加 `-progress pipe:1 -nostats`，解析 `out_time_us` / `total_size` / `speed`
换算百分比；无总时长场景用「已完成片段数 / 总片段数」估算。

### 5.12 长任务队列（`infra/queue`，所有重活必须走它）

**必须入队的任务**：`book.import`（数秒~数分钟）、`canvas.generate`、`embedding.batch`（分钟级）、
`asr.transcribe`（实时率 0.3~1×）、`audio.process`（0.05~0.3 s/秒音频）、`audio.render`、
`export.chapter` / `export.book`（分钟~小时）、`package.export` / `package.import`。

**`TaskKind` 共 12 项**：

```
book.import | canvas.generate | embedding.batch | asr.transcribe | audio.process | audio.render
export.chapter | export.book | package.export | package.import | db.backup | cache.clean
```

**`TaskRecord` 字段**：`id, kind, status, priority, projectId, payload(JSON), progress(0..1),
stage(人类可读阶段名), result(JSON), error(JSON {code,message,details}), attempts, maxAttempts,
concurrencyKey, dedupeKey?, createdAt, startedAt, finishedAt`；
`status: queued | waiting | running | succeeded | failed | cancelled | interrupted`。
`priority` 越小越先（用户交互 = 0、后台维护 = 100）。

| 机制 | 要求 |
|------|------|
| 并发控制 | 按 `concurrencyKey` 独立上限：`ffmpeg: min(4, cores-1)`、`whisper: 1`（模型不可并发）、`embedding: 1`（避免 OOM）、`db-write: 1` |
| 进度上报 | `ctx.report(progress, stage)`，**节流 ≤10 次/秒**；`etaMs` 无历史同类任务时给 `null`（UI 显示「计算中」） |
| 取消 | `AbortController` 贯穿 `ctx.signal`；关键点检查 `signal.aborted` 并清理临时文件；**已完成的结果不回滚** |
| 重试 | 仅对 `retryable`（默认 1 次，指数退避 1s/4s）；**ffmpeg 编码失败不重试** |
| 持久化 | 任务写库；启动时把 `running`/`waiting` 标 `interrupted`，UI 询问「重试 / 丢弃」 |
| 幂等 | `dedupeKey`（如 `audio.process:{segmentId}:{presetHash}`、`book.import:sha256:xxx`），重复提交返回已有任务 |
| 上报通道 | `ctx.report() → 队列(节流) → webContents.send('task:progress', { taskId, kind, progress, stage, etaMs, throughput })`；UI 统一用 `<TaskProgressCard>`，**禁止每个功能自建进度 UI 或轮询** |
| 任务模板 | 读文件用 `fs/promises`；关键点 `ctx.throwIfAborted()`；写库每批 200 + 事务 + `yieldToLoop()`；`onCancel(ctx) { cleanupTemp(ctx.tempDir) }` |
| 失败隔离 | 单个片段失败**不中断整批**；逐条记录，任务结束时汇总报告 |

**并发与背压（§6 的落地）**：同时录音会话 1；同时 1 个 `export.book`（可叠加多个 `export.chapter`）；
网络默认 2 并发、超时 60 s；**录音写入用有界队列（容量约 2 秒音频），将满时先扩大到 10 秒，
仍满则立刻停止录音、定稿文件并明确告知用户「因磁盘写入跟不上已停止录音，已保存 X 秒素材」——
绝不静默丢帧。**

**崩溃恢复（`bootstrap/recovery.ts`）**：

```
扫 projects/*/recordings/*.wav.tmp 与 *.pcm.part
→ 读伴生元数据 {sessionId}.meta.json
→ 校验长度与样本数一致（截断到完整帧边界）
→ 生成合法 WAV 头（RIFF/WAVE/fmt/data，data size = 样本数 × 帧字节）
→ 原子改名 {sessionId}.wav
→ 写 recording_sessions（status = 'recovered'）
→ tasks 中 running/waiting 标 interrupted
→ 清残留 → 推送「已恢复 N 段录音（共 X 分钟），可继续录制」
```

元数据字段：`sessionId, projectId, chapterId, sampleRate, bitDepth, channels, mode, startedAt,
framesWritten, peakDb, gainDb, device{label,deviceId}`——**录音一开始就写、每 5 秒与结束前更新
（这是录音安全的核心）**。放弃恢复的条件：文件 **<44 字节**，或 ffprobe 无法解析且头字段自相矛盾
（**保留原始文件不删**）；被隔离的 tmp 移入 `.tmp/quarantine/` **保留 7 天**。

### 5.13 基础设施其余要点

- **DB 铁律**：任何可能超过 50 ms 的查询必须先 `EXPLAIN QUERY PLAN` 验证走索引；
  批量写必须分批（每批 2000 行）+ 事务 + `setImmediate` 让出事件循环；
  事务包装 `tx<T>(fn)`（savepoint 嵌套安全），写事务用 `txImmediate`（减少锁升级失败）；
  repository **只暴露领域类型，不暴露 `Statement`/`Row`**；全部参数化查询，
  **禁止字符串拼接**；**禁止跨域 join**（`book` 域不查 `audio` 域的表）。
- **日志**：五级 error/warn/info/debug/trace（生产关后两级）；`logs/YYYY-MM-DD.log` 保留 14 天；
  事件命名 `域.动作.结果`（如 `canvas.generate.done`）；脱敏 API Key（`sk-***`）、作品正文
  （debug 仅前 20 字 + 长度）、绝对路径（记 `{userData}/...`）、系统用户名；
  渲染进程日志经 `console-message` → `forwardRendererConsole()` 落盘，
  结构化记录**必须以单字符串** `'[ns] ' + JSON.stringify(payload)` 发出。
- **设置**：存 SQLite `settings` 表（key-value JSON）；敏感值 `safeStorage.encryptString` 后 base64；
  分组 `paths / audio / recording / canvas / mixing / export / ai / embedding / asr / ui / advanced`；
  变更广播 `settings:changed`（带 changedKeys）；采样率 / ffmpeg 路径 / embedding 模型**不能热改**，
  必须标注「重启后生效」或「将触发重算」。
- **secure**：`safeStorage.isEncryptionAvailable()` 不满足则抛 `SECURE_UNAVAILABLE` 拒绝保存 Key；
  换机器解密失败 → 清除并提示重输（**不崩溃**）。
- **可观测**：`measure('canvas.generate', {...}, fn)` 写 `metrics` 表保留 30 天，全部本地不上报；
  必须埋点 6 项——录音丢帧数（期望恒 0）、监听往返延迟、embedding 每千行耗时、
  ffmpeg 实时率 `speed`、导出响度偏差、说话人判定人工修改率。

## 7. 数据模型与存储

### 7.1 存储分层

- **结构化数据 → SQLite**：项目、书籍、章节、画本行、角色、配音员、片段、对轨、任务、导出、日志。
- **大二进制 → 文件系统**：录音 WAV、派生处理结果、BGM/SFX 素材、导出成品、模型文件。
- **向量 → SQLite 表 `line_embeddings` / `character_centroids`**（小体量 float 数组，暴力余弦，不建索引结构）。
- **缓存 → SQLite 表 `ai_cache` + 文件缓存**（波形峰值、转码）。

### 7.2 数据库 PRAGMA 与事务

```
journal_mode = WAL
synchronous  = NORMAL
foreign_keys = ON
busy_timeout = 5000
```

- 写入必须使用事务；**禁止长事务**（同步 API 会阻塞主进程）。
- schema 变更**必须走版本化迁移脚本**（`src/main/infra/db/migrations/NNN_name.sql`），
  迁移在**单事务**内执行，跨版本前先自动备份。

### 7.3 表清单（必须建全，这是 1.0 的完整数据面）

### 7.4 文件布局与迁移、备份

- 用户数据根：`userData/`；项目：`userData/projects/{projectId}/`；
  录音：`.../recordings/`；派生：`.../processed/`；导出：按书建目录；临时：统一收口 `.tmp/`。
- **临时文件统一收口到 `.tmp/` 并在启动时清理（带白名单，绝不误删待修复录音）**。
- 自动备份：每日/每周策略、保留 N 份、从备份恢复、`PRAGMA integrity_check` 完整性检查；
  备份时正确处理 `-wal` 文件。

### 7.5 `.nsp` 项目包 / `.nst` 任务包

- `.nsp`：整项目可迁移归档（画本、角色、录音、对轨位置、设置），带清单与校验和。
- `.nst`：下发给单个配音员的角色子集 + 空白录音位；含画本行清单（**`line_id` 稳定**）、
  角色信息、表演提示（情绪/语速/停顿/发音提示/备注）、录音设置建议、可选参考音；
  含 `linesHash` 用于「包发出后画本是否变更」的差异提示。
- 回收合并：按 `line_id` 归位，处理三类冲突——重复（多次回传 → 提示择一）、缺漏（列出）、
  未知 line（拒绝并报告）。
- ZIP 读写必须做 **zip bomb 与路径穿越防护**（默认解压总量上限 50 GB、条目数 50000、
  拒绝 `..`/绝对路径/符号链接）。

### 7.6 用户数据目录布局（照此落地）

```
{userData}/
├── novel-studio.db  (+ -wal / -shm)
├── logs/YYYY-MM-DD.log              保留 14 天
├── backups/{novel-studio-{ts}.db, index.json}   保留 7 份
├── cache/{asr/*.json, tmp/}
└── projects/{projectId}/
    ├── project.json
    ├── recordings/{sessionId}.wav            ← 永不自动删除
    ├── takes/{lineId}/{takeId}.wav
    ├── segments/{segmentId}.wav
    ├── processed/{segmentId}.{presetHash}.wav

    ├── packages/

```

- **便携模式**：应用目录存在 `portable.flag` 时，全部路径改为相对应用目录。

### 7.7 路径与命名铁律

- **库里只存相对于 `projects/{projectId}/` 的路径**（如 `segments/abc.wav`）；
  绝对路径只在运行时由 `infra/fs/paths.ts` 拼接，**禁止入库**（唯一例外 `projects.root_dir`）。
- 音频文件名用**不可变 ID**（UUID/nanoid），**不使用中文标题**；人类友好名存库，导出时才套命名模板。
- 统一封装 `infra/fs/model-paths.ts`，**禁止各处自己拼模型路径**。
- `resolveProjectPath` 强制校验落在项目目录内（防 `..` 逃逸）；
  `atomicWriteFile` = 写 `.tmp` → `fsync` → `rename`（同盘 rename 才原子）；
  `safeRemove` **拒绝删除项目根、模型目录、数据库**。
- **启动清理顺序不能变**：先崩溃恢复 → 再清「超过 24 小时且不在恢复清单内」的 `.tmp` → 再清缓存（按 TTL）。
- **非破坏性消费优先级**：`processed_path`（且 `preset_hash` 与当前方案一致）→ `segments.file_path`
  → 从 take 现切并缓存为 segment。
- **清理默认值**：recordings 永不自动删（被 take 引用时禁止清理）、非选中 takes 保留 30 天、
  过期 processed 保留 7 天、cache 保留 3 天、exports 永不自动删。

### 7.8 数据一致性规则（踩过的坑）

- 音频相关实体**禁止物理删除**（改软删除 `deleted_at`）；有 segment 引用的画本行禁止删除。
- 角色被删但画本还引用它 → **禁止物理删除，改 `archived` 状态**。
- **别名只有一个权威**：读路径一律查 `character_aliases`，`characters.aliases` 只是镜像值，
  **不是真相来源**（两处都能存别名就必须指定唯一权威，否则迟早分叉）。
- `voice_segments(line_id)` 唯一约束，保证「一行一成品」；
  自 `004` 迁移起 `takes` 增加软删除，`idx_takes_line_alive`。
- 并发写靠 repository 层串行 + `rev` / `updated_at` 乐观锁；冲突抛 `CONFLICT`。
- 任务表 `tasks` **独立于业务域**；`dedupe_key` 用部分唯一索引
  `WHERE dedupe_key IS NOT NULL AND status IN ('queued','waiting','running')`。
- `character_voice_bindings` 表**没有**「至多一个主绑定」的约束，由实现负责
  （新的主绑定会把旧的降级为备选）。
- **备份只含数据库，音频不在备份内** → **`.nsp` 是唯一的完整归档方案**，UI 必须把这点讲清楚。
- **恢复备份时必须同时删除同名 `-wal`/`-shm`**（否则与旧 WAL 混合导致损坏——
  这是恢复失败的头号原因）；恢复后跑 `integrity_check` + `foreign_key_check`，失败自动回退保留库。

### 7.10 画本行字段的必要性（缺一个会出什么故障）

## 8. 功能域需求（每个域都要有 FR 编号、优先级、AC 验收标准）

> 编号规则：`FR-<域>-<序号>`；优先级 `P0` = 1.0 必须，`P1` = 1.0 尽力 / 2.0 兜底，`P2` = 3.0。

### FR-1 书籍导入（域 `book/import`）

- **P0** TXT 导入，自动嗅探编码：UTF-8（含/不含 BOM）、UTF-16LE/BE（BOM）、GBK/GB18030、Big5；
  嗅探失败让用户手选并以预览确认。
- **P0** 自动分章：内置中文小说分章正则族（`第X章`、`第X节`、`Chapter N`、`序章/楔子/尾声/番外`、
  全角数字、中文数字）；支持用户自定义正则并**实时预览**匹配结果。
- **P0** 无章节标记文本支持按长度/空行均匀切分，或整体作为单章。
- **P0** DOCX 导入（保留段落结构，识别标题样式为章节边界）；**P0** PDF 导入（保留页序；
  扫描版无文本层时明确提示「需 OCR，本期不支持」）；**P0** 粘贴文本导入（走同一分章管线）。
- **P1** URL 抓取：内置常见小说站正文容器规则 + 自定义 CSS 选择器 + 多页「下一章」跟随（可设上限）。
- **P0** 清洗：去站点广告水印行（如「本章未完，请点击下一页继续阅读」）、重复行、多余空行、
  零宽字符、`\r` 归一。
- **P0** 预览与人工干预：章列表可改名、合并、拆分、排序、删除、勾选部分导入。
- **P0** 大文件（≥50 MB / ≥500 万字）导入不阻塞 UI，带进度与可取消。
- **P1** 导入历史与去重（SHA-256 重复提示「已存在」，允许另存为副本）；
  **P1** 导入后按章统计字数、行数、预估录音时长。

- **P0（实际交付新增）画本导入模式**：向导第 1 步可勾选「这份文档已经是画本」→ `importMode:'canvas'`。
  此时分章只用 **`CANVAS_IMPORT_RULE_SET`（只认「第N章」）**——**不能用通用规则集**，
  它的 `^(序章|序言|序|…)` 会把角色表表头「序号」切成假章。
  解析规则（`shared/text/canvas-script.ts`）：`【角色-CV】“台词”` → 角色行；其余段落 → 旁白；
  角色表（每格一行，或 `a | b | …` 单行）→ 角色。入库直接写 `canvas_lines`
  （`state = assigned`、`decided_by = human`，不需复核）并建角色，章节 `canvas_state = generated`；
  **不再做说话人判定**（否则会把 `【】` 标记当正文）。
  细节：章标题行不算台词；台词不要求独占一行（按 `【…】` 拆成「旁白/台词/旁白」，
  只把像说话人标记的 `【…】` 当台词，`【贝利法案】` 不误判，`（OS）` 作 note 并标 `inner`）；
  角色按名字复用（同名不重复建、**不覆盖用户改过的资料**），CV/音色/年龄写进角色备注；
  角色表用「**等长抹除**」处理（换行与字符偏移完全不变），按「表头前 6 列 + 首列是数字」识别整表，
  **不能要求固定 8 列 / 8 行**（DOCX 解析器会丢空单元格——实测曾漏 1151 行）。
- **P0（实际交付新增）追加到已有书籍**：`book:commitImport` 可选 `targetBookId`——不新建书，
  `seq` 从目标书 `nextSeq` 顺延，`start/endOffset` 叠加目标书已有正文长度，
  `chapter_count/char_count` 累加，书名/作者/封面/来源沿用；
  **目标书不存在 → `NOT_FOUND`，绝不静默新建**；追加不参与内容哈希去重。

**AC-1**：一份 30 MB 的 GBK TXT，在 60 秒内完成导入与分章；「第X章」与「序章/番外」全部正确切出；
章节总数与预期一致；导入可随时取消且不留下半个章节。

### FR-2 画本（域 `editor` + `book/canvas`）——全系统最核心、也最容易做错的一步

**切分与判定**

- **P0** 按段落/句读切分为画本行，保留原文偏移（`char_start`/`char_end`）以支持双向定位。
- **P0** 说话人**初筛**：基于引号族（`“”`、`「」`、`‘’`、`""`）、对话引导语
  （`说道/问道/喊道/答道/冷笑/喃喃`等）、破折号做「对白 / 旁白」粗分类。
- **P0** 说话人**判定**：每行取 embedding，与该章出场角色的**原型向量（centroid）**做余弦相似度，
  取最高分且超阈值者为归属；低于阈值判 `narration` 或 `unknown`。
- **P0** **上下文增强**：把「前后各 1~2 行 + 本节场景已有角色」拼入判定文本，
  解决「他点了点头。」这类无主语短句。
- **P0** 判定结果必须带**置信度**与**候选列表**（Top-3 角色 + 分数），UI 用颜色区分高/中/低置信，
  低置信进「待确认队列」。
- **P0** **可复算**：换模型/换阈值后能一键重算全部低置信行，**且不覆盖人工已确认的结果**。
- **P1** AI（LLM）辅助判定：可把「待确认行 + 角色表」提交 Provider 做二次裁决。
- **P0** 批处理：「一键确认全部高置信」+「按存疑筛选」。

**角色表与音色**

- **P0** 角色表增删改排序，含角色名、别名列表（`萧炎`/`炎帝`/`小炎子`）、性别、年龄段、
  性格描述、备注。
- **P0** 合并/拆分角色（合并时自动迁移台词与别名）；**P0**「批量改归属为某角色」。
- **P0** 角色 ↔ 配音员绑定：一角色一个主配音员 + 备选；一配音员可担任多角色。
- **P0** 角色级默认表演参数（默认语速、情绪基调、音量偏移），画本行未指定时继承。
- **P1** 自动抽取候选角色名：高频人名识别（对话引导语前的主语、称谓词频、姓氏+称谓）并给建议列表。
  ⚠️ 已知教训：候选里会有大量「常用词」，**只有人名形态能挡住**，抽取规则必须做形态过滤。
- **P1** 音色档案 `voice_profile`：参考样本、性别、音域、语速倾向、样本路径。

**表演标记**

- **P0** 情绪标记，预设 **14 种**（`EMOTIONS`，全应用唯一来源）：
  平静 / 喜悦 / 愤怒 / 悲伤 / 惊讶 / 恐惧 / 厌恶 / 嘲讽 / 激动 / 低沉 / 温柔 / 焦急 / 决绝 / 无奈，
  可自定义扩展。
- **P0** 语速标记 `slow`/`normal`/`fast` 或 -50%~+50% 相对偏移。
- **P0** 停顿标记：句内停顿（`/`）与句末留白时长（秒），**直接影响对轨时间线**。
- **P0** 发音提示 `pronunciation`（多音字、生僻字、英文缩写，如 `行(háng)`、`NVIDIA`）；
  **P0** 自由备注字段。
- **P1** 情绪强度 1~5；**P1** 音量标记 ±12 dB；**P1** AI 自动标注情绪与语速（标为「AI 建议」，
  可一键采纳/忽略）；**P2** 重音/强调标记。

**编辑器**

- **P0** **双视图**：表格视图（一行一记录，列=序/说话人/文本/情绪/停顿/状态，适合批量改）+
  剧本视图（连续阅读感，旁白与台词不同样式，适合精修）。
- **P0** 行内编辑：改文本、改说话人、改标记，**全部即时保存（防抖 500 ms）**。
- **P0** 键盘优先：`↑/↓` 移动、`Enter` 下一行、`Ctrl+1..9` 快速指派说话人、`空格` 试听该行。
- **P0** 查找替换（按文本/说话人/情绪筛选，正则替换，限定本章或全书）。
- **P0** 批量操作：批量改说话人、加/清标记、改停顿、合并相邻旁白行。
- **P0** 撤销/重做至少 100 步，覆盖文本与标记的所有变更。
- **P0** 画本质检 12 项：空行、超长行（>200 字）、未被使用的角色、引号不配对、
  纯旁白连续超 N 行、`unknown` 行数等。
- **P1** 章节级快照与版本对比（每次 AI 生成前自动打快照，可回滚、可 diff）；
  **P1** 文本与原文对照高亮。

**AC-2**：对一章 3000 字、含 60 句对白、8 个角色的文本，AI 生成画本后说话人判定准确率 **≥ 85%**
（以人工校对为基准）；所有低置信行可在 3 分钟内通过 UI 清理完；角色合并后无孤立引用；
停顿标记能正确传导到对轨时间线。

### FR-3 录音（域 `recording`）

- **P0** 设备管理：枚举输入设备、采样率（44.1/48 kHz）、位深（16/24/32f，落盘 WAV float32 或 24-bit）、
  声道（默认单声道）；设备诊断页显示实时电平、底噪、延迟估计。
- **P0** **逐行录制模式**：显示当前画本行 → 倒计时（可关）→ 录音 → `Enter`/空格/脚踏踏板停止 →
  自动写片段 → 自动跳下一行。
- **P0** **连续录制模式**：一路录到底，基于 VAD（自适应噪声底 + 能量 + 过零率）自动切片，
  切片结果按顺序或人工拖拽对齐画本行。
- **P0** **角色模式**：按当前配音员过滤，只显示其负责角色 + 旁白（可开关），用于任务包下发后自录。
- **P0** 多 take：同一行可录任意多次并全部保留，支持 A/B 试听对比与「选为成品」；
  被替换的 take **不删除**，进回收区（软删除）。
- **P0** 断点续录（默认从第一个未录行开始，可标记「从这里继续」，已有录音可选跳过或覆盖）；
  **P0** 断点回听（当前行已有 take、上一行、下一行，不必退出录音）。
- **P0** **监听返送**：录音时能听到已录轨道回放（BGM / 对手戏 / 已录旁白），监听音量独立可调；
  启用监听时自动开启 `echoCancellation` 或提示戴耳机。
- **P0** 输入处理：增益滑块（数字增益，写盘前）、AGC（默认关）、削波指示
  （**连续 3 个样本 ≥ 0.99 判定削波**）、防喷麦提示。
- **P0** 录音期间崩溃/断电**不丢素材**：增量写盘 + 启动时 WAV 头修复。
- **P0** 快捷键与外部控制：开始/停止/重录/上一行/下一行/播放；支持脚踏板映射为「停止并下一行」。
- **P0** 录音会话留存原始素材（`recording_session` 的 WAV 不因片段生成而删除），可随时回溯重切。
- **P0** 元数据：每个 take 记录设备、采样率、增益、时间戳、时长、峰值 dBFS、LUFS 初测。
- **P1** Punch-in 补录：在已有片段任意位置插入重录，**拼接处 5~30 ms 交叉淡化**，避免爆音。
- **P1** 实时波形 + 峰值/有效值电平表 + 录完显示缩略波形。

**AC-3**：戴耳机环境下连续录制 30 分钟后强制结束进程，重启能恢复出完整可播放的 WAV（头部已修复）；
逐行模式从选中行开始录 20 行全程无需鼠标；同一行 3 个 take 可 A/B 对比并选定成品。

### FR-4 对轨（域 `alignment`）

> 定义澄清：本项目「对轨」= **录制对齐 + 多轨对齐 + 人工微调**三件事的合集。

- **P0** **录制对齐**：每个 `voice_segment` 必须绑定到唯一 `canvas_line`；提供把「未绑定片段」
  拖到画本行、或把「未录行」匹配到片段的界面。
- **P0** 自动匹配：连续录制产生的片段序列，按「画本行顺序 + 时长合理性 + 可选 ASR 文本相似度」
  自动匹配，给出匹配置信度。
- **P0** **多轨对齐**：轨道 = 说话人（旁白轨 + 各角色轨），同角色片段按画本行顺序串行排布；
  轨道间按场景允许重叠。
- **P0** 留白计算：行间停顿 = `pause_after_ms`（为 0 则用章节默认值）；句内停顿按标记插入静音。
  留白优先级：**先压缩空白，再移动音频**。
- **P0** **重叠消解**：检测同轨/跨轨重叠，提供 4 种策略——`串行化`（后一段后移）、
  `保留交叠`（对话交叠更自然）、`压缩留白`、及逐条手动处理；冲突列表可逐条处理。
- **P0** 时间线视图：多轨波形 + 画本行块对照，横向缩放（样本级 ↔ 整章级），纵向缩放轨高。
- **P0** 手动微调：拖动起始时间、拖边裁剪、吸附网格（0.1 s / 0.5 s / 画本行边界），结果持久化。
  微调语义必须是「**内容位置不变**」——改 `offset_ms` 不改变片段内容。
- **P0** `offset_ms` 与源区间 `src_in_ms` / `src_out_ms` **分离存储**，非破坏性，随时可还原。
- **P0** 静音修剪：段首/段尾静音自动修剪（阈值可设），同时**保留 50~150 ms 呼吸留白**。
- **P0** 试听：从任意点播放混音预览（轻量实时混音）或只播某轨（solo）。
- **P0** 校验 11 项：缺行、孤儿片段、时长异常（<0.2 s 或 >60 s）、同轨重叠、跨轨不合理重叠、
  **`wrong_order` 错绑检测**等。
- **P1** 对轨方案可导出为 `arrangement`，供混音导出消费；同一章允许多个方案
  （如「快节奏版 / 舒缓版」）。
- **P2** **AI 强制对齐（1.0 只留接口与数据字段，不实现）**：用 whisper.cpp 词级时间戳反向校验
  片段实际内容与画本行文本，检出漏读/错读/串行。

**AC-4**：一章 87 行录音与 87 个画本行，自动匹配后错配 ≤ 2 处且都能被校验列表指出；
时间线 500 个片段滚动流畅（≥30 fps）；手动拖动后刷新位置不丢失。

### FR-5 音频处理（域 `processing`）

- **P0** 处理链（**有序、可开关、可调参，顺序固定**）：
  **高通 → 降噪 → 齿音抑制 → EQ（≥4 段参量）→ 压缩 → 限幅**。
- **P0** 降噪：优先 ffmpeg `afftdn`（可调噪声底/降噪量）；提供「采样噪声轮廓」辅助。
- **P0** 去齿音：`deesser` 或动态 EQ，可调中心频率与强度。
- **P0** EQ：低切、低架、峰值（参量）、高架、高切；可视化响应曲线 + 常用预设
  （男声清晰度/女声温暖/广播/去闷）。
- **P0** 压缩：阈值、比率、启动、释放、补偿增益；3 档预设（轻/中/重）。
- **P0** 限幅：真峰限幅 `alimiter`，上限默认 **-1 dBTP**。
- **P0** 预设系统：内置 + 用户预设，可保存/命名/导入导出（JSON）；支持「按角色套用预设」。
- **P0** 处理范围：单片段 / 某角色全部 / 某章节全部 / 全书；结果写入新的**派生文件（非破坏）**，
  可回退到原始。
- **P0** 处理耗时任务化：进任务队列，带进度、可取消、可查看失败原因。
- **P0** BGM / 音效轨：导入音频，配置入出点、循环、音量、淡入淡出包络。
- **P0** 自动闪避（ducking）：以人声总线为侧链，说话时 BGM 降 N dB，含启动/恢复时间与阈值。
- **P1** 修补工具：静音段填充、点击/爆音修复（局部淡入淡出）、DC 偏移去除、相位/极性反转；
  **P1** 变速不变调（`atempo`，±10% 内）用于对轨救急；**P1** 处理前后 A/B 试听。
- **P2** 敏感词处理（标记位置，导出时可选 `哔` 音替换或静音，保留原文件）。

**AC-5**：对带底噪与齿音的男声套预设后，主观可听出底噪显著下降且人声不发闷（A/B 试听为准）；
批量处理 100 个片段进度准确、取消后无残留临时文件；BGM 在人声出现时明确下潜且恢复自然。

### FR-6 混音与导出（域 `mixing`）

- **P0** 多轨混音：轨道 = 说话人轨 + BGM 轨 + SFX 轨；每轨有增益（dB）、声像、静音、独奏、
  处理链引用。
- **P0** 总线结构：`人声总线`（旁白 + 角色）→ 侧链源；`音乐总线`；`音效总线`；全部汇入 `主总线`
  后做响度与限幅。
- **P0** 响度标准化：默认目标 **-16 LUFS**（可改 -14 / -23），真峰上限 **-1 dBTP**；
  **两遍法（先测量后应用）**确保准确。
- **P0** 章节头尾：片头静音时长、片尾静音时长、可选「章节标题念白」（占位）。
- **P0** **分章导出**：一章一文件；MP3（128/192/256/320 kbps CBR/VBR）、WAV、M4A/AAC。
- **P0** **整本合并导出 M4B**：内嵌章节标记（chapter markers）、书名/作者/朗读/封面元数据、
  可选按章切分与位率。
- **P0** 文件命名模板：`{book}_{chapter:03}_{title}` 等占位符；输出目录按书建立。
- **P0** 导出前 QC：响度预检、峰值超标、静音异常（整章静音/超长空白）、缺行统计；
  不通过给明确清单，可选择「仍要导出」。
- **P0** 预览渲染：只渲染前 30 秒或某一章的「试混」，用于快速确认预设。
- **P0** 导出任务化与断点：可暂停/取消；已完成的章节不重复渲染。
- **P0** 项目包 `.nsp` 导出与导入；任务包 `.nst` 导出与回收。
- **P1** 导出后校验（重新测量成品 LUFS/峰值并写报告）；**P1** ID3/iTunes 标签与封面；
  **P1** 多方案导出（干声版/带 BGM 版/广播版）。

**AC-6**：一章 15 分钟音频导出 MP3 后，第三方工具测得响度在 **-16 ± 1 LUFS**、真峰 **≤ -1 dBTP**；
M4B 在常见播放器正确显示章节列表；取消导出后无残留临时文件；`.nsp` 换机器导入后画本、角色、
录音、对轨位置全部完整。

### FR-7 协作与任务包（域 `editor` + `recording` + `book/package`）

- **P0** 配音员管理：姓名、联系方式（可选）、备注、负责角色清单。
- **P0** 角色分工：画本页可查看「每个配音员的行数/字数/预估时长」，用于均衡分配。
- **P0** **`.nst` 导出**：该配音员的画本行清单（`line_id` 稳定）、角色信息、表演提示、
  录音设置建议、可选参考音。
- **P0** 配音员侧：导入 `.nst` → 只看到自己的行 → 角色模式录制 → 导出「录毕包」
  （takes 音频 + 与 `line_id` 的映射清单）。
- **P0** **回收合并**：按 `line_id` 归位，处理重复（提示择一）、缺漏（列出）、未知 line（拒绝并报告）。
- **P1** 回收日志（谁、何时、回传多少行、哪些被采纳）；**P1** 任务包版本化差异提示。

**AC-7**：为 4 名配音员导出 4 个 `.nst`，回收 4 个录毕包后全部行正确归位，

## 9. AI 抽象层与说话人判定（本项目的技术亮点，必须按此实现）

### 9.1 三层能力与 Provider 抽象

**先立三层能力模型，这是全部 AI 设计的骨架**：

| 层 | 内容 | 可用性硬约束 |
|----|------|--------------|
| **L1 规则** | 引号检测、对话引导语、分句、停顿推断、情绪词表、角色名抽取 | **无条件可用**（离线、零成本、确定性） |
| **L2 向量** | 本地 ONNX embedding + SQLite 中的原型向量 | **无条件可用**（离线） |
| **L3 LLM** | 低置信复核、情绪建议、角色抽取增强 | **可选**；每一次调用都要能被「跳过」而不破坏流程 |

> **AI 是加速器，不是依赖。**

**接口与实现**：

```ts
type ProviderKind = 'mock' | 'local' | 'openai-compatible' | 'dify'
interface ChatMessage { role: 'system' | 'user' | 'assistant'; content: string }
interface ChatOptions { model?; temperature?; maxTokens?; jsonSchema?; signal?; purpose?; allowCloud: boolean }
interface ChatResult { text; usage?: { promptTokens; completionTokens; totalTokens }; model; provider; latencyMs }
interface AIProvider {
  readonly kind: ProviderKind
  healthCheck(): Promise<{ ok: boolean; message: string; latencyMs?: number }>
  chat(messages: ChatMessage[], opts: ChatOptions): Promise<ChatResult>
  chatStream?(messages, opts): AsyncIterable<string>
}
interface EmbeddingProvider { modelId: string; dim: number; embed(texts: string[], signal?): Promise<Float32Array[]>; healthCheck() }
```

| 实现 | 职责 |
|------|------|
| `mock` | 开发/测试/演示，返回可预测的确定性假数据 |
| `local-echo` | 降级占位，返回「无法判定」而**不是抛错**，**永远作为链尾兜底** |
| `openai-compatible` | 覆盖 Ollama / vLLM / LM Studio / 兼容网关（HTTP） |
| `dify` | 对齐 Dify 应用（1.0 只做接口对齐，不联调） |

配套：

- **工厂 `resolveProvider(settings)`**：按 `settings.provider` 建链 → 末尾**永远** push `LocalEchoProvider`
  → 返回 `FallbackProvider(chain)`，依序尝试、失败自动下一个。
- **熔断**：链首 Provider 连续失败 **3 次 → 熔断 5 分钟**，期间只用兜底；
  **熔断状态必须 UI 可见**（设置页显示「Dify：已熔断，剩余 3:12」），**不允许静默降级**；
  事件 `provider:circuitChanged { provider, state: 'open' | 'closed', untilTs }`。
- **`allowCloud = false` 必须直接抛云端禁用错误**（不弹任何网络请求）。
- 并发上限默认 2（`p-limit`）、超时：连接 10 s / 首字节 60 s（流式空闲 30 s）；
  重试仅对网络类与 429/5xx，退避 1s → 4s 最多 2 次；读系统代理。
- 用量落 `ai_usage`：
  `{ id, projectId|null, purpose, provider, model, promptTokens, completionTokens, latencyMs, accepted|null, createdAt }`。

**本地 embedding 实现要点（踩过的坑，逐条照做）**：

- 模型 `bge-small-zh-v1.5`（ONNX），**dim 512**（以 `config.json` 的 `hidden_size` 为准，
  运行时校验，并把实际维度写进 `line_embeddings.dim`）；max 512 token。
- **必须用 CLS pooling**（bge 不是 mean pooling，用错效果显著下降）；池化方式登记在
  `resources/models/models.json` 的 `pooling` 字段。
- 输出后**立即 L2 归一化**；INT8 动态量化；`onnxruntime-node`，
  `intraOpNumThreads = min(4, cores/2)`；batch 默认 16，OOM 依次降 8/4/1；首次加载预热。
- int64 张量必须用 `BigInt64Array`；**张量名从 `session.inputNames` 动态读取**，不要硬编码。
- **`yieldToLoop()` 不可省**：ONNX 同步推理会阻塞主线程、卡死 UI。

### 9.2 Dify 适配要点（踩过的坑，必须写进文档）

- **接口差异**：Dify 应用是 `POST /v1/chat-messages`（字段 `query` + `inputs` + `conversation_id` + `user`），
  不是 OpenAI 的 `/v1/chat/completions`（`messages`）；不同应用类型路径不同
  （Chatflow / Agent / Completion → `/v1/chat-messages`，**Workflow → `/workflows/run`**）；
  响应字段是 `answer`；流式是 SSE（`event: message` / `agent_message`）；
  鉴权 `Authorization: Bearer {app-xxx}`（**应用级 Key，不是账号 Key**）；
  输入变量必须经 `inputs` 传入；**必须 `response_mode: 'blocking'` 才同步返回**。
- **适配策略**：把 messages 折叠成单个 `query`（`[role] content` 用 `\n\n` 连接），
  或要求工作流定义 `messages` 数组类型的字符串输入；`user` 用**稳定匿名 ID**，不传真实身份。
- **每次新建会话**：**不得**依赖 `conversation_id` 携带上下文。
- 原因：`conversation_id` 会累积上下文，用在批量逐行判定时导致**上下文污染**
  （第 500 行的判定被第 1 行影响）。
- 因此批量判定必须把上下文**显式放进 prompt**（见 §9.5 的模板）。

### 9.3 说话人判定算法（Step1–8，必须完整实现）

```
Step1 分句：换行 + 句末标点（。！？…；）切；单句 > maxLineChars(120) 时按逗号/分号二次切；
      过长句标 flags:['too_long']；保留 char_start/char_end
Step2 规则粗筛 kind：
      引号包裹 → dialogue（剥离引号后的内容存 text）；
      **引号外的文字各自成行 narration**（引号外的话一个字都不能丢）；
      行内短引号（≤4 字且前后都有叙述）→ 整句 narration（拟声/强调）；
      纯说话人标签（`萧炎说道：`/`无畏：`）不单独成行，已写进 cue；
      心理描写标志（想/心想/暗忖/心中一动）→ inner；其余 narration
Step3 角色名抽取：引导语前 2~6 字窗口人名；**剧本体行首主语**（`无畏：“你瞎啊…”`）；
      高频称谓（老X/小X/X儿/X兄/X老/X长老/X大人）；
      **人名形态证据**（姓氏开头含异体归一 / 音译名形态 / 角色称谓 / 行首说话人位置 /
      分词器 nr 词性，且 ≥5% 出现在句首）→ 候选角色表初稿（人工确认）
Step4 上下文拼装：context = [前 2 行, 当前行, 后 2 行]；
      dialogue 优先拼「最近的引导语」与「上一个说话人」
Step5 向量判定：embed(context) = v；score(c) = cos(v, centroid(c))；取 Top-3；
      best.score ≥ threshold 且 (best − second) ≥ margin → 归属 best；
      否则 needs_review = 1，candidates 存 Top-3
Step6 规则后处理（规则优先于向量）：引导语明确指名直接覆盖向量；行首说话人标签 / 行内主语
      （`沈绪推开殿门而入，“…”`）；引导语窗口被状语顶开时回到句首主语，主语取
      「处在主语边界上」的提及（`代掌教的沈绪` → 沈绪）；引号前出现多个角色名时给结论但标待确认；
      连续对白偏向上一说话人（**同一句原文切出的旁白行不打断此链——字符区间是包含关系**）；
      场景内角色过滤（只在本节已出场角色中判定）；**短句 <6 字跳过向量**，强制依赖上下文与规则
Step7 低置信复核（L3，可选）：仅对 needs_review 行调用，一次一批（默认 20 行）；
      返回 { lineId, character, confidence, reason }；LLM 置信度 ≥ 阈值才采纳，否则仍标人工
Step8 落库：写 canvas_lines + line_embeddings，**增量**更新 character_centroids，
      统计各角色行数、低置信比例、规则覆盖比例
```

**阈值与置信度（默认值必须原样，且全部可在设置里改）**：

| 参数 | 默认 | 含义 |
|------|------|------|
| `canvas.attributionThreshold` | **0.62** | 低于此分不归属任何角色（判 narration/unknown） |
| `canvas.attributionMargin` | **0.06** | Top1 − Top2 的差值下限 |
| `canvas.contextWindow` | **2** | 上下文取前后各 N 行 |
| `canvas.autoAcceptConfidence` | **0.85** | 「一键确认全部高置信」的门槛 |
| `canvas.maxLineChars` | **120** | 超长行切分与质检阈值 |
| 短句阈值 | **6 字** | 短于此不走向量 |

- 余弦即点积（向量已 L2 归一化）。
- **阈值必须可实测**：提供「判定质量评估」工具——人工确认 100 行后扫描 0.5~0.8，
  输出「准确率-覆盖率」曲线，供用户自选工作点。
- **度量埋点**：`人工修改率 = 用户手动改过的行数 / 总行数`，写 `metrics` 表（按作品/章节）；
  某章 >40% 时建议人工过一遍；**目标 ≤15%（即准确率 ≥85%，AC-2）**。
- UI 置信度色带：**≥0.85 绿、0.62~0.85 黄、<0.62 红、人工确认（decidedBy='human'）蓝**。

**重算与增量的正确语义（这几条最容易做错）**：

| 触发 | 正确行为 |
|------|----------|
| 文本被人工编辑 | `content_hash` 变化 → **只重算该行** |
| 人工改了说话人 | `decided_by='human'`，**永不自动覆盖**；同时从旧角色 sum_vector 减、向新角色加 |
| 新建 / 合并角色 | 全章重算（合并要先迁移台词再重算） |
| 换 embedding 模型 | 全项目重算（向量空间不可比），**UI 必须警告 + 给出预计耗时** |
| 只调阈值 | 只重跑判定，**不需要重新 embedding** |

→ 因此 **`line_embeddings` 与判定结果必须分离存储**（否则调阈值会白跑一轮推理）。

**原型向量（centroid）**：`centroid(c) = normalize(mean(normalize(e(line_i))))`，人工确认优先；
先算均值，再剔除与均值余弦 **<0.3** 的离群样本后重算一次；为支持可逆增量，
额外存未归一化的 `sum_vector` 与 `sample_count`，`centroid` 是二者算出的快照；
冷启动用「角色名 + 别名 + 性格描述 + 首次出现上下文」合成文本作初始原型，首轮判定后立刻迭代一次。

**向量存储三条必须遵守的规则**：写入前 **L2 归一化**；必须记录 **`model_id`**；必须记录 **`content_hash`**。

### 9.4 结构化输出三层防护

`callStructured<T>()` 的确定性流程：

```
最多 3 次尝试循环：
  raw = provider.chat(messages, { jsonSchema, ... })
  → stripCodeFence()   // 去掉 ```json 围栏
  → tryJsonParse()     // 提取首个 {...} 或 [...]
  → schema.safeParse() // 严格校验
  → allIdsValid(data, opts.expectedIds)   // 防幻觉 ID：返回的 lineId 必须都在请求集合内
  成功 → 返回
  失败 → 修复轮：把 { role:'assistant', content: raw.text }
                 + { role:'user', content: '你的输出不符合要求，错误：…\n请只输出合法 JSON。' }
                 追加回传后重试
3 次仍失败 → throw AppError('AI_INVALID_OUTPUT')
```

三层防护的职责：

1. **提示层**：「只输出 JSON」+ 给出 schema 示例 + 少样本（few-shot），提高格式服从度。
2. **解析层**：容忍代码围栏、前后废话、尾随逗号，提取首个合法 JSON。
3. **语义层**：schema 校验 + 枚举白名单 + **ID 存在性校验** + 长度限制。

**失败处理**：3 次失败 → 该批次标记「AI 不可用」，**退回规则结果、不阻塞用户**，并在报告里说明。
（结构校验用项目自研的极简 schema 原语 `src/main/infra/validate/`，避免离线环境下 zod 不可用；
两者语义等价，`schemaFromShape` 负责从「形状」生成 JSON Schema 与校验器。）

### 9.5 Prompt 模板（必须带版本号，原文照用）

模板结构：

```ts
interface PromptTemplate {
  id: string
  version: number          // 每次修改递增；与结果一起记录，便于回溯
  purpose: 'attribution_review' | 'emotion_tag' | 'canvas_struct' | 'character_extract'
  system: string
  userTemplate: string     // 含 {{变量}} 占位
  outputSchema: JsonSchema
  examples?: Array<{ input: string; output: string }>   // 少样本，提高格式服从度
}
```

**调用时必须把 `id + version` 与结果一起记录**——这样「同样的输入为什么结果不同」才有得追溯，
缓存键也才稳定。

**模板 1 · `attribution_review`（说话人复核）**

```
system:
你是一个中文有声书制作助手。你的任务是判断一句台词/旁白归属于哪个角色。
只依据给定的上下文与角色列表判断，不要编造角色。
如果依据不足，把 speaker 设为 "narration" 并把 confidence 设为 0。
必须只输出 JSON，不要输出任何解释性文字。

user:
## 角色列表
- {{name}}（别名：{{aliases}}）；性格：{{desc}}

## 上下文
{{index}}. {{text}}

## 待判定行
行号：{{lineIndex}}
内容：{{text}}

## 输出格式
{"lineId":"{{lineId}}","speaker":"角色名或 narration","confidence":0.0,"reason":"不超过20字"}

输出 schema: { lineId, speaker, confidence(0..1), reason(≤40 字，可选) }
few-shot: 输入「我萧炎，从来不会认输。」→ {"lineId":"line-12","speaker":"萧炎","confidence":0.92,"reason":"引导语明确指名"}
```

**模板 2 · `emotion_tag`（情绪与语速标注）**

```
system:
你是中文有声书的配音指导。为给定句子标注情绪与语速，用于指导配音演员。
情绪只能从给定列表中选择；语速只能是 slow/normal/fast。
必须只输出 JSON 数组，不要输出任何解释性文字。

user:
## 可选情绪
{{emotionList}}

## 句子列表
{{index}}. [lineId={{lineId}}] {{text}}

## 输出格式
[{"lineId":"xxx","emotion":"决绝","intensity":4,"speed":"fast","reason":"..."}]

输出 schema 根节点是数组：{ lineId, emotion(enum=EMOTIONS), intensity(1..5), speed(enum), reason(可选) }
```

**模板 3 · 角色抽取（`character_extract`）** 的 system 要点：

```
你是中文小说的角色抽取器。只输出 JSON，不要解释；
只抽真正出场的人物名，排除地名/组织/泛称/代词。
```

> 已知教训：抽取规则若只做词频，会抽出大量常用词碎片；**必须做人名形态过滤**（姓氏+称谓、
> 引导语前主语等），否则角色表不可用。

未实现的 purpose 必须**显式抛 `NOT_IMPLEMENTED`**，不得返回空模板或静默降级。

### 9.6 缓存键、TTL、用量与降级矩阵

**缓存键（三套，不要混用）**：

| 对象 | 键 | 落点 |
|------|----|------|
| Embedding | `sha256(modelId + '|' + text)` | SQLite `line_embeddings`（按 `content_hash` 命中） |
| 说话人复核 / 情绪标注 | `sha256(promptId + version + model + 输入集合的稳定哈希)` | SQLite `ai_cache` |
| ASR | `sha256(audioFile)` | `cache/asr/{hash}.json` |

- 稳定哈希用 `fast-json-stable-stringify`（键序必须稳定，否则缓存永远不命中）。
- `ai_cache(cache_key PK, purpose, model, provider, response, created_at, hits DEFAULT 0)`；
  **TTL 30 天**；命中 `hits++`（用来分析哪些提示词值得固化）。
- **文本编辑 → `content_hash` 变化 → 只重算该行**，不重算整章。

**成本策略**：只送低置信行（`needs_review = 1`，通常 10%~20%）；一次批量 20 行；
上下文默认 2 行；单行 >200 字先截断并标注；本地优先（情绪先命中 L1 词表「冷笑/怒吼/喃喃」才调 LLM）；
设预算上限（单任务最大调用次数 / 最大 token，默认不限但显示预估消耗）；
**首次云端调用必须弹窗**「本次将发送约 N 行、约 M 字到 \<域名\>」并记住选择。

**降级矩阵（每一格都要落到代码，且 UI 可见）**：

| 故障 | 行为 |
|------|------|
| 模型缺失 / 校验不符 | 规则判定 + UI 明确提示「向量判定不可用」 |
| ONNX OOM | batch 16 → 8 → 4 → 1 → 逐行；仍失败标「未判定」进人工队列 |
| Provider 不可达 / 熔断 | 规则词表标情绪，低置信行全进人工队列；画本页提示「AI 增强不可用」 |
| `allowCloud = false` | 同「不可达」，但**不产生任何网络请求** |
| 角色表为空 | 先跑 L1 抽取候选，提示确认后再判定 |
| 全章对话无引导语 | 报告告警，并降低 `autoAcceptConfidence` 后交由人工 |

**隐私**：默认 `ai.provider = 'mock' | 'local'` 且 **`ai.allowSendTextToCloud = false`**；
切云端必须勾选确认；发送内容最小化（不发全书、不发文件路径、不发用户名）；
**AI 请求与响应体不写日志**（只记长度、耗时、状态码）；诊断包不含作品正文。

## 10. 音频管线关键参数（必须写进 `05-音频管线.md` 并落到代码）

### 10.1 采集与落盘

- 采集：渲染进程 AudioWorklet，**float32 PCM**，固定大小环形缓冲 + 无分配写入路径 +
  预分配 `ArrayBuffer` 池（防 GC 抖动）。
- 传输：`MessagePort`（主进程侧创建、`MessagePortMain.start()`、发送不带 transfer 列表；
  每 50 ms 一批，约 9 KB）。
- 落盘：主进程**追加写** `.tmp` WAV + **每秒 fsync** + 记录样本数；停止时**定稿头部**。
- **采样率不匹配时在采集侧重采样到工程统一采样率**，避免后续对轨漂移。
- **录音写入丢帧率必须为 0**（写入样本数 vs 采集样本数可比对）。

### 10.2 崩溃恢复

- 启动扫 `projects/*/recordings/*.tmp` → 依据实际数据长度**修复 WAV 头** → 生成 `session` 记录。
- 修复必须在「清理临时文件」**之前**执行（否则直接丢用户录音）。

### 10.3 VAD 切片

- 自适应噪声底（**10 分位噪声底**）+ 能量 + 过零率；**边界精修**避免切掉字头/字尾。
- 切片结果写 `vad_slices`，与画本行按顺序或人工拖拽对齐。

### 10.4 静音修剪与拼接

- 段首/段尾静音自动修剪（阈值可设），**同时保留 50~150 ms 呼吸留白**（留白太少会显得急促）。
- Punch-in 拼接处 **5~30 ms 交叉淡化**，避免爆音。

### 10.5 削波与电平

- 削波判定：**连续 3 个样本 ≥ 0.99**。
- 每个 take 记录峰值 dBFS 与 LUFS 初测（`audio_metrics`）。

### 10.6 对轨时间线

- 行间留白 = `pause_after_ms`，为 0 用章节默认值；句内停顿按 `/` 标记插入静音。
- 留白优先级：**先压缩空白，再移动音频**。
- 重叠消解 4 策略：串行化 / 保留交叠 / 压缩留白 / 手动逐条。
- 时间线位置全部是「相对量」：`offset_ms` + `src_in_ms` / `src_out_ms`，**非破坏性**。

### 10.7 处理链与响度

- 滤镜链顺序**固定**：高通 → 降噪（`afftdn`）→ 齿音（`deesser`）→ EQ → 压缩 → 限幅（`alimiter`）。
- 限幅上限 **-1 dBTP**。
- 响度：目标 **-16 LUFS**（可改 -14 / -23），真峰 **-1 dBTP**，**两遍法**：
  第一遍 `loudnorm` 测量（解析 JSON 输出）→ 第二遍按测得的线性增益应用。
  理由：单遍是动态的，逐章响度不齐。
- 混音图：`amix` + `sidechaincompress`（ducking）+ `loudnorm` 两遍；分批构建滤镜图避免命令行过长。
- 导出：分章 MP3/WAV/M4A；整本 M4B（`concat` + `ffmetadata` 章节标记 + 封面/元数据）。
- **ffmpeg 调用一律 `spawn` + 参数数组（不经 shell）**，并发 `min(4, cores-1)`。

### 10.8 参数速查表（默认值必须原样落地，全部可在设置里改）

| 项 | 值 |

**对轨**

| 项 | 值 |
|----|----|
| 匹配权重 | `score = w1*duration + w2*text + w3*order`，默认 **0.45 / 0.45 / 0.10**；无 ASR 时 **0.8 / 0 / 0.2** |
| 预期时长 | `字数 / 语速 × 情绪系数`，中文默认 **4.2 字/秒**，`slow×0.85`、`fast×1.18` |
| 匹配算法 | DP（DTW 风格）求全局最优单调匹配 |
| 留白优先级 | `line.pauseAfterMs` > 角色默认 > 章节默认 **500 ms** |
| 场景切换 | **1200 ms**；章首 `headSilenceMs` **500**；章尾 `tailSilenceMs` **1500** |
| 节奏乘数 | 紧凑 **0.8** / 标准 **1.0** / 舒缓 **1.3** |
| 同轨重叠 | **必须消解**（上限 0 ms）；`serialize` 默认 `start_b = end_a + minGapMs 50` |
| 跨轨重叠 | ≤ `maxOverlapMs` **3000 ms** 保留；>3000 ms 或无人说话空隙 **>5 s** 报告 |
| 四策略 | `serialize`（默认）/ `keep` / `compress-pause`（先压前段留白）/ `tighten`（`end_a + 20 ms` + 修剪尾静音）；**逐条处理优先于全局** |
| 静音修剪 | 阈值 **-45 dBFS**；起/尾留白 **100 / 120 ms**（呼吸留白 50~150 ms） |
| 微调步进 | `←/→` **±10 ms**、`Shift` **±1 ms**、`Ctrl` **±100 ms**；吸附默认开（`Alt` 关），网格 **0.1 / 0.5 s** |
| 微调语义 | 拖整体改 `timeline_start_ms`；**拖左边缘必须反向补偿 `srcInMs' = srcInMs + Δ`（内容绝对位置不变，必须单测）**；拖右边缘改 `srcOutMs`；独立 undo 栈 **≥50 步** |
| 校验 12 项 | `missing_line / unarranged_line / orphan_segment / same_track_overlap / cross_track_overlap_warn / long_gap / short_segment(<200ms) / long_segment(>60s) / silent_segment(RMS<-60dBFS) / clipped_segment / file_missing / wrong_order` |
| 口径澄清 | `missing_line` 的判定源是 **`voice_segments`**，不是「方案里没有条目」（后者是 `unarranged_line`）；跨轨正常交叠**不得误报** |
| 波形 | 峰值缓存 `cache/peaks/*.bin`，**100 peaks/s**，**3 级 LOD 100/10/1**；`OffscreenCanvas` + Worker；时间线用 Canvas 自绘（不用 DOM），轨内按 `timelineStartMs` 二分命中 |
| 性能 | **1000 item 拖动 ≥30 fps**（目标 60），多轨同步误差 **<5 ms** |

**处理链**

| 项 | 值 |
|----|----|
| 顺序（固定不可换） | ①修补前置(去 DC/极性反转) ②高通 ③降噪 ④去齿音 ⑤EQ ⑥压缩 ⑦限幅 ⑧修补后置(declick/静音填充/变速) |
| 排序理由 | 压缩会抬起噪声 → 降噪必须在 EQ/压缩前；齿音瞬态会误触发压缩器 → 去齿音必须在压缩前 |
| 默认滤镜串 | `highpass=f=80:poles=2, afftdn=nr=12:nf=-30, deesser=i=0.5:f=0.5, equalizer=f=200:t=q:w=1:g=-2, equalizer=f=3000:t=q:w=1.2:g=2.5, acompressor=threshold=-18dB:ratio=3:attack=8:release=180:makeup=2, alimiter=limit=0.891:attack=5:release=80` |
| 限幅 | `limit=0.891` = **-1 dBFS**（`10^(-1/20)`）；**`alimiter` 是采样级限幅不是真峰限幅**，真峰兜底放在响度处理后 |
| 参数范围 | `nr` 0.01~97（建议 **6~18**）；`nf` **-80~-20**，默认 **-30**（必须接近实际噪声底，否则吃字或无效）；`deesser i/f` 0~1（`f=0.5 @48k ≈ 12 kHz`）；`equalizer` 统一 `t=q` |
| 必须实测 | `acompressor.makeup` 单位（线性倍数 or dB；或改用链尾 `volume=XdB`）、`alimiter.limit` 是线性 0~1 非 dB、`afftdn` 的 `nf/nr` 版本差异 → 启动跑 `ffmpeg -h filter=afftdn` 生成 **`ffmpeg-capabilities.json`**，UI 按能力渲染控件 |
| 工作格式 | `aresample=48000 → aformat=sample_fmts=s32:channel_layouts=mono → 处理链 → 输出 pcm_s24le 48000 mono` |
| 输出命名 | 含 `presetHash`（`abc123.a1b2c3d4.wav`），换预设不覆盖；同批格式必须一致 |
| 内置预设 7 个 | 男声·旁白·沉稳 / 女声·角色·明亮 / 广播·有力 / 手机录音·抢救 / ASMR·贴近 / 老录音·去嘶声 / 仅修剪；**内置预设不可直接编辑**，编辑即创建副本 |
| 修补工具 | 去 DC `highpass=f=10:poles=1`；极性反转 `aeval=val(0)*-1:c=same`；declick 区间 **5~20 ms** 淡入淡出；静音填充带 **5 ms** 边缘淡化；**局部删除危险**（改时长 → 对轨需重算，必须二次确认）；`atempo` **0.9~1.1** |
| 批量 | `dedupeKey = process:{segmentId}:{presetHash}`，hash 未变则 skip；**失败不中断**继续下一个；临时文件统一 `cache/tmp/{taskId}/`，任务结束（含取消）无条件清理；取消 = 停派发 + `SIGTERM`，**2 秒后 `SIGKILL`**，已完成结果保留；报告必须含**「查看命令」**（完整 ffmpeg 命令行可复制） |
| 空间预估 | 批量输出 = 输入 **× 1.2**；单片段 >10 min 提示 |
| BGM/SFX | 支持 mp3/wav/m4a/flac/ogg，复制到 `projects/{id}/music/{bgm\|sfx}/`；自动读时长/采样率/峰值；**自动推荐 BGM 比人声低 18~24 dB** |
| Ducking | `amountDb` **-12**、`thresholdDb` **-30**、`attackMs` **20**、`releaseMs` **400**；`[music][voice]sidechaincompress=threshold=0.02:ratio=8:attack=20:release=400:makeup=1:level_sc=1`；**侧链源必须用人声总线**（角色台词也要压 BGM）；常见错误：Solo 时侧链源被静音→不降、`threshold` 用错单位、`release` 太短→抽气 |

**混音与导出**

| 项 | 值 |
|----|----|
| 两层方案 | 对轨方案（`arrangement`）与混音方案（`mix_project`）是**两层，不要合并** |
| 总线 | `voiceBus`（旁白+角色，同时 `asplit` 出侧链源）+ `musicBus` + `sfxBus` → 主总线 → 响度 → 限幅 |
| 四条必记 | ①**`amix=normalize=0`**（默认按 1/N 衰减，音量大跌）②**`apad=whole_dur={chapterDur}`**（不加则只出前几秒，头号原因）③**`adelay={ms}\|{ms}` 单声道也要写两个值**④**无 item 的轨不要加入 `amix`**（空输入让整个图失败） |
| 时长口径 | 必须与对轨共用同一函数 `chapterDurationMs = max over tracks(lastItem.timelineStartMs + itemDuration) + tailSilenceMs`；渲染后偏差 **>1 s** 打警告 |
| 响度两遍法 | Pass1 测量 `loudnorm=I=-16:TP=-1:LRA=11:print_format=json` 解析 `input_i/input_tp/input_lra/input_thresh/target_offset` → `gainDb = target_I - input_i`（**线性增益，保持动态**）→ Pass2 `-af volume={gainDb}dB,alimiter=limit=0.891` → Pass3 复测，偏差 **>0.5 LU** 微调一次 |
| 不要做的事 | **不要用 `loudnorm` 跑第二遍**（动态归一化会压动态、逐章不齐，单遍偏差常 ±2 LU） |
| 目标 | 逐章独立归一到 **-16 LUFS**（可选 -14 / -23），真峰 **≤ -1 dBTP**（超则再降 0.5~1 dB） |
| 短章 | **<60 s** 时 `input_i` 不稳 → 用相邻章平均增益校正并提示 |
| 验收 | 以第三方测量为准（`ebur128` / Audacity）；降级：`loudnorm` 不可用则 `ebur128` + 手算增益 |
| 分章导出 | MP3 `-c:a libmp3lame -b:a 192k -ar 44100 -write_xing 1 -id3v2_version 3`（默认 44.1 kHz / 192 kbps）；WAV `pcm_s24le`；M4A `-c:a aac -b:a 192k -movflags +faststart`；元数据 `title/artist/album/album_artist/track("{i}/{total}")/genre="Audiobook"/comment/date` + 封面 `attached_pic` |
| 整本 M4B | `chapters.txt` 用 `;FFMETADATA1` + `[CHAPTER]` + `TIMEBASE=1/1000` + **整数毫秒**，**严格连续无缝**（上一章 END = 下一章 START，用累积时长避免浮点误差）；命令 `ffmpeg -f concat -safe 0 -i list.txt -i chapters.txt -map_metadata 1 -map_chapters 1 -c:a aac -b:a 96k -ar 44100 -ac 1 -movflags +faststart out.m4b` |
| M4B 坑 | **`-map_chapters 1` 不加则章节丢失**；章数 **>200** 建议按卷拆分（部分播放器 >255 章异常）；单文件 **≤ 24 h**；编码器用 `aac`（`libfdk_aac` 有许可问题） |
| 命名模板 | `{bookTitle}/{chapterIndex:03}_{chapterTitle}`；清洗 `\ / : * ? " < > \|` 与控制字符；UTF-8 字节截断 **120**；冲突加 `_2`；占位符 `{bookTitle}{author}{chapterIndex}{chapterIndex:03}{chapterTitle}{narrator}{date}`；输出目录含 `export-report.json` |
| 断点 | `paramsHash = hash(混音方案 + 对轨方案版本 + 处理预设 + 响度参数 + 导出参数)`；同 hash 且文件存在 → skip（120 章整本可能跑 1 小时） |
| 渲染后 QC | 响度偏差 **\|Δ\| ≤ 1.0 LU**；真峰 **≤ 目标**；章间响度差 **≤ 1.5 LU**；整章 RMS **<-60 dBFS → 阻断**；单段静音 **>10 s**（非头尾）警告；时长偏差 **≤ 1 s**；连续削波 **>0** 警告；`ffprobe` 读不出 → **阻断该章**；`input_i = -inf` → **阻断该章** |
| 预览 | 长章节只渲**前 30 秒 + 中间 15 秒 + 末尾 15 秒**；Web Audio 试听与 ffmpeg 结果可能不一致（尤其 ducking 与响度）→ **必须用渲染预览验证** |
| 性能与空间 | 15 min 音频完整渲染（含两遍响度）**≤ 3 min**；混音中间 WAV 空间 ≈ **时长 × 288 KB/s** |

## 11. 错误体系与消息纪律（三级兜底）

### 11.1 要解决的三件事

| 问题 | 机制 |
|------|------|
| 出错时该说什么？ | **消息表集中管理**（`src/shared/messages.ts`），**任何模块不得硬编码用户可见文案** |
| 错误码怎么记、怎么报？ | **双轨编号**：语义键（如 `RECORD_DEVICE_LOST`）+ 派生数字编号（如 `E200005`），统一日志字段 |
| 没预料到的异常怎么办？ | **三级兜底**：业务显式抛 → 边界包裹 → 全局钩子/错误边界 |

### 11.2 三级兜底（每级都留痕）

```
第一级 · 业务显式抛出
  throw AppError.of('RECORD_DEVICE_LOST', { params: { device: 'USB Mic' } })

第二级 · 边界包裹（必须装，否则下面全部失效）
  · IPC handler 入口（src/main/ipc/registry.ts）→ 校验 + 执行 + 统一转 {ok,data,error}
  · 后台任务执行器（队列 runner）→ 异常转业务异常 + 任务标记 failed，不中断整批
  · 服务层入口（可选）→ 附加 projectId/chapterId 上下文

第三级 · 全局钩子 + 错误边界
  主进程：uncaughtException / unhandledRejection → 日志 + 通知渲染 + （生产）优雅退出
  渲染进程：app.config.errorHandler / window.onerror / unhandledrejection /
           router.onError / <ErrorBoundary> → 统一兑现提示
```

### 11.3 关键接线点（这就是「有没有真接上」的验收点）

| 位置 | 必须做的事 |
|------|------------|
| `src/main/ipc/registry.ts` | handler **永不 throw**，一律返回 `{ ok, data }` 或 `{ ok: false, error }`。抛出去会让 Electron 丢掉 `code/severity/retryable`，只剩一个字符串 |
| `src/main/infra/errors/install.ts` | 在**创建窗口之前**装配全局钩子；致命错误先执行「录音定稿」再通知再退出 |
| `src/main/ipc/events.ts` | 主进程主动推送的错误走 `app:error` 事件（否则用户永远不知道主进程出了问题） |
| `src/renderer/src/shared/lib/ipc.ts` | 统一解包 `{ok,error}` 并调用 `reportError`；**组件禁止直接 `window.api.invoke`** |
| `src/renderer/src/shared/lib/error-bus.ts` | 唯一出提示的口子：分级展示 + 去重合并 + 日志 |
| `src/renderer/src/app/error-handler.ts` | 挂载前调用；覆盖 Vue / window / promise / 路由四条路径 |
| `src/renderer/src/shared/ui/ErrorBoundary.vue` | 包住 `<router-view>`，页面级异常只退化该区域而不是白屏 |

### 11.4 三条不可违背的规则

1. **取消不是错误**：`AbortError` → 语义键 `TASK_CANCELLED` → UI **不弹提示**、日志写 `info`。
   用户主动取消却弹一个红框，是常见但很糟的体验。
2. **不重复包裹**：`wrapUnknown` 遇到已是业务异常的对象必须**原样返回**，否则用户会看到
   「发生了未预期的错误」而不是真正原因。
3. **错误处理路径本身永不抛错**：未知语义键回退 `INTERNAL`、插值缺参数退化为 `—`、
   通知窗口失败只记日志。兜底机制自己崩掉是最糟的情况。

### 11.5 验收标准（可测）

| 项 | 标准 |
|----|------|
| 全覆盖 | 主进程与控制台**零未处理异常**（跑完整 E2E 流程后检查） |
| 不泄露 | 任意错误提示的 UI 文本不含：绝对路径、`ffmpeg`/`SQLite`/`EACCES`、堆栈、`undefined` |
| 可定位 | 每条错误日志都有 `numericCode` 与非空 `causeChain`（业务显式抛的除外） |
| 不刷屏 | 1.5 s 内同一错误触发 5 次 → 只出现 1 条提示且显示「已发生 5 次」 |
| 不白屏 | 任一路由组件抛错 → 显示兜底区域，导航仍可用 |
| 取消静默 | 取消录音/导出 → 无任何错误提示 |
| 编号稳定 | `listAllCodes()` 快照测试通过（防止段内顺序被破坏导致编号漂移） |

### 11.6 双轨编号的派生规则（必须确定性，不许手写）

- **语义键（主）**：`RECORD_DEVICE_LOST` —— 代码里的稳定标识，TS 可补全可穷举，给开发看。
- **数字编号（派生）**：`E200005` —— 日志 / QA 单 / 用户报障口述，给支持看。
- **数字编号不手写**，由语义键确定性导出：`段号 + 段内序号`，共 5 位；
  `resolveCode('RECORD_DEVICE_LOST') → 'E200005'`；段内序号按 `messages.ts` 中**该段的声明顺序**生成。
- 段号分配：

  | 段 | 领域 |
  |----|------|
  | `1` | GENERIC（校验/权限/磁盘/未知兜底） |
  | `2` | RECORD（录音/设备/切片/片段/处理链） |
  | `3` | BOOK / IMPORT |
  | `4` | EXPORT（混音与导出） |
  | `5` | CANVAS（画本/角色/任务包） |
  | `6` | AI（Provider / embedding / ASR / TTS） |
  | `7` | DATA（数据库/项目包/备份/文件系统） |
  | `8` | TASK / QUEUE |
  | `9` | APP（生命周期/窗口/更新） |
  | `0` | INTERNAL（框架内部与未捕获异常兜底） |

- **纪律 1（与数据库迁移同性质）**：**新增消息只能追加在所属段的末尾**，
  **禁止在段中间插入或删除条目**——否则该段后续编号整体漂移，历史日志会指向别的错误。
  **发布即冻结**；必须废弃时保留定义并标 `deprecated: true`，而不是删行。

### 11.7 消息表与文案纪律

```ts
interface ErrorMessage {
  title: string        // 用户看到的标题，一句话，≤24 字，不带句号
  detail?: string      // ≤60 字；未知原因时留空
  hint?: string        // 用户可执行的下一步（纯文案，动作由 action 决定）
  severity: 'info' | 'warning' | 'error' | 'fatal'
  action: 'retry' | 'open_settings' | 'open_folder' | 'reload' | 'contact_support' | 'dismiss' | 'none'
  retryable?: boolean  // 默认 true
  dev?: string         // 开发补充，只进日志与诊断包，不进 UI
  params?: readonly string[]
  deprecated?: boolean
}
```

- 占位符**必须裸写并用中文书名号包裹**：`文件「{name}」可能已被移动。`
  **不要**写成 `文件“{name}”…`——全角引号会让 `validatePlaceholders()` 与
  `gen-error-docs.ts` 的正则 `\{(\w+)\}` 漏判，于是「params 声明了却校验不出使用」。
- 文案纪律：① **不出现技术名词**（不写 `ffmpeg`、`SQLite`、`EACCES`、`IPC`、`undefined`、堆栈、
  含用户名的绝对路径）；② **必须可行动**；③ **不甩锅**（不要写「操作失败」，
  要写清哪一步失败、为什么、怎么办）；④ 英文/路径等原样内容用参数传入并加引号。
- **一个码一件事**：`FFMPEG_FAILED` 不区分降噪/混音失败，差异由 `params.task` 表达；
  **只有能给出不同建议的才拆码**（`MODEL_MISSING`「去放置模型」vs
  `MODEL_CHECKSUM_MISMATCH`「模型损坏需重新拷贝」）。
- 系统错误映射集中在 `SYSTEM_ERRNO_MAP`（**新增系统错误时只改这里**）：
  `ENOENT→FILE_NOT_FOUND`；`EACCES/EPERM→PERMISSION_DENIED`；`ENOSPC→DISK_FULL`；
  `EMFILE/ENFILE→INTERNAL`（hint 请重启应用）；`EBUSY→FILE_BUSY`；`EROFS→PERMISSION_DENIED`；
  `SQLITE_BUSY/LOCKED→DB_BUSY`；`SQLITE_CORRUPT/NOTADB→DB_CORRUPT`；`SQLITE_FULL→DISK_FULL`；
  `ERR_MODULE_NOT_FOUND→INTERNAL`（hint 安装可能不完整）；
  `ETIMEDOUT/ECONNRESET/ENOTFOUND→PROVIDER_TIMEOUT/PROVIDER_ABORTED`；
  `MEDIA_ERR_*`/`NotAllowedError`(getUserMedia)`→DEVICE_PERMISSION`。
  不映射的话，90% 的兜底都会退化成「发生了未知错误」。

### 11.8 分级展示与去重

| severity | 展示 | 是否阻断 |
|----------|------|----------|
| `info` | 顶部轻提示 | 不阻断（取消、降级告知如「已改用规则判定」） |
| `warning` | Toast 3 秒 + 可展开详情 | 不阻断（文件过大、抓取被拒、模型缺失） |
| `error` | Toast 5 秒 + 重试按钮；关键流程用 Modal | 部分阻断（导入/导出失败、录音设备丢失） |
| `fatal` | **Modal 不可自动关闭** | 阻断（数据库损坏、磁盘满、录音写入失败、主进程异常） |

- `action` → 按钮：`retry`「重试」（由调用方注入 `retryFn`，未注入不显示按钮）、
  `open_settings`「前往设置」（`router.push('/settings', { query: { focus: code } })`，
  设置页按 code 高亮）、`open_folder`「打开文件夹」（`app:showItemInFolder`）、
  `reload`「重新加载」（fatal 可用 `app:relaunch`）、
  `contact_support`「导出诊断包」（`app:diagnostics`）、`dismiss`/`none` 无按钮。
- 去重键 `key = \`${code}|${stableStringify(params)}\``；1.5 秒内相同键更新已有 toast 标题为
  「\<title\>（已发生 N 次）」。
- **消息展示只允许走 `error-bus`**（`ipc.ts` 与全局钩子调用它）——
  禁止任何组件自己 `ElMessage.error`。
- **任务类错误的正确姿势**：任务内部逐条记录，任务结束时由**任务报告统一汇总展示**；
  `error-bus` 只负责「立刻需要用户知道的事」。
- 错误日志必含：`event / level / code / numericCode / severity / retryable / params / cause /
  causeChain / context{channel,taskId,projectId,chapterId} / stack`（仅 error|fatal）；
  脱敏 API Key、作品正文、绝对路径、系统用户名；诊断包保留 `causeChain`（排障必需）但参数值过滤。
- 在帮助页写清「**报障三步**」：记下编号（如 `E400012`）→ 点「导出诊断包」→ 一起发给支持。
- `gen-error-docs.ts` 的 5 项自检任一项失败即**中止且不覆盖已有文档**：
  `assertCatalogIntegrity()`、`validatePlaceholders()`、编号唯一性、
  `SYSTEM_ERRNO_MAP` 目标键存在、标题非空且 ≤40 字。
  **宁可报错，也不生成错文档。**

## 12. 工程纪律（每一条都是真机事故换来的，必须遵守）

1. **Vue 模板表达式按 JavaScript 解析，不是 TypeScript**。
   `@update:model-value="(value: number | number[]) => f(value)"` 会让 `vue-tsc` 报 TS1109
   **并放弃整个文件的类型检查**——不是少报几个错，而是整片区域无人看守（曾因此掩盖 137 个真实类型错误）。
   正确做法：把处理逻辑搬进 `<script setup lang="ts">`，模板只写函数名。
   必须提供 `check:template-types` 门禁。
2. **注释里的 `/*` 会毁掉解析**：`check:syntax` 必须扫描这类隐患。
3. **迁移 SQL 必须复制到 outDir**：electron-vite 把整个主进程**内联成单个** `out/main/index.js`，
   所以被内联的 `dirname(import.meta.url)` **就是 outDir 本身**；SQL 写成任何子目录都会 ENOENT，
   表现为「应用能开窗口、但一张业务表都没有」。`check:assets` 必须真跑一次 `writeBundle` 验证。
4. **CSP 必须允许 `blob:`**（`script-src` / `worker-src`）：否则 AudioWorklet 加载被拦，
   录音永远无声，而 Chromium 报 `AbortError`（看起来像用户取消）。
5. **MessagePort 三件事**：主进程必须 `MessagePortMain.start()`；发送侧不能带 transfer 列表；
   渲染进程建的 port 过不了 `contextBridge`。
6. **IPC 载荷里不能带 Vue 响应式 Proxy**：必须 clone 成纯对象再发，否则落库/校验出兜底码「-」。
7. **契约里区分 `null` 与 `undefined`**：界面「清空一个字段」发的是 `null`，
   而 schema 若只收 `undefined` 会拒收——**显式设计可空语义并写进契约**。
8. **设置必须做部分更新语义**：曾发生「改一个设置项把同组其它项清空」「一次保存把整棵设置树写成 null」，
   导致应用再也起不来。设置写入必须是**分支级/字段级**的，且写入前做 schema 校验。
9. **`<script setup>` 声明顺序（防 TDZ）**：`watch{immediate}` / `watchEffect` 在 setup 期间立刻执行，
   若引用了后面才声明的 `const` → 整页 `Cannot access 'x' before initialization`，
   而 `tsc`/`vue-tsc` **抓不到**。必须有 `check:setup-order` 门禁。
10. **测试计数必须确定性**：静默少算用例比测试失败更危险（曾出现「全绿」但每次报的用例数都不一样）。
    用 TAP 结果行的 `type:` 字段分类；出现无法分类的结果行 → 整轮判失败。
    测试文件跑在**独立 Worker 线程**（`--test-isolation=none` 语义），避免沙箱 `spawn EPERM`。
11. **`<script setup>` 里 `watch(..., {immediate})` 与表单初值**：编辑态数据必须显式 clone 后编辑，
    保存时才回写（参考「导入预览不回传 `contentHash` 导致永远提交不了」事故）。
12. **门禁必须先于功能**：每加一类新文件（`.vue`、`.sql`、`.ts` 生成物）就补一条自检，
    否则同类问题会以「看起来像用户取消」的形式反复出现。
13. **引号外的话一个字都不能丢**：画本切分时，引号外的叙述必须各自成行落 `narration`。
    （真机事故：曾经只保留双引号内的内容，叙述全丢。）
14. **不要静默删用户的东西**：清洗必须保留 `raw_text`，并提供「查看被删除的内容」逐条恢复；
    任何删除都要有报告。
15. **宁可漏切，不可错切**（分章）；**不要产出空书**（PDF 无文本层要明确报错而不是给一本空书）。
16. **不做**登录墙、付费墙、验证码绕过；不做 OCR（扫描版 PDF 明确不支持）。
17. **不伪造结果**：不返回一堆 `null` 假装测过；不伪造识别结果；不拿峰值冒充响度。
18. **禁止把业务状态只存在内存或 JSON 文件里**：任务、录音会话必须入库。
19. **已发布的迁移永不修改**（hash 校验，不一致直接 `DB_MIGRATION_FAILED`）；
    **已发布的错误码段内永不插入/删除**（发布即冻结）。
20. **ADR 只追加、不改写**——决策的历史比「当前看起来正确」更重要。
21. **文档与代码同一次提交更新**；文档与代码不一致时，先确认哪边是事实（通常是代码），
    然后**回头修文档**，不要让两者长期分叉（§5.6 的通道分隔符就是这么发现的）。
22. **多音字不做自动替换**：命中多音字表且上下文无消歧线索时才提示，
    **只标记让人判断**（自动替换会错得更离谱）。
23. **`canvas:batchUpdate` 必须给 `lineIds`**：只给 `filter` 等于「按条件更新全库」——
    这是危险默认值。同理，任何批量接口都不接受「无 id 的隐式全量」。
24. **不要逐章调 `canvas:generate`**：多章要用 `canvas:generateBatch`
    （一条任务一份进度，且要求同属一本书）。
25. **真实测试优先于漂亮数字**：测试用例总数必须确定性（TAP `type:` 分类）；
    出现无法分类的结果行 → **整轮判失败**，绝不静默放过。

## 13. 非功能指标（必须达成，且测量方式要写进文档）

### 13.1 性能预算

| 场景 | 目标 | 测量方式 |
|------|------|----------|
| 应用冷启动到可用 | ≤ 3 s | 主窗口可交互时间 |
| 导入 30 MB TXT + 分章 | ≤ 60 s | 后台任务耗时 |
| 打开一章画本（≤500 行） | ≤ 500 ms | 首屏渲染完成 |
| 画本行编辑保存延迟 | ≤ 50 ms（本地防抖后写库） | 主进程写库耗时 |
| **录音监听往返延迟** | ≤ 30 ms（理想 ≤ 15 ms） | 采集→监听输出 |
| 录音写入丢帧率 | 0（不允许丢帧） | 写入样本数 vs 采集样本数 |
| 时间线视图滚动 | ≥ 30 fps（500 片段） | 开发者工具帧率 |
| 向量判定（单章 500 行） | ≤ 20 s（CPU 推理） | 批量任务耗时 |
| 渲染一章 15 min 音频 | ≤ 3 min（含两遍响度） | 导出任务耗时 |
| 数据库规模 | 10 万行画本 + 1 万片段仍可正常操作 | 压测 |
| 内存占用（空闲） | ≤ 400 MB | 任务管理器 |

### 13.2 可靠性

- **录音零丢失**：任何时刻强制结束进程，已采集样本必须可恢复（增量写盘 + 头部修复）。
- **任务可重入**：所有长任务可取消，取消后不留残留半成品（临时文件统一收口 `.tmp/` 并启动时清理）。
- **非破坏性**：原始录音素材永不自动删除；处理结果一律派生新文件。
- **数据完整性**：写入使用事务；`journal_mode=WAL` + `synchronous=NORMAL`；每天自动备份。
- **失败隔离**：单个片段处理失败不得中断整章任务；错误逐条记录并在 UI 汇总。

### 13.3 可用性与可维护性

- 全流程键盘可操作（录书场景必须）。
- 长任务永远有进度、可取消、失败有原因；破坏性操作二次确认；可恢复操作提供回收区。
- 关键路径提供「一键」入口（一键生成画本 / 一键套预设 / 一键导出整本）。
- 领域逻辑与 Electron/Vue 解耦，可单测；IPC 通道全部有类型定义与运行时校验；
  schema 变更走版本化迁移。

### 13.4 兼容性

- Windows 10/11 x64 为一级目标；macOS（Intel/ARM）二级；Linux 尽力。
- 音频后端：WASAPI（Win，可选独占）、CoreAudio（mac）、ALSA/PulseAudio（Linux）。
