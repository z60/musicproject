# 10 · 功能域：书籍导入

> 需求：FR-1（`00-需求规格.md`）
> 代码：`main/features/book/import/` · `renderer/src/features/book/`

## 1. 职责边界

| 做 | 不做 |
|----|------|
| 读取文件/URL/剪贴板 → 纯文本 | 不做排版阅读体验 |
| 编码嗅探与解码 | 不做 OCR（扫描版 PDF 明确不支持） |
| 清洗（广告、水印、零宽字符） | 不做翻译 |
| 分章 + 人工干预（合并/拆分/改名/排序） | 不做画本切分（那是 `11`） |
| 入库 `books` / `chapters` | 不碰音频 |

**出口物**：一个 `book` + N 个 `chapter`（含 `rawText` 与清洗后文本）。

## 2. 支持的导入源

| 源 | 入口 | 解析器 | 优先级 | 说明 |
|----|------|--------|--------|------|
| TXT | 文件选择/拖拽 | `txt.parser.ts` | P0 | 最主要路径，必须做到极致稳 |
| DOCX | 文件选择/拖拽 | `docx.parser.ts`（mammoth） | P0 | 标题样式 → 章节边界 |
| PDF | 文件选择/拖拽 | `pdf.parser.ts`（pdfjs-dist） | P0 | 仅文本层；无文本层 → 明确拒绝 |
| 粘贴文本 | 文本域 | 直通 | P0 | 走同一分章管线 |
| URL | 输入框 | `web.parser.ts`（cheerio + undici） | P1 | 内置站点规则 + 自定义选择器 |
| 剪贴板文件 | 「从剪贴板导入」按钮 | 按扩展名分发 | P1 | 支持从资源管理器复制文件后直接粘贴 |

### 2.1 画本导入（文档本身已经是画本）

有些来源给的**已经是画本**（有声书制作方的成品画本），形如：

   第1章 最离谱的世纪笑话（上）
   　　2000年4月8日，西班牙首都马德里南部。            ← 旁白
   　　【杨浩-嬉小天】“只有我才能帮助马竞保级！”          ← 台词（角色名-CV名）
   序号 | CV | 角色名 | 性别 | 角色描述 | 台词数 | 音色 | 年龄   ← 章末角色表表头
   1 | 嬉小天 | 杨浩 | 男 | 男主…… | 1645 | 青叔音 | 25

导入向导第 1 步勾选「这份文档已经是画本」（IPC 的 importMode: 'canvas'）后：

| 环节 | 行为 |
|------|------|
| 分章 | 用 CANVAS_IMPORT_RULE_SET（**只认「第N章」**）。不能用 cn-standard：它的 ^(序章\|序言\|序\|…) 会把角色表表头「**序号**」切成假章 |
| 解析 | shared/text/canvas-script.ts：【角色-CV】“台词” → 角色行；其余段落 → 旁白；角色表（每格一行 **或** a \| b \| … 单行——mammoth 转表格的形态）→ 角色 |
| 入库 | 直接写 canvas_lines（state=assigned、decidedBy=human，不需要复核）并建角色；章节 canvas_state=generated |
| 不再做 | 说话人判定（规则 / 向量 / LLM）——跑了只会把【】标记当正文 |

- 章标题行**不算台词**：要不要朗读标题由「插入章首标题念白行」单独决定。
- 台词**不要求独占一行**：`旁白：【角色-CV】“台词”`、`【角色-CV】“台词”后面又跟旁白`、`（OS）【角色-CV】“台词”` 都会按【…】拆成「旁白 / 台词 / 旁白」；只把**像说话人标记**的【…】当台词（含 `-` 或后面紧跟引号），所以 `【贝利法案】` 这类正文方括号不会被误判；`（OS）` 作为 note 且标成 inner（内心）。
- 角色按**名字**复用：同名不重复建，也不覆盖用户改过的资料；CV / 音色 / 年龄写进角色备注。
- **角色表不进正文**：表头与数据行会从章节正文里**等长抹除**（换行与字符偏移完全不变，见 `blankCanvasCharacterTables`），所以正文里只剩要录的旁白 / 台词，角色表数据（CV / 角色名 / 台词数…）不会出现在正文；角色表本身只用来建角色。
  ⚠️ mammoth 把 `<tr>` 转文本时**空单元格会被丢掉**，同一张表里各行可能只有 5~8 列。因此按「表头前 6 列 + 首列是数字」识别整张表，**不能要求固定 8 列 / 8 行**——否则表格行会漏进正文被当成旁白（实测样本里漏了 1151 行）。
- 卷首「角色总表」会成为一章「前言」（只有角色、没有台词），可在预览里取消勾选。

## 3. 导入流程（管线）

```
① 探测源类型
   ├─ 文件：读扩展名 + 魔数（magic bytes）双重判定（防改扩展名）
   ├─ URL：抓取 → 判定 Content-Type
   └─ 粘贴：直接进 ③

② 读取为 Buffer（限流）
   · 单文件上限：默认 200 MB（可配置）
   · URL：单页上限 5 MB，总页数上限 50

③ 解码
   · 嗅探编码（§4）
   · 解码为 JS string，统一换行（\r\n|\r → \n）
   · 记录 encoding 到 book 元数据

④ 结构化提取
   · TXT：整段作为待分章文本
   · DOCX：mammoth → HTML/段落数组 → 保留标题层级
   · PDF：逐页 extractText → 合并（插入页分隔标记）
   · URL：选择器提取正文 → 可选跟随「下一章」

⑤ 清洗（§5）
   · 去广告行、水印、重复行、零宽字符、页码行、站点署名
   · 保留原始文本副本（raw_text）便于回溯

⑥ 分章（§6）
   · 按规则集匹配章节标题 → 切分为章
   · 无匹配 → 备选策略（按长度/空行/单章）

⑦ 预览与人工干预（§7）
   · 章列表：改名、合并、拆分、排序、删除、批量勾选导入
   · 每章显示：标题、字数、预估录音时长

⑧ 入库
   · 事务写 books + chapters
   · 计算 SHA-256 去重检查
   · 返回 bookId
```

**任务化**：整个流程是一个 `book.import` 任务，带进度与取消（见 `04` §2.3）。取消时**不写入任何数据**（入库是最后一步且在一个事务内）。

## 4. 编码嗅探（TXT 的主要坑）

> **二进制容器（DOCX / PDF）不做编码嗅探。** 它们内部是 ZIP / PDF 结构，字节层面没有
> 「文本编码」这回事 —— 正文由 mammoth / pdfjs 以 Unicode 提取，落库为 UTF-8。
> 早期实现对它们也跑了一遍嗅探：DOCX 头（PK\x03\x04…）被判成 UTF-16BE、置信度 0.16，
> 于是导入向导第 2 步弹出「无法确定文本编码」，把用户挡在门外。
> 现在 book:detectEncoding 对这两类文件直接返回
> { encoding: 'utf-8', confidence: 1, needsUserChoice: false }，第 2 步只作说明。

### 4.1 判定顺序（从强到弱）

```
1. BOM 检测（最强信号）
   EF BB BF          → UTF-8
   FF FE 00 00       → UTF-32LE
   00 00 FE FF       → UTF-32BE
   FF FE (后随非00)   → UTF-16LE
   FE FF             → UTF-16BE

2. 严格 UTF-8 校验
   直接按 UTF-8 解码，若全程无非法序列且无 U+FFFD → UTF-8

3. chardet 启发式
   取前 512 KB → detect() → 得到候选（GB18030 / Big5 / Shift_JIS / EUC-KR ...）

4. 中文场景的启发式修正（关键）
   · 若候选为 GB2312/GBK → **升级为 GB18030**（GBK 是 GB18030 的子集，用 GB18030 解码更安全，
     且能处理生僻字）
   · 若候选为 Big5 但文本中出现简体常用字高频特征 → 尝试 GB18030 并比较「合理字符比例」

5. 打分选优（当 3/4 不确信时）
   用候选编码分别解码前 N KB，计算「合理字符得分」：
     汉字 + 中文标点 → +2      ASCII 可见字符 → +1
     控制字符（除 \n\t） → -10  U+FFFD → -20
   取最高分的编码。

6. 仍不确信 → 返回 top-3 候选 + 各自预览片段，让用户选（UI 必须提供这个开关）
```

### 4.2 为什么必须升级 GBK → GB18030

真实案例：GBK 编码的小说里出现「锟斤拷」或生僻字时，用 GBK 解码会产出乱码；GB18030 是 GBK 的超集，解码同样的字节不会出错，且对新字覆盖更好。**这是中文小说导入最容易踩的坑。**

### 4.3 编码判定接口

```ts
interface EncodingDetection {
  encoding: string                  // 最终选择
  confidence: number                // 0..1
  candidates: Array<{ encoding: string; score: number; preview: string }>
  bomLength: number
  needsUserChoice: boolean
}
export function detectEncoding(buf: Buffer): EncodingDetection
```

**UI**：默认自动选择；若 `needsUserChoice` 或 `confidence < 0.7`，在导入向导顶部高亮「编码识别不确定，请确认」，并以**多列表格**展示候选编码下的前 200 字预览，用户点选即重新解码（不重新读文件）。

### 4.4 常见异常与处理

| 现象 | 原因 | 处理 |
|------|------|------|
| 文件开头是 `ï»¿` | 被当成 UTF-8 读的 BOM | 识别 BOM 并剥离 |
| 全是 `????` | 编码不兼容被降级替换 | 提示「文件可能已损坏或被错误转码」 |
| 半数正常半数乱码 | 混合编码（拼接文件） | 按块嗅探分段解码（启发式：每 1 MB 独立嗅探，若不同则说明混合，给出警告） |
| 出现大量 `锟斤拷` | 原本就是 UTF-8 被当 GBK 转码后的产物 | 属于源文件损坏，无法恢复 → 明确提示 |

## 5. 清洗规则

### 5.1 必须清洗（默认开启，可关）

| 类型 | 规则 | 示例 |
|------|------|------|
| 站点广告行 | 行内含「请记住本站」「最新章节」「手机版阅读」「加入书签」「天才一秒记住」等关键词 | `天才一秒记住本站地址：www.xxx.com` |
| 页尾导航 | 匹配「上一章 / 下一章 / 返回目录 / 章节报错」组合行 | `上一章 目录 下一章` |
| 网址水印 | 行内 URL 且整行长度 < 60 | `www.example.com` |
| 重复行 | 相邻或有界窗口（±5 行）内完全重复且长度 > 8 | 分页导致的重复段落 |
| 页码行 | 形如 `第 12 页` / `- 12 -` / 纯数字行（长度 < 6 且周围是空行） | `12` |
| 零宽与特殊字符 | 移除 `U+200B~U+200F`、`U+202A~U+202E`、`U+FEFF`（非首位） | — |
| 全角空格 | `U+3000` → 普通空格；连续空格压缩 | — |
| 多余空行 | 连续 ≥3 个 `\n` → 2 个 | — |
| 行首尾空白 | 每行 `trim()`（中文排版惯例） | — |
| 不换行空格 | `&nbsp;` 与 `U+00A0` → 普通空格 | — |

### 5.2 谨慎处理（默认关闭，用户可开）

| 类型 | 风险 |
|------|------|
| 去重「非相邻重复行」 | 可能误删作者有意重复的排比句 |
| 合并被硬换行切断的段落 | 可能误合对话（对话本就该独立成行） |
| 繁简转换 | 改变原文，只应在用户明确需要时启用 |
| 去除所有括号内容 | 会删掉作者注释与音效提示 |

### 5.3 清洗报告（必须可见）

```ts
interface CleanReport {
  removedAdLines: number
  removedDuplicateLines: number
  removedPageNumberLines: number
  removedZeroWidthChars: number
  normalizedNewlines: number
  suspiciousLines: Array<{ lineNo: number; text: string; reason: string }>  // 最多 200 条
  remainingChars: number
}
```
UI 在导入完成页展示摘要，并提供「查看被删除的内容」列表（可逐条恢复 —— **不要静默删用户的东西**）。

## 6. 分章

### 6.1 规则集结构

```ts
interface ChapterRuleSet {
  id: string; name: string
  builtin: boolean
  patterns: Array<{
    id: string
    /** 主匹配：整行必须匹配 */
    linePattern: string          // 正则源串（不含锚点，引擎自动加 ^...$ 并允许前后空白）
    /** 附加条件：行长度上限（防止匹配到正文中的「第三章」） */
    maxLineLength: number        // 默认 40
    /** 是否需要前后有空行（提高精度） */
    requireBlankAround: boolean  // 默认 false
    /** 标题提取组（默认为整个匹配） */
    titleGroup: number           // 默认 0
    /** 章节类型 */
    kind: 'chapter' | 'volume' | 'front' | 'back' | 'extra'
  }>
  /** 纯数字章节号是否允许（如 "1" 单独成行） */
  allowNumericOnly: boolean      // 默认 false
}
```

### 6.2 内置规则（默认开启）

| ID | 模式（示意） | 匹配示例 |
|----|--------------|----------|
| `cn-num` | `第[零一二三四五六七八九十百千万两0-9]+章.*` | 第一章 陨落的天才 / 第12章 |
| `cn-jie` | `第[...]+节.*` | 第三节 |
| `cn-hui` | `第[...]+回.*` | 第五回 |
| `cn-juan` | `第[...]+[卷部篇].*` | 第二卷 |
| `special` | `^(序章|序言|序|楔子|引子|前言|后记|尾声|终章|番外\|大结局).*` | 楔子 / 番外一 |
| `en-chapter` | `(?i)^chapter\s+[\dIVXLC]+.*` | Chapter 12 |
| `cn-numonly` | `^[0-9]{1,4}$` 且前后空行 | `12`（部分站点风格，默认关） |
| `bracket` | `^[【\[](第[...]+章.*)[】\]]$` | 【第一章 开始】 |

### 6.3 匹配算法（宁可漏切、不可错切）

```
对每一行 i：
  for rule in rules（按优先级）:
    if 行长度 > rule.maxLineLength → 跳过（正文里的「第三章」多半是引用）
    if rule.requireBlankAround 且 (前一行非空 或 后一行非空) → 跳过
    m = match(rule.linePattern, trimmedLine)
    if m:
       → 记为候选章节边界
       → 校验：若匹配到 `kind='volume'`，记为卷边界（不切章，但作为层级标记）
       → break
```

**边界校验（降低误切）**
| 校验 | 说明 |
|------|------|
| 长度 | 标题行通常 ≤ 40 字，超出则多半是正文 |
| 位置 | 若两个候选边界之间**字数 < 50** → 后者可能是误切（正文中的引用），合并 |
| 单调性 | 章节号若能解析为数字，应大致递增；出现倒退时给出警告（可能是上下部/倒叙，不强制阻止） |
| 首章 | 第一个边界之前的文本：若 > 200 字 → 作为「前言/序」保留为一章；否则丢弃（多为书名、作者、简介） |
| 末章 | 最后一个边界之后的文本：若 > 200 字 → 作为「尾声」保留；否则并入上一章 |

### 6.4 备选分章策略（无匹配时）

| 策略 | 触发 | 做法 |
|------|------|------|
| 按空行块 | 文本有稳定空行结构 | 连续 2+ 空行处切分；块长 < 100 字则与相邻合并 |
| 按长度均分 | 无明显结构 | 每 N 字（默认 3000）在最近的句末标点处切；标题自动生成「第 N 部分」 |
| 整本一章 | 用户选择 | 适用于短篇 |

**必须让用户在预览页手动切换策略并实时看结果**，不要自动猜完就入库。

### 6.5 自定义正则

- UI 提供正则输入框 + 实时预览（显示匹配到的前 20 个标题与总匹配数）。
- 必须做**正则安全校验**：拒绝灾难性回溯模式（如嵌套量词 `(a+)+`）——用超时保护（`re2` 或简单启发式检测）+ 匹配超时（100 ms 后中断并提示）。
- 用户规则保存为自定义规则集，可导出分享。

### 6.6 分章结果结构

```ts
interface ChapterDraft {
  tempId: string
  index: number              // 章内序号（导入预览期）
  title: string
  rawText: string            // 清洗后文本
  charCount: number
  estimatedDurationMs: number  // charCount / defaultCharsPerSec * 1000（默认 4.2 字/秒）
  kind: 'chapter' | 'front' | 'back' | 'extra' | 'volume'
  volumeIndex: number | null
  startOffset: number        // 在全书文本中的偏移（保留原文定位）
  endOffset: number
  included: boolean          // 是否勾选导入
}
```

### 7.1 向导步骤

```
Step 1  选择来源（文件 / 粘贴 / URL）
Step 2  解析与编码确认（失败时在此等待用户处理）
Step 3  分章规则（自动选中的规则集 + 预览 + 可调）
Step 4  清洗报告（可选调整清洗开关，实时重算预览）
Step 5  章节列表（人工干预：改名/合并/拆分/删除/勾选）
Step 6  确认导入（显示书名、作者、章数、总字数、预估时长；去重提示）
Step 7  完成（进度 → 结果摘要 → 「进入画本」按钮）
```

**关键交互要求**
- 每一步都可**后退**，后退不丢已解析的数据（草稿驻留内存/store）。
- Step 5 的表格必须能**预览章节正文**（右侧抽屉），否则用户无法判断合并是否正确。
- 章标题支持批量前缀/后缀增删（如统一加「斗破苍穹·」）。
- 排序：支持拖拽 + 「按标题中的数字排序」（因为正则切出来的顺序可能是乱的）。
- 章节号规范化：识别「一二三」「123」「零一二」并统一为 `index`（用于导出命名 `{chapterIndex:03}`）。

### 7.2 导入完成后

- 进入章节列表页；每章显示：序号、标题、字数、预估时长、画本状态（未生成/已生成/部分录音/已完成）、录音完成度。
- 提供「批量生成画本」（跳 `11`）、「从第 N 章开始录音」（跳 `12`）。
- 书籍详情页展示：总章数、总字数、总预估时长、已完成录音时长、配音员分工概览（配合 `11`/`07`）。

## 8. 各解析器实现要点

### 8.1 TXT（`txt.parser.ts`）
- 以 Buffer 读取（不用 `readFile(utf8)`——那是编码陷阱的根源）。
- 大文件流式处理：先用前 512 KB 做编码判定，然后**整体解码**（Node 能处理 200 MB 字符串，但要注意内存峰值约 4× 字节数；50 MB 以上建议分块解码后拼接）。
- 保留 `rawText`（清洗前）用于「查看被删内容」。

### 8.2 DOCX（`docx.parser.ts`）
```ts
const { value: html } = await mammoth.convertToHtml({ buffer })
// 或 convertToMarkdown 保留标题层级更清晰
```
- 用 `h1/h2/h3` 与 `Heading 1/2/3` 样式作为**强章节边界**（优先于正则）。
- 保留段落结构（每 `<p>` → 一行）。
- 图片：忽略内容但记录数量，提示「文档含 N 张图片，已忽略」。
- 表格：转为文本（按行用 ` | ` 连接），或跳过并提示。

### 8.3 PDF（`pdf.parser.ts`）
```ts
const doc = await pdfjs.getDocument({ data, useWorkerFetch: false, isEvalSupported: false }).promise
for (let p = 1; p <= doc.numPages; p++) {
  const page = await doc.getPage(p)
  const content = await page.getTextContent()
  // 按 y 坐标聚合为行（PDF 无「段落」概念，必须自己按坐标还原）
}
```
| 坑 | 处理 |
|----|------|
| 无文本层（扫描版） | `textContent.items` 全为空或极少 → 明确报错「该 PDF 无文本层，需要 OCR，本版本不支持」，**不要产出空书** |
| 按坐标还原行 | 用 `transform[5]`（y）分组，容差 2~3 px；同组内按 x 排序后用 `hasEOL` 或间距判断是否加空格 |
| 页眉页脚 | 每页重复出现的短行（跨页比对）→ 自动识别并移除 |
| 双栏排版 | 检测 x 坐标分布呈双峰 → 按栏切分再合并（否则文字会交错） |
| 连字符断词 | 行尾 `-` 且下行首为小写字母 → 合并 |
| 中英文混排空格 | 汉字与 ASCII 相邻时插入空格（可选，默认不做以免破坏文本） |
| 页码行 | 单独成行的数字 → 移除 |

**PDF 必须给出质量提示**：解析后计算「可读性指标」（连续乱码比例、行平均长度、异常空行比例），若质量差则提示「该 PDF 解析质量较低，建议改用 TXT 版本」。

### 8.4 URL（`web.parser.ts`）

```ts
interface SiteRule {
  id: string; name: string
  matchHosts: string[]              // ['www.example.com', '*.example.org']
  contentSelectors: string[]        // ['#content', '.read-content', 'article']
  removeSelectors: string[]         // ['.ad', '#footer', 'script', 'style']
  titleSelector: string             // 'h1.bookname' 或 'meta[property=og:title]'
  nextPageSelectors: string[]       // ['a#next', 'a.next']
  charsetHint?: string              // 站点固定编码
}
```

抓取流程
```
1. SSRF 检查（拒内网/环回/链路本地/非 http(s)）
2. 抓取首页 → 嗅探编码（复用 §4）→ cheerio 加载
3. 提取标题（书名/章节名）
4. 按 contentSelectors 依次尝试，取第一个非空结果；全部失败 → 退化为「全页 body 文本减去 removeSelectors」
5. 移除 removeSelectors
6. 提取正文文本（按 <p> / <br> 转行）
7. 若启用跟随：解析 nextPageSelectors → 得到下一页 URL → 限制同域 → 循环（页数上限 50）
8. 每页都记录 URL 与抓取时间（写入 book 元数据，便于追溯）
```

**礼貌与合规**
- 默认**请求间隔 1.5 s**（可配 0.5~5 s），带随机抖动。
- 使用真实 UA，但设置 `From`/注释说明用途（部分站点会封 UA）。
- 遵守 `robots.txt`（默认检查；用户可强制忽略但需勾选确认）。
- 遇 403/429 → 立即停止，提示「站点拒绝访问，请改用粘贴文本」。
- **不做**登录墙、付费墙、验证码绕过。

### 8.5 粘贴文本（直通）
- 文本域支持粘贴任意长度；超过 1 MB 时提示「文本较大，解析可能需要一会」。
- 走同一分章管线；默认书名「未命名作品」+ 时间戳，用户可改。

## 9. 去重与幂等

```ts
// 导入前
const hash = sha256File(filePath)                 // 或 sha256(cleanedText) 对粘贴/URL
const existing = booksRepo.findByContentHash(hash)
if (existing) {
  // 三个选项，不做静默选择
  → 「打开已有书籍」 / 「作为副本导入」 / 「取消」
}
```
- URL 导入的哈希用「全部页面文本拼接」的结果，避免重复抓同一本书。
- 幂等：同一任务重复提交由 `dedupeKey` 拦截（`book.import:sha256:xxx`）。

## 10. 异常与错误码

| 场景 | 错误码 | 用户可见提示 |
|------|--------|--------------|
| 文件不存在/无权限 | `FILE_NOT_FOUND` / `FILE_PERMISSION` | 「无法读取文件：<原因>」+ 重新选择 |
| 文件过大 | `FILE_TOO_LARGE` | 「文件为 X MB，超过上限 Y MB，可在设置中调整」 |
| 编码无法确定 | `ENCODING_UNCERTAIN` | 进入编码选择步骤（非错误） |
| PDF 无文本层 | `PDF_NO_TEXT_LAYER` | 「该 PDF 是扫描件，需要 OCR，本版本不支持」 |
| PDF 加密 | `PDF_ENCRYPTED` | 「PDF 已加密，请先解密」 |
| DOCX 损坏 | `DOCX_CORRUPT` | 「文档结构异常，已尽力提取 X 段」 |
| 分章零结果 | `NO_CHAPTER_MATCHED` | 「未识别到章节标记，请选择分章方式」（进入策略选择） |
| 分章结果异常（1 章却 100 万字） | `CHAPTER_SPLIT_SUSPICIOUS` | 警告 + 建议检查规则 |
| URL 抓取失败 | `FETCH_FAILED` | 「抓取失败：<状态码/原因>」+ 建议粘贴 |
| URL 被拒（403/429） | `FETCH_BLOCKED` | 「站点拒绝访问，请改用粘贴文本」 |
| SSRF 拦截 | `FETCH_FORBIDDEN_TARGET` | 「该地址不被允许访问」 |
| 磁盘空间不足 | `DISK_FULL` | 「磁盘空间不足，需至少 X MB」 |
| 重复导入 | `DUPLICATE_BOOK` | 见 §9 的三选一 |
