## 1. 产品定义

### 1.1 一句话

把一本小说，变成一份**可下发给多人分角色录制的画本**，再把录回来的音频**自动对轨、处理、混音**成**可分发的有声成品**。

### 1.2 它不是什么

- 不是在线阅读器（不负责排版阅读体验）
- 不是完整 DAW（不做 MIDI、不做多轨实时效果器链的宿主级编辑）
- 不是 TTS 生成工具（1.0 不生成人声，只录真人；TTS 见 3.0）
- 不是云端协作平台（1.0~2.0 靠文件包交换，不做实时协同编辑）

### 1.3 核心价值链

```
文本导入 ──▶ 画本（谁说的 / 什么情绪 / 停多久） ──▶ 录音（单人 or 多人分工）
                                                      │
成品分发 ◀── 混音导出（-16 LUFS / M4B） ◀── 处理（降噪 EQ 压缩） ◀── 对轨（时间线排布）
```

**这条链上任一环节断裂都会导致返工**，所以设计上有一条铁律：

> **画本行（`canvas_line`）是全系统唯一主轴，其余一切数据都必须能追溯到某一行画本。**

## 2. 角色与场景

| 角色 | 描述 | 关键诉求 | 主要用到的功能域 |
|------|------|----------|------------------|
| **制作人 / 主播（P）** | 一个人搞定全部，通常是 UP 主、有声书爱好者 | 快、少手活、不要对不上号 | 导入、画本（AI 辅助）、录音、混音 |
| **配音导演（D）** | 负责分配角色、下发任务、验收音频 | 分工清楚、回收不混乱、能查错 | 画本、任务包（`.nst`）、对轨、质检 |
| **配音员（V）** | 只录自己角色的人，可能不在同一台机器 | 打开就有得录、只看自己的词、录错能重录 | 录音（角色模式）、任务包 |
| **后期（E）** | 只做处理与混音 | 参数可存可复用、批量、可校验 | 处理、混音、导出 |
| **技术用户（T）** | 配置模型、API、路径 | 能改配置、能看日志、能降级 | 设置、AI Provider、日志 |

### 2.1 主场景（User Journey）

**J1 · 单人全流程（P）**
1. 导入 `斗破苍穹.txt`（GBK 编码，120 万字）
2. 系统自动分章，得到 1643 章；选择第 1 章进入画本
3. 一键「AI 生成画本」：切分旁白/对白 + 向量判定说话人 + 标情绪
4. 人工扫一遍，改掉 12 处判错的说话人
5. 进录音页，选「逐行录制」，戴耳机，一行一停，录完 87 行
6. 进对轨页，自动排好时间线，手动调了 3 处重叠
7. 进混音页，套用预设「男声旁白 + 轻 BGM」，导出第 1 章 MP3
8. 全部章节完成后，一键导出整本 M4B

**J2 · 多人分工（D）**
1. D 完成画本，建角色表：萧炎 / 药老 / 纳兰嫣然 / 旁白
2. 绑定配音员：旁白→A，萧炎→B，药老→C，纳兰嫣然→B（一人多角色）
3. 导出 `.nst` 任务包（只含 B 的萧炎 + 纳兰嫣然台词清单 + 提示）
4. B 在自己电脑导入 `.nst`，用「角色模式」连续录制，导出录毕包回传
5. D 回收 3 个包，系统按 `line_id` 自动归位，冲突/缺漏在质检报告里列出

**J3 · 返工（V）**
1. 质检报告提示：第 34 行削波（clipping），第 51 行漏录，第 77 行有明显口水音
2. V 打开任务包，只重录这 3 行，导出增量包回传

## 3. 功能需求

> 编号规则：`FR-<域>-<序号>`。每个域末尾给出**验收标准（AC）**，即「什么算做完」。
> 优先级：`P0` = 1.0 必须；`P1` = 1.0 尽力，2.0 兜底；`P2` = 3.0。

| FR-1.3 | 无章节标记的文本支持按长度/空行均匀切分，或整体作为单章 | P0 |
| FR-1.4 | 支持 DOCX 导入，保留段落结构，识别标题样式为章节边界 | P0 |
| FR-1.5 | 支持 PDF 导入，提取文字并保留页序；对扫描版（无文本层）给出明确提示「需 OCR，本期不支持」 | P0 |
| FR-1.6 | 支持粘贴文本导入（多行文本域 → 走同一分章管线） | P0 |
| FR-1.7 | 支持 URL 抓取：内置常见小说站规则（正文容器选择器），支持自定义 CSS 选择器；支持多页「下一章」跟随抓取（可设上限） | P1 |
| FR-1.8 | 导入清洗：去除站点广告水印行（如「本章未完，请点击下一页继续阅读」）、重复行、多余空行、零宽字符、`\r` 归一 | P0 |
| FR-1.9 | 导入结果预览与人工干预：章列表可改名、合并、拆分、排序、删除、勾选部分导入 | P0 |
| FR-1.10 | 大文件（≥50 MB / ≥500 万字）导入不阻塞 UI，带进度与可取消 | P0 |
| FR-1.11 | 导入历史与去重：同一文件的 SHA-256 重复时提示「已存在」，允许另存为副本 | P1 |
| FR-1.12 | 导入后自动进入画本前处理：按章统计字数、行数、预估录音时长 | P1 |

**AC-1**：一份 30 MB 的 GBK TXT，在 60 秒内完成导入与分章；分章结果对「第X章」与「序章/番外」全部正确切出；章节总数与预期一致；导入过程可随时取消且不留下半个章节。

### FR-2 画本（域 `editor` + `book/canvas`）

> 「画本」= 把小说文本翻译成「表演脚本」。这是全系统最核心、也最容易做错的一步。

#### FR-2.1 切分与判定

| 编号 | 需求 | 优先级 |
|------|------|--------|
| FR-2.1.1 | 按段落/句读切分章节文本为**画本行**，保留原文偏移量（`char_start`/`char_end`）以实现双向定位 | P0 |
| FR-2.1.2 | 说话人**初筛**：基于引号族（`“”`、`「」`、`‘’`、`""`）、对话引导语（`说道/问道/喊道/答道/冷笑/喃喃`等）、破折号等进行「对白 / 旁白」粗分类 | P0 |
| FR-2.1.3 | 说话人**判定**：对每一行取 embedding，与该章节出场角色的**原型向量（centroid）**做余弦相似度，取最高分且超过阈值者为归属；低于阈值判为 `narration` 或 `unknown` | P0 |
| FR-2.1.4 | 说话人判定的**上下文增强**：把「前后各 1~2 行 + 本节场景已有角色」作为上下文拼入判定文本，解决「他点了点头。」这类无主语短句 | P0 |
| FR-2.1.5 | 判定结果必须带**置信度**与**候选列表**（Top-3 角色 + 分数），UI 用颜色区分高/中/低置信，低置信进入「待确认队列」 | P0 |
| FR-2.1.6 | 判定可**复算**：换模型/换阈值后能一键重算全部低置信行，且不覆盖人工已确认的结果 | P0 |
| FR-2.1.7 | 支持 AI（LLM）辅助判定：可选把「待确认行 + 角色表」提交给 Provider 做二次裁决（本地 provider 或未来的 Dify） | P1 |
| FR-2.1.8 | 支持「一键确认全部高置信」与「按存疑筛选」的批处理 | P0 |

#### FR-2.2 角色表与音色

| 编号 | 需求 | 优先级 |
|------|------|--------|
| FR-2.2.1 | 角色表：增/删/改/排序，含角色名、别名列表（同一角色不同称呼：`萧炎`/`炎帝`/`小炎子`）、性别、年龄段、性格描述、备注 | P0 |
| FR-2.2.2 | 从文本自动抽取候选角色名：高频人名识别（对话引导语前的主语、称谓词频、姓氏+称谓）并给出建议列表 | P1 |
| FR-2.2.3 | 合并/拆分角色；合并时自动迁移台词与别名；支持「批量改归属为某角色」 | P0 |
| FR-2.2.4 | 角色 ↔ 配音员绑定：一个角色绑定一个主配音员，可配置备选；一个配音员可担任多角色 | P0 |
| FR-2.2.5 | 音色档案（`voice_profile`）：每个配音员可上传/录制参考样本，记录性别、音域、语速倾向、样本路径 | P1 |
| FR-2.2.6 | 角色级默认表演参数：默认语速、默认情绪基调、默认音量偏移，画本行未指定时继承 | P0 |

#### FR-2.3 表演标记（tag）

| 编号 | 需求 | 优先级 |
|------|------|--------|
| FR-2.3.1 | 情绪标记：预设情绪集（平静/喜悦/愤怒/悲伤/惊讶/恐惧/厌恶/嘲讽/激动/低沉…），可单选，支持自定义扩展 | P0 |
| FR-2.3.2 | 强度标记：情绪强度 1~5（弱→强），用于指导表演与后续可能的动态处理 | P1 |
| FR-2.3.3 | 语速标记：`slow` / `normal` / `fast`，或 -50%~+50% 相对偏移 | P0 |
| FR-2.3.4 | 音量标记：相对 ±12 dB | P1 |
| FR-2.3.5 | 停顿标记：句内停顿（`/`）与句末留白时长（秒），直接影响对轨的时间线 | P0 |
| FR-2.3.6 | 重音/强调标记：对画本行内某个词/片段标记强调 | P2 |
| FR-2.3.7 | 发音提示（`pronunciation`）：为多音字、生僻字、英文缩写提供读音提示（如 `行(háng)`、`NVIDIA`） | P0 |
| FR-2.3.8 | 自由备注字段，供配音员看 | P0 |
| FR-2.3.9 | AI 自动标注：批量推测情绪与语速建议，标为「AI 建议」并可一键采纳/忽略 | P1 |

#### FR-2.4 编辑器

| 编号 | 需求 | 优先级 |
|------|------|--------|
| FR-2.4.1 | **双视图**：表格视图（一行一记录，列=序/说话人/文本/情绪/停顿/状态，适合批量改）与剧本视图（连续阅读感，旁白与台词不同样式，适合精修） | P0 |
| FR-2.4.2 | 行内编辑：改文本、改说话人（下拉 + 快捷键）、改标记，全部即时保存（防抖 500 ms） | P0 |
| FR-2.4.3 | 键盘优先：`↑/↓` 移动，`Enter` 下一行，`Ctrl+1..9` 快速指派说话人，`空格` 试听该行（若有录音） | P0 |
| FR-2.4.4 | 查找替换：按文本/按说话人/按情绪筛选，正则替换（限定当前章或全书） | P0 |
| FR-2.4.5 | 批量操作：按筛选批量改说话人、批量加/清标记、批量改停顿、批量合并相邻旁白行 | P0 |
| FR-2.4.6 | 撤销/重做：至少 100 步，覆盖文本与标记的所有变更 | P0 |
| FR-2.4.7 | 章节级快照与版本对比：每次 AI 生成前自动打快照，可回滚、可 diff | P1 |
| FR-2.4.8 | 画本质检：空行、超长行（>200 字）、未被任何角色使用的角色、引号不配对、纯旁白连续超过 N 行、说话人为 `unknown` 的行数 | P0 |
| FR-2.4.9 | 文本与原文对照：点击画本行可高亮右侧原文对应位置 | P1 |

**AC-2**：对一章 3000 字、含 60 句对白、8 个角色的文本，AI 生成画本后，说话人判定准确率 ≥ 85%（以人工校对为基准），所有低置信行可在 3 分钟内通过 UI 清理完；角色合并后无孤立引用；停顿标记能正确传导到对轨时间线。

| 编号 | 需求 | 优先级 |
|------|------|--------|
| FR-3.1 | 设备管理：枚举输入设备、选择采样率（44.1/48 kHz）、位深（16/24/32f，落盘以 WAV float32 或 24-bit 为准）、声道（单声道为默认）；设备诊断页显示实时电平、底噪、延迟估计 | P0 |

| FR-3.9 | Punch-in 补录：在已有片段的任意位置插入重录，拼接处带 5~30 ms 交叉淡化，避免爆音 | P1 |
| FR-3.10 | 输入处理：增益滑块（数字增益，写盘前）、自动增益（AGC，默认关）、削波指示（连续 3 个样本 ≥ 0.99 判定削波）、防喷麦提示 | P0 |
| FR-3.11 | 录音期间崩溃/断电**不丢素材**：采用增量写盘 + 启动时 WAV 头修复（见 `05-音频管线.md`） | P0 |
| FR-3.12 | 快捷键与外部控制：开始/停止/重录/上一行/下一行/播放；支持脚踏板映射为「停止并下一行」 | P0 |
| FR-3.13 | 录音会话留存原始素材（`recording_session` 的 WAV 不因片段生成而删除），可随时回溯重切 | P0 |
| FR-3.14 | 波形与电平：录音中实时波形 + 峰值/有效值电平表，录完显示该段波形缩略 | P1 |
| FR-3.15 | 元数据：每个 take 记录设备、采样率、增益、时间戳、时长、峰值 dBFS、LUFS 初测 | P0 |

**AC-3**：戴耳机环境下，连续录制 30 分钟后强制结束进程，重启应用能恢复出完整可播放的 WAV（头部已修复）；逐行录制模式下从选中行开始录 20 行，全程无需鼠标；同一行 3 个 take 可 A/B 对比并选定成品。

### FR-4 对轨（域 `alignment`）

> 定义澄清：本项目「对轨」= **录制对齐 + 多轨对齐 + 人工微调**三件事的合集。

| 编号 | 需求 | 优先级 |
|------|------|--------|
| FR-4.1 | **录制对齐**：每个 `voice_segment` 必须绑定到唯一的 `canvas_line`；提供对轨页把「未绑定片段」拖到画本行上，或把「未录行」匹配到片段 | P0 |
| FR-4.2 | 自动匹配：连续录制产生的片段序列，按「画本行顺序 + 时长合理性 + 可选 ASR 文本相似度」自动匹配到画本行，给出匹配置信度 | P0 |
| FR-4.3 | **多轨对齐**：为章节生成时间线，轨道 = 说话人（旁白轨 + 各角色轨），同一角色的片段按画本行顺序串行排布；轨道间按场景允许重叠 | P0 |
| FR-4.4 | 留白计算：行间停顿 = 画本行 `pause_after_ms`（若为 0 则用章节默认值）；句内停顿按标记插入静音 | P0 |
| FR-4.5 | **重叠消解**：检测同轨/跨轨重叠，提供策略：`串行化`（后一段后移）、`保留交叠`（对话交叠，更自然）、`压缩留白`（优先压缩空白而非移动音频）；冲突列表可逐条处理 | P0 |
| FR-4.6 | 时间线视图：多轨波形 + 画本行块的对照，横向缩放（到样本级/到整章级），纵向缩放轨道高度 | P0 |
| FR-4.7 | 手动微调：拖动片段调整起始时间、拖动块边缘裁剪、吸附到网格（0.1 s / 0.5 s / 画本行边界）；微调结果持久化 | P0 |
| FR-4.8 | 偏移量（`offset_ms`）与源区间（`src_in_ms` / `src_out_ms`）分离存储，非破坏性编辑，随时可还原 | P0 |
| FR-4.9 | 静音填充与修剪：段首/段尾静音自动修剪（阈值可设），同时保留 50~150 ms 呼吸留白 | P0 |
| FR-4.10 | 试听：从任意点播放混音预览（轻量实时混音），或只播放某轨（solo） | P0 |
| FR-4.11 | 校验：缺行（画本行无片段）、孤儿片段（片段无画本行）、时长异常（<0.2 s 或 >60 s）、同轨重叠、跨轨不合理重叠 | P0 |

## 4. 非功能需求

### 4.1 性能预算

| 场景 | 目标 | 测量方式 |
|------|------|----------|
| 应用冷启动到可用 | ≤ 3 s | 主窗口可交互时间 |
| 导入 30 MB TXT + 分章 | ≤ 60 s | 后台任务耗时 |
| 打开一章画本（≤500 行） | ≤ 500 ms | 首屏渲染完成 |
| 画本行编辑保存延迟 | ≤ 50 ms（本地防抖后写库） | 主进程写库耗时 |
| **录音监听往返延迟** | ≤ 30 ms（理想 ≤ 15 ms） | 采集→监听输出 |
| 录音写入丢帧率 | 0（不允许丢帧） | 写入样本数 vs 采集样本数 |
| 时间线视图滚动 | ≥ 30 fps（500 片段） | 开发者工具帧率 |
| 向量判定（单章 500 行） | ≤ 20 s（CPU 推理） | 批量任务耗时 |
| 渲染一章 15 min 音频 | ≤ 3 min（含两遍响度） | 导出任务耗时 |
| 数据库规模 | 10 万行画本 + 1 万片段仍可正常操作 | 压测 |
| 内存占用（空闲） | ≤ 400 MB | 任务管理器 |

### 4.2 可靠性

- **录音零丢失**：任何时刻强制结束进程，已采集样本必须可恢复（增量写盘 + 头部修复）。
- **任务可重入**：所有长任务可取消，取消后不留下残留半成品（临时文件统一收口到 `.tmp/` 并启动时清理）。
- **非破坏性**：原始录音素材永不自动删除；处理结果一律派生新文件。
- **数据完整性**：写入使用事务；`PRAGMA journal_mode=WAL` + `synchronous=NORMAL`；每天自动备份。
- **失败隔离**：单个片段处理失败不得中断整章任务；错误逐条记录并在 UI 汇总。

### 4.3 安全与隐私

- 渲染进程 `nodeIntegration: false`、`contextIsolation: true`、`sandbox: true`；全部能力经 preload 白名单暴露。
- 禁止 `remote` 模块；禁止渲染进程直接读文件系统。
- API Key 存储：使用 Electron `safeStorage`（系统密钥链）加密后落库，绝不写入日志。
- 作品文本视为用户私密数据：默认不外发；接入云端 AI 前必须显式确认，并在发送前提示「将发送 N 字到 <Provider>」。
- 外链一律走系统浏览器（`shell.openExternal`），禁止应用内 `webview` 加载任意页面。
- URL 抓取做 SSRF 基本防护：拒绝 `file://`、内网地址（127.0.0.0/8、10/8、192.168/16、169.254/16）。

### 4.4 可用性

- 全流程键盘可操作（录书场景必须）。
- 长任务永远有进度、可取消、失败有原因。
- 破坏性操作二次确认；可恢复的操作（删 take）提供回收区。
- 关键路径提供「一键」入口（一键生成画本 / 一键套用预设 / 一键导出整本）。

### 4.5 可维护性

- TypeScript `strict: true`；共享类型单一来源（`src/shared/types.ts`）。
- 领域逻辑与 Electron/Vue 解耦，可单测。
- IPC 通道全部有类型定义与运行时校验（见 `20-IPC契约.md`）。
- 数据库 schema 变更走版本化迁移脚本。

### 4.6 兼容性

- Windows 10/11 x64 为一级目标；macOS（Intel/ARM）为二级；Linux 尽力。
- 音频：WASAPI（Win，可选独占）、CoreAudio（mac）、ALSA/PulseAudio（Linux）。
- 采样率不匹配时在采集侧重采样到工程统一采样率，避免后续对轨出现漂移。

## 6. 依赖与假设

**假设**
1. 用户机器有可用的录音设备与耳机（监听返送场景）。
2. 用户理解「画本是给人看的表演脚本」，愿意做人工校对。
3. 目标作品以中文小说为主（分章正则、情绪词表、embedding 模型均以中文优化）。
4. 单人配音员可能不具备技术能力，需要零配置的使用体验（任务包导入即用）。

**外部依赖**
| 依赖 | 用途 | 缺失时的影响 |
|------|------|--------------|
| ffmpeg 二进制 | 全部音频转码/滤镜/混音 | 无法导出与处理（核心阻断） |
| whisper.cpp 模型 | ASR、后续强制对齐 | 不影响 1.0 主链 |
| embedding 模型（ONNX） | 说话人向量判定 | 降级为「规则 + 人工」 |
| LLM Provider | AI 画本增强、情绪标注 | 降级为纯本地规则 |
