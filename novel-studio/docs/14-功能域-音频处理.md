> 需求：FR-5（`00-需求规格.md`）
> 代码：`main/features/audio/processor.ts` · `presets.ts` · `renderer/src/features/mixing/`（处理链 UI 部分）
> 滤镜细节：`05-音频管线.md` §6

---

## 1. 定位

> **音频处理 = 对「单个片段」或「一批片段」施加既定的信号处理链，产出派生文件。**

它**不是**混音（多轨合成）、**不是**录音。它是「把素材变好听」这一步，且必须**非破坏、可回退、可批量、可复用参数**。

| 做 | 不做 |
|----|------|
| 降噪、去齿音、EQ、压缩、限幅 | 不做多轨混音（`15`） |
| 预设的保存/导入/导出/按角色套用 | 不做实时效果器（不做 DAW 级实时链） |
| 批量处理与失败隔离 | 不修改原始文件 |
| 修补（爆音、静音、DC、极性） | 不做变调/时间拉伸（仅 ±10% 不变调变速救急） |

## 2. 处理链模型

```ts
interface ProcessChain {
  highpass: { enabled: boolean; freq: number; poles: 1 | 2 }
  denoise: {
    enabled: boolean
    nr: number          // 降噪量 dB，范围 0.01~97，建议 6~18
    nf: number          // 噪声底 dBFS，建议 -80~-20，默认 -30
    tn: boolean         // 是否启用噪声跟踪（track_noise）
    profile: number[] | null   // 可选：采样噪声得到的每频段电平
  }
  deesser: { enabled: boolean; intensity: number; freq: number }   // i:0~1, f:0~1
  eq: Array<{
    id: string
    type: 'lowshelf' | 'highshelf' | 'peak' | 'lowpass' | 'highpass'
    freq: number
    gainDb: number
    q: number
    enabled: boolean
  }>
  compressor: {
    enabled: boolean
    thresholdDb: number; ratio: number
    attackMs: number; releaseMs: number
    makeupDb: number
    knee: number | null      // 若 ffmpeg 构建支持
  }
  limiter: { enabled: boolean; limitDb: number; attackMs: number; releaseMs: number }
  /** 附加：修补类操作（在链的两端执行，不在 ffmpeg 图中间） */
  repair: {
    dcOffset: boolean        // 去 DC：highpass=f=10 或 dynaudnorm 前处理
    polarityInvert: boolean  // 极性反转
    declick: Array<{ atMs: number; lengthMs: number }>   // 局部淡入淡出修爆音
    silenceFill: Array<{ startMs: number; endMs: number }>
    tempo: { enabled: boolean; factor: number }          // 0.9~1.1
  }
}
```

### 2.1 执行顺序（固定，不可调换）

```
① 修补前置：去 DC / 极性反转
② 高通（去低频隆隆声、桌面震动）
③ 降噪（先去掉噪声，后续 EQ/压缩才不会把噪声抬起来）
④ 去齿音（在压缩之前，避免压缩把齿音突出）
⑤ EQ（塑造音色）
⑥ 压缩（控制动态）
⑦ 限幅（防峰值超标）
⑧ 修补后置：declick、静音填充、变速
```

**为什么降噪必须在 EQ/压缩之前**：压缩会提升小信号（含噪声），如果在压缩后降噪，噪声已经被抬起，降噪难度更大且更容易吃字。

**为什么去齿音在压缩之前**：`s`/`sh` 音的瞬态会被压缩器「压住又放开」，若先去齿音能避免压缩器被齿音误触发。

## 3. 滤镜图构建（`infra/ffmpeg/filter-graph.ts`）

```ts
export function buildChainFilter(chain: ProcessChain): string {
  const f: string[] = []
  if (chain.repair.dcOffset) f.push('highpass=f=10:poles=1')
  if (chain.repair.polarityInvert) f.push('aeval=val(0)*-1:c=same')   // 极性反转

  if (chain.highpass.enabled) f.push(`highpass=f=${chain.highpass.freq}:poles=${chain.highpass.poles}`)

  if (chain.denoise.enabled) {
    const parts = [`nr=${chain.denoise.nr}`, `nf=${chain.denoise.nf}`]
    if (chain.denoise.tn) parts.push('tn=1')
    f.push(`afftdn=${parts.join(':')}`)
  }

  if (chain.deesser.enabled) f.push(`deesser=i=${chain.deesser.intensity}:f=${chain.deesser.freq}`)

  for (const band of chain.eq.filter(b => b.enabled)) {
    const t = band.type === 'peak' ? 'q' : 'q'
    f.push(`equalizer=f=${band.freq}:t=${t}:w=${band.q}:g=${band.gainDb}`)
  }

  if (chain.compressor.enabled) {
    const c = chain.compressor
    f.push(`acompressor=threshold=${c.thresholdDb}dB:ratio=${c.ratio}` +
           `:attack=${c.attackMs}:release=${c.releaseMs}` +
           (c.makeupDb ? `:makeup=${dbToLinear(c.makeupDb)}` : ''))
  }

  if (chain.limiter.enabled) {
    f.push(`alimiter=limit=${dbToLinear(chain.limiter.limitDb)}` +
           `:attack=${chain.limiter.attackMs}:release=${chain.limiter.releaseMs}`)
  }

  if (chain.repair.tempo.enabled) f.push(`atempo=${chain.repair.tempo.factor}`)

  return f.join(',')
}
```

### 3.1 必须实测确认的三处（写文档时已标记，实现时必须验证）

| 项 | 不确定点 | 处理 |
|----|----------|------|
| `acompressor` 的 `makeup` | 不同 ffmpeg 版本可能是线性倍数或 dB | 启动时跑一个 3 秒测试信号（1 kHz 正弦）实测；或**干脆不用 `makeup`**，改在链尾加 `volume=XdB`（更可控） |
| `alimiter` 的 `limit` | 是线性值（0~1），不是 dB | `dbToLinear(-1) ≈ 0.891`；必须确认单位 |
| `afftdn` 的 `nf`/`nr` 范围 | 版本差异较大（有的版本 `nr` 是 dB，有的带 `nt` 参数） | 启动探测：解析 `ffmpeg -h filter=afftdn` 的输出，验证参数存在再启用；不支持则隐藏该控件并提示 |

> **实现策略**：启动时生成一份 `ffmpeg-capabilities.json`（记录每个滤镜的参数支持情况），UI 按能力渲染控件。这比「写死参数然后在用户机器上崩」要好得多。

### 3.2 内部工作格式（统一，避免片段间不一致）

```
输入 → aresample=48000 → aformat=sample_fmts=s32:channel_layouts=mono
     → 处理链 → 输出 WAV pcm_s24le 48000 mono
```
若源是立体声且用户希望保留 → 输出立体声，但**同一批处理必须格式一致**（否则后续 `amix` 会失败）。

### 4.3 预设参数 UI

每个参数必须有：
1. **滑块 + 数字输入**（精确输入很重要，不能只有滑块）
2. **单位与范围提示**（如「降噪量 0~97 dB，建议 6~18」）
3. **默认值重置**（双击滑块恢复默认）
4. **EQ 响应曲线可视化**（实时绘制频率响应，这是最有用的反馈）
5. **A/B 试听按钮**（选中片段 → 原始 vs 处理后，同一位置切换）

## 5. 噪声轮廓采样（提高降噪效果的关键功能）

`afftdn` 的 `nf` 参数需要接近真实噪声底，用户很难猜。提供工具：

```
1. 用户在对轨/录音页选中一段「纯噪声」（没人说话的静音段）
2. 系统用 astats 分析该段 → 得到 RMS 与各频段电平
3. 把 RMS 填入 `nf`（自动），把频段轮廓存为 `profile`
4. UI 显示「已采样噪声轮廓：RNN 底噪 -52.3 dBFS」
```

实现：
```bash
ffmpeg -i sample.wav -af astats=metadata=1:reset=0 -f null - 2>&1
# 解析 Overall.RMS_level 等字段
```
或更直接：在 PCM 域算 RMS（`infra/media/analysis.ts`），无需 ffmpeg。**推荐后者**（快且无依赖）。

## 6. 修补工具（FR-5.7）

| 工具 | 实现 | 交互 |
|------|------|------|
| 去 DC 偏移 | 前置 `highpass=f=10:poles=1` 或减去均值 | 开关 |
| 极性反转 | `aeval` 或 PCM 域取反 | 开关（用于多麦相位问题） |
| 爆音修复（declick） | 在指定区间做 5~20 ms 淡入淡出 | 波形上框选区间 → 点「修复」 |
| 静音填充 | 指定区间置零（带 5 ms 边缘淡化） | 同上 |
| 局部删除 | 删除区间并把后续音频左移（会改变时长 → 对轨会重算） | 同上，且**必须提示时长变化** |
| 静音修剪 | 自动扫描首尾（`05` §5.3） | 一键 |
| 轻微变速 | `atempo` 0.9~1.1（超出此范围会明显失真，UI 上限制） | 滑块 |

> **「局部删除」是危险操作**：它改变片段时长，进而影响对轨。必须二次确认，并提示「对轨位置将重新计算」。

## 7. 批量处理与失败隔离（FR-5.11）

### 7.1 任务流程

```
process.batch 任务
├─ 1. 解析目标集合（按范围：片段/角色/章/书）
├─ 2. 计算去重键 dedupeKey = `process:{segmentId}:{presetHash}`
│     └─ 已存在且 preset_hash 未变 → skip（幂等，重复点不会重跑）
├─ 3. 并发执行（受 ffmpeg 并发限制，见 04 §6）
│     ├─ 成功 → 更新 voice_segments.processed_path + preset_hash
│     └─ 失败 → 记录错误，**继续下一个**（不中断）
├─ 4. 汇总报告：成功 N / 跳过 K / 失败 M（含每条失败原因）
└─ 5. 清理临时目录（含取消时）
```

### 7.2 取消语义

- 取消 → 停止派发新任务 + 等待正在跑的 ffmpeg 收到 kill（`SIGTERM`，2 秒后 `SIGKILL`）。
- **已完成的片段保留**（不回滚，因为它们是有效产物）。
- 清理 `.tmp` 与缓存中间文件。
- 报告：「已取消，完成 X/Y，已完成的处理结果保留」。

### 7.3 报告 UI

```
┌──────────────────────────────────────────────────────────┐
│ 批量处理完成                                              │
│ 目标 124 | 成功 118 | 跳过 4（参数未变） | 失败 2          │
├──────────────────────────────────────────────────────────┤
│ ✗ line 42 (萧炎)  ffmpeg 退出码 1：Invalid argument       │
│   详情：alimiter 参数不被当前 ffmpeg 版本支持              │
│   [查看命令] [重试] [改用其他预设]                         │
│ ✗ line 77 (药老)  文件读取失败：segments/xxx.wav 不存在     │
│   [重新定位文件] [重新录制]                                │
└──────────────────────────────────────────────────────────┘
```

**「查看命令」必须提供**：把完整 ffmpeg 命令行显示出来（可复制），这样用户/开发者能在终端里复现问题。这是排障效率的关键。

## 9. 自动闪避 / Ducking（FR-5.14）

配置在混音侧（`15` 消费），但参数与实现属本域：

```ts
interface DuckingConfig {
  enabled: boolean
  amountDb: number        // 下潜量，默认 -12
  thresholdDb: number     // 触发阈值，默认 -30（人声电平）
  attackMs: number        // 默认 20
  releaseMs: number       // 默认 400
  /** 'sidechain' = ffmpeg sidechaincompress；'envelope' = 按画本行时间精确计算（3.0） */
  mode: 'sidechain' | 'envelope'
}
```

**实现**（`05` §7.5）：
```bash
[music][voice]sidechaincompress=threshold=0.02:ratio=8:attack=20:release=400:makeup=1:level_sc=1[ducked]
```

**侧链源的选择**：用**人声总线**作为侧链源（而不是「旁白轨」），因为角色台词同样应该压低 BGM。

**常见错误**（写进文档以避免返工）
1. Solo 某轨时侧链源被静音 → BGM 不下潜（必须让侧链源始终有效）
2. `threshold` 用了 dB 而实际要线性值（`ffmpeg` 的 `sidechaincompress.threshold` 是线性 0~1）
3. `release` 太短 → BGM 在人声停顿处「抽气」，比不 duck 还难听

## 13. 异常与边界

| 场景 | 处理 |
|------|------|
| ffmpeg 不支持某滤镜 | 启动探测 → 隐藏对应控件 + 提示；或使用降级滤镜 |
| 参数越界 | UI 层限制范围；主进程再校验一次（防 IPC 直调） |
| 源文件缺失 | 跳过并报告；提供「重新定位文件」 |
| 输出目录空间不足 | 提前检查（预估输出大小 = 输入 × 1.2）；不足则拒绝并提示 |
| 处理耗时极长的单片段（> 10 min） | 提示可能时长异常；允许中断 |
| 连续两次相同请求 | `dedupeKey` 拦截，第二次直接返回第一次的结果引用 |
| 处理链全关 | 仍会生成一个「仅格式统一」的派生文件（或直接跳过处理，标记 `processed_path = null`） |
| 变速导致对轨位置失效 | 提示「该片段时长已变化，对轨已重新计算」；`locked` 的 item 保持起点不变 |
