# 12 · 功能域：录音

> 需求：FR-3（`00-需求规格.md`）
> 代码：`main/features/audio/recorder.ts` · `renderer/src/features/recording/` · `renderer/src/shared/audio/`
> 底层实现：`05-音频管线.md` §2（采集与落盘）、§3（崩溃恢复）、§4（VAD）

---

## 1. 三种录音模式

| 模式 | 适用 | 交互 | 产出 |
|------|------|------|------|
| **逐行录制**（默认） | 单人录音、配音新手、需要精确控制 | 一行一停，自动跳下一行 | 每个画本行 1 个 take / segment |
| **连续录制** | 熟练配音员、大段独白、效率优先 | 一路录到底，VAD 自动切片 | 一次会话 → 会话 WAV + 多个切片 |
| **角色模式** | 配音员只录自己的角色（任务包场景） | 只显示自己的行 + 可选旁白 | 同逐行/连续，但行集合被过滤 |

**模式是可切换的**，切换不动已有数据。三种模式共用同一套采集与落盘链路，差异只在「如何切分」与「显示哪些行」。

## 2. 录音会话状态机（主进程权威）

```
                    ┌──────────────────────────────────────┐
                    │                                      │
  idle ──prepare──▶ preparing ──ready──▶ recording ⇄ paused │
    ▲                  │                    │               │
    │                  └──fail──▶ error     │               │
    │                                       │               │
    └────── abort/stop ◀────────────────────┘               │
                                            │               │
                                        stop│               │
                                            ▼               │
                                      finalizing ───────────┘
                                            │
                        ┌───────────────────┼───────────────────┐
                        ▼                   ▼                   ▼
                      done            recovered            failed
```

| 状态 | 含义 | 允许的操作 |
|------|------|------------|
| `idle` | 无会话 | 准备设备、开始录制 |
| `preparing` | 申请设备、加载 worklet、检查磁盘 | 取消 |
| `ready` | 设备就绪，等待用户按录制（有倒计时） | 开始、取消 |
| `recording` | 正在采集与写盘 | 暂停、停止、打标记 |
| `paused` | 暂停采集（不写盘，已采集缓冲保留） | 继续、停止 |
| `finalizing` | 定稿文件、生成片段、入库 | 不可取消（必须完成） |
| `done` | 完成 | — |
| `recovered` | 由启动恢复产生 | 可继续录制（新建会话） |
| `failed` | 失败（设备错误/磁盘满） | 查看原因、重试 |

**关键约束**
1. `paused` 期间**不丢缓冲**：已采集但未写盘的样本继续写完再真正暂停。
2. `finalizing` 不可取消：它只有三件事（补头、生成片段、入库），必须做完。UI 在此期间显示「正在保存，请勿关闭」。
3. **磁盘空间检查**：`preparing` 阶段必须检查剩余空间（按 1 分钟录音约 8.6 MB 估算，要求 ≥ 500 MB）；`recording` 期间每 30 秒复查，不足则**主动停止并保住数据**。

## 3. 逐行录制模式

### 3.1 主界面

```
┌───────────────────────────────────────────────────────────────┐
│ 第1章 陨落的天才                   录制中 ●   00:12.4  [■ 停止] │
├───────────────────────────────────────────────────────────────┤
│ 当前行 42/87   ▸ 说话人：萧炎   ▸ 情绪：愤怒(4)   ▸ 语速：快    │
│                                                               │
│   「我萧炎，从来不会认输。」                                     │
│                                                               │
│ 备注：这里是情绪爆发点，不要喊破音                                │
│ 发音提示：无                                                    │
├───────────────────────────────────────────────────────────────┤
│ 上下文（前 2 / 后 2，当前行框出）：                              │
│  40 (旁白) 殿内一片寂静。                                       │
│  41 (旁白) 他缓缓抬起头，眼中闪过一丝狠厉。                       │
│  42 (萧炎) 我萧炎，从来不会认输。      ← 当前行（加框高亮）        │
│  43 (药老) 小子，别冲动。                                       │
│  44 (旁白) 药老按住他的肩膀。                                   │
├───────────────────────────────────────────────────────────────┤
│  ▁▂▃▅▇▇▆▅▃▂▁▁▂▃▅▇▆▄▂▁  电平 ████████░░░  -6.2 dBFS  峰值 -3.1 │
│  take: [1 ✓] [2] [3]      [▶ 试听] [A/B] [设为成品] [🗑]        │
├───────────────────────────────────────────────────────────────┤
│ [倒计时 3s▾] [◀ 上一行] [● 录制/停止] [下一行 ▶] [跳过] [补录]   │
└───────────────────────────────────────────────────────────────┘
```

> 上下文取的是**整章**里当前行的前 2 行与后 2 行（含当前行，见 `shared/canvas/context-window.ts`）。
> 即使开了「按角色录制」（§3.4），相邻行也按整章取 —— 别的角色的台词往往正是语气衔接的提示；
> 用筛选后的集合取下标会把它们漏掉。

### 3.2 录制循环（一次按键 → 一次成品）

```
1. 显示当前行（含上下文、情绪、备注、发音提示）
2. 可选倒计时（默认 3 秒，可关；按下录制键立即开始）
   —— 倒计时**归零必须真的开始采集**（会话准备 → `record:start`），
      不是「把遮罩关掉就完事」：真机事故 docs/91 §5.2.37 就是这一步漏了，
      表现为「点击录制没有开始」。倒计时期间按任意键 = 立刻开始，不是取消本次录制。
      这段状态机只有一份实现（`composables/useRecordCountdown.ts`，可单测）
   ⚠️ 关闭倒计时（`countdownMs = 0`）时，`countdown.request(0)` 返回 **false**，
      调用方**必须**立即开录 —— 真机事故 docs/91 §5.2.45：两个录音视图都忽略过这个返回值，
      结果「倒计时设成 0 → 点录制完全没反应」。
3. 采集开始 → 实时波形 + 电平表
4. 停止（Enter / 空格 / 按钮 / 踏板）
5. finalize：
   a. 定稿 WAV
   b. 静音修剪（首尾，按设置）
   c. 生成 take（保留原始 + 修剪后）
   d. 若该行无 segment → 生成 segment（指向该 take + 区间），画本行 state → recorded
   e. 可选：自动播放本次录音（默认开，便于自检）
6. 自动跳下一行（可关）
```

### 3.3 逐行模式的关键细节

| 细节 | 处理 |
|------|------|
| **最短录音保护** | < 150 ms 的录音直接丢弃（误触），并提示「录音太短，已忽略」 |
| **超长告警** | > 60 s 提示「该行录音过长，是否确认？」（多半是忘了停） |
| **自动跳下一行** | 默认「跳到下一个未录行」，而非「序号 +1」（避免在已录区域反复跳） |
| **跳过** | 标记为「本轮跳过」，方便回头再录；不改变 state |
| **重录** | 覆盖成品（旧 take 保留），`state` 不变 |
| **A/B 对比** | 多 take 时并排播放或交替播放（左/右声道分离也可，作为高级选项） |
| **录音中改行** | 禁止（会误导）；必须先停 |
| **段落导航** | `Ctrl+↑/↓` 按段落跳（对话块） |
| **行内分段录** | 超长行可「拆成 2~3 段分别录」→ 生成多个 segment？（**注意**：`voice_segments` 对 `line_id` 唯一）→ 因此改为「多个 part 合成一个 segment」，用对轨的顺序拼接实现（见 `13`）|

> **超长行的处理决策**：`voice_segments(line_id)` 唯一约束是为了对轨清晰。若一行太长需要分段录，则在 `takes` 层记录多个 part，合成时按 `part_index` 顺序 concat 成一个 segment。`takes` 表加 `part_index` 字段支持这一点。

### 3.4 按角色录制（主界面角色筛选）

一个人分饰多角时，逐行/连续录制都可能在整章的行里来回跳。顶栏提供「**录制角色**」下拉：

- 选项：`全部角色`（默认，整章）、`旁白`、以及**本章实际出现的每个角色**（带行数，避免下拉里塞几十个没行的角色）；
- 选中后，当前行、上一行/下一行、行进度、完成度都只在**该角色的行**里走（纯逻辑在 `shared/canvas/role-filter.ts`，有单测）；
- 不改画本、不改行的说话人，也不影响 take 归属（take 仍挂在行上）—— 与 §5 任务包页同一语义，只是不要求先导入任务包；
- 录音中/暂停中禁止切换（会误导），切换后自动定位到该角色的第一个未录行；
- 不认识的角色 id → 空集合并给出提示，绝不退化成「全部行」（否则会录到别人角色的台词）。
- **只在逐行模式生效**：连续模式的一段录音会按整章做 VAD 切片与匹配（`continuous.store.runMatch` 面向整章），按角色过滤会误导「这段只属于我」，因此连续模式下入口隐藏、行集合不筛。

## 4. 连续录制模式

### 4.1 交互

```
按「开始连续录制」→（倒计时）→ 一直录 → 你说你的，它自己切
  期间可打标记：按 M 打标记（人工切点）/ 按 N 标记「这段重来」
按停止 → 主进程跑 VAD → 生成 K 个切片 → 自动匹配画本行 → 进确认界面
```

### 4.2 采集侧的实时反馈

| 反馈 | 说明 |
|------|------|
| 已录时长 | 大字号 |
| 实时波形 | 滚动显示，最近 5 秒。**未录音时显示当前行选中 take（试录版本）的整段波形，该行无 take 时为空**；停止后先显示**刚录完那一段**（自动跳行也不清），用户主动改行才切走 —— 波形数据走主进程 `analysis:peaks`（渲染进程 CSP 是 `connect-src 'self'`，读不了 `ns-media://` 音频），见 docs/91 §5.2.46 / §5.2.47 |
| 静音指示 | 当前是否处于静音（给用户「可以停了」的提示） |
| 切点提示 | 检测到切点时闪烁一下 + 轻微计数（可关，避免干扰） |
| **已匹配行数** | 实时显示「已识别到约 N 句」（用 VAD 计数估算，给用户进度感） |
| 快捷键 | `M` 手动打切点、`N` 标记重来、`Space` 停止 |

### 4.3 停止后的切片与匹配（`05` §4）

```
1. 定稿会话 WAV
2. VAD 分析（帧级）→ 得到候选切片 [start,end] 列表
3. 边界精修（头回退 80 ms、尾保留 200 ms）
4. 过滤（过短、过静音）
5. 与画本行匹配（DP，见 `05` §4.4）
6. 进入「切片确认界面」
```

### 4.4 切片确认界面（关键，决定连续录制好不好用）

```
┌──────────────────────────────────────────────────────────────┐
│ 连续录制结果：58 个切片 → 匹配 55 行                            │
│ 未匹配：3 个切片 | 缺录：2 行                                   │
├───────────────┬──────────────────────────────────────────────┤
│ 切片列表       │ 波形 + 时间线对照                              │
│ 1 ✓ →42  0.9  │ [====]  ▁▃▅▇▆▃▁  [====]  ...                  │
│ 2 ✓ →43  0.8  │ 42: 我萧炎，从来不会认输。                     │
│ 3 ? (未匹配)  │ 43: 药老：小子，别冲动。                       │
│ 4 ✓ →45  0.95 │                                               │
│ ...           │ [▶ 试听全部] [▶ 试听选中] [重切] [手动匹配]     │
├───────────────┴──────────────────────────────────────────────┤
│ [全部接受] [仅接受高置信] [重做切片(调参)] [放弃本次]            │
└──────────────────────────────────────────────────────────────┘
```

| 功能 | 说明 |
|------|------|
| 试听单个切片 | 立即播放 |
| 试听全部 | 按顺序连播（这是最快的验证方式） |
| 手动匹配 | 把未匹配切片拖到某画本行 |
| 拆分/合并切片 | VAD 切错了（一句话被切两半，或两句被粘一起）→ 手动调整 |
| 重切 | 调 VAD 参数（阈值/最短静音）后重新切片。**原始会话 WAV 还在**，所以可以反复重切（FR-3.13 的价值） |
| 接受策略 | 高置信自动接受，低置信进待确认 |

> **原始会话永不删除**是连续录制可行性的基础。用户切错了可以随时「从会话重切」。

## 5. 角色模式（任务包场景）

- 从 `.nst` 任务包导入时自动进入。
- 只显示该配音员负责的角色行；旁白可开关（默认关）。
- 画本**只读**：不能改文本、不能改说话人。
- 允许的操作：录音、重录、标记「文本有问题」（生成反馈项）、添加个人备注（本地）。
- 导出「录毕包」时打包全部 takes + `takes.json`。
- 顶部显示「[配音员名] · 共 142 行 · 已完成 87 行（61%）」。

## 6. 设备与诊断（FR-3.1）

### 6.1 设备诊断页

```
┌──────────────────────────────────────────────────────────────┐
│ 输入设备：[USB Condenser Microphone ▾]  [刷新]                 │
│ 采样率：  [48000 Hz ▾]（设备实际：48000 Hz ✓）                  │
│ 声道：    [单声道 ▾]                                           │
│ 增益：    [────●────] 0 dB                                    │
│ 监听：    [x] 启用   音量 [───●───] -6 dB   延迟：18 ms         │
├──────────────────────────────────────────────────────────────┤
│ 实时电平：  ████████░░░░░░░░  -12.3 dBFS   峰值 -6.1 dBFS      │
│ 底噪（3 秒测量）：-58.2 dBFS  [重新测量]   [作为降噪参考]        │
│ 削波：无    建议增益：+6 dB（当前偏小）                          │
├──────────────────────────────────────────────────────────────┤
│ 自检：[▶ 录 5 秒并回放]  结果：正常（无丢帧、无削波）             │
└──────────────────────────────────────────────────────────────┘
```

**「录 5 秒并回放」自检**必须做，它是用户排除「没声音/声音小/有杂音」的最快手段，可以省掉大量售后问题。自检结果检查项：
1. 是否有信号（RMS > -50 dBFS 才算有输入）
2. 是否削波（峰值 = 0 dBFS 出现多次）
3. 是否丢帧（采集样本数 vs 写盘样本数）
4. 底噪水平（建议是否需要降噪）
5. 实际设备采样率与请求采样率是否一致（不一致要提示重采样）

### 6.2 延迟测量

```
monitorLatencyMs ≈ (ctx.baseLatency + ctx.outputLatency) * 1000 + inputLatencyEstimate
```
输入延迟无法直接从 Web Audio 读出，用「点击-回声」法估算（可选高级功能）：播放一个短促脉冲，同时录音，找回声位置 → 单程延迟。**不强制**，先显示「估算值」。

## 7. 监听返送（FR-3.8）

| 配置 | 场景 | 风险 |
|------|------|------|
| 监听关闭（默认） | 纯录音 | 无 |
| 监听已有轨道（不开麦克风直通） | 对词、跟 BGM 唱/读 | 麦克风会拾取耳机漏音 → 建议戴封闭式耳机 |
| 监听 + 麦克风直通 | 想听自己的声音 | **啸叫风险高** → 必须戴耳机，且给出警告 |
| 节拍器 | 需要节奏 | 可能被录进去 → 建议戴耳机 |

**实现**（`05` §11.2）：
```
[参考音/BGM 轨] ─▶ monitorGain ─┐
[上一行/下一行试听] ────────────┼─▶ destination
[节拍器] ──────────────────────┘
```

**必须处理的坑**
1. **监听回放会被麦克风拾取**：无法完全避免（除非耳机隔音好）。对策：
   - 默认开启 `echoCancellation`（当监听开启时），并在 UI 说明「已启用回声消除，音色可能略有变化，追求音质请在设置中关闭并戴好耳机」。
   - 提供「录音期间自动降低监听音量」选项。
2. **`echoCancellation` 会引入处理伪影**：它是为通话设计的。**专业用户应关闭**，因此必须可配置，且默认值要按用户水平决定（高级模式关闭）。
3. **监听链路的增益必须独立**于录音增益，否则用户调监听的音量会改变录制音量（这是非常常见的实现错误）。

## 8. 多 take 与补录

### 8.1 多 take 管理

```ts
interface Take {
  id: string
  lineId: string
  sessionId: string
  filePath: string
  partIndex: number          // 超长行分段录时的顺序
  srcInMs: number            // 在会话文件中的区间
  srcOutMs: number
  trimmedInMs: number        // 修剪后的实际有效区间（相对 take 文件）
  trimmedOutMs: number
  durationMs: number
  peakDb: number
  rmsDb: number
  gainDb: number
  sampleRate: number; bitDepth: number; channels: number
  deviceLabel: string | null
  source: 'local' | 'package'      // 本地录的 or 从任务包回收的
  packageId: string | null
  flags: string | null             // ['clip','too_short','too_long','noise','reported']
  isSelected: 0 | 1                // 是否为当前成品
  createdAt: number
}
```

- **任何 take 都不自动删除**（除用户显式清理），包括被替换的。
- A/B 对比：并排播放、交替播放、或左右声道分离（高级）。
- 选中后更新 `voice_segments` 指向该 take（`segment.take_id`）。

### 8.2 补录（Punch-in，FR-3.9）

```
1. 在对轨页或录音页选中要修补的位置（片段内区间）
2. 进入补录模式：播放前置 2 秒（pre-roll）→ 到补录点自动开始录 → 按停
3. 拼接：原片段 [0, in) + 新录音 + 原片段 [out, end)
4. 拼接处交叉淡化 10 ms（防爆音）
5. 生成新 take（不覆盖原文件），可选设为成品
```

**pre-roll/post-roll** 必须支持（默认 2 s / 1 s），否则用户很难接上语气。

## 9. 快捷键与外部控制（FR-3.12）

### 9.1 默认快捷键（可自定义）

| 功能 | 默认键 |
|------|--------|

| 下一行 | `↓` 或 `Ctrl+→` |
| 上一行 | `↑` 或 `Ctrl+←` |
| 跳过（本轮） | `→`（录制空闲时） |
| 播放当前 take | `P` |
| 播放上一行 | `Shift+P` |
| 录制中打标记 | `M` |
| 连续录制：标记重来 | `N` |
| 撤销上一个 take 选择 | `Ctrl+Z` |
| 切换监听 | `Ctrl+M` |
| 下一段落 | `Ctrl+↓` |

### 9.2 脚踏板

- 通过 `navigator.getGamepads()` 或键盘映射（多数踏板模拟键盘 `F13`/`Ctrl` 等）。
- 映射表可配置：「踏板 = 停止并下一行」（最重要的用法）。
- 提供「踏板测试」界面（按下 → 显示检测到的键/按钮），否则用户配不上会以为软件坏了。

### 9.3 全局快捷键冲突

录音页激活时**接管**全局快捷键，并禁用可能误触的系统级快捷键（如 `Ctrl+W` 关闭窗口在录音中要拦截 —— 防止误关导致录音中断）。

> 这条很重要：录音中拦截窗口关闭，改为「先停止录音并保存，再关闭」。

## 11. IPC 接口（录音侧）

| 通道 | 模式 | 说明 |
|------|------|------|
| `record.prepare` | invoke | 检查磁盘、创建会话记录、准备写盘 |
| `record.attachPort` | invoke | 声明「这个（由 preload 转移的）端口归哪个会话」。**端口本身走 `record:port`**，两条消息不保证先后，失败必须重试而不是静默（docs/91 §5.2.41） |
| `record.start` | invoke | 开始采集写盘 |
| `record.pause` / `record.resume` | invoke | 暂停/继续 |
| `record.stop` | invoke | 停止 → 定稿 → 生成 take/segment |
| `record.abort` | invoke | 放弃（删除会话文件） |
| `record.mark` | send | 录制中打标记（时间点） |
| `record.meter` | send（渲染→主） | 电平上报（用于写库统计，可选） |
| `record.status` | event（主→渲染） | 状态机变更 |
| `record.progress` | event | 已录时长、写盘样本数、丢帧计数 |
| `record.slice` | invoke | 连续录制：执行 VAD 切片 |
| `record.matchSlices` | invoke | 切片与画本行匹配（DP） |
| `record.acceptSlices` | invoke | 接受匹配结果 → 生成 takes/segments |
| `record.reslice` | invoke | 用新参数重新切片（原始会话仍在） |
| `takes.list` / `setSelected` / `delete` / `flag` | invoke | take 管理 |
| `takes.compare` | invoke | A/B 对比播放信息（返回两个文件路径） |
| `record.punchIn` | invoke | 补录（指定 lineId + 区间） |
| `devices.list` | invoke | 设备枚举（**主进程转发**，实际由渲染进程 `enumerateDevices` 完成，需权限） |
| `devices.selfTest` | invoke | 自检结果落库与报告 |

> **设备枚举位置说明**：`navigator.mediaDevices.enumerateDevices()` 只能在渲染进程调用（需要用户授权后才能拿到 `label`）。因此设备列表由渲染进程获取，但**设备偏好与自检结果存主进程**，两侧通过 IPC 同步。

## 12. 异常处理

| 场景 | 处理 |
|------|------|
| 麦克风权限被拒 | 明确指引到系统设置；提供「重试授权」按钮 |
| 设备被其他程序独占 | 提示可能占用的程序；提供设备切换；允许进入「只听不录」模式查看已有素材 |
| 设备中途被拔出 | 立即停止录音 → **定稿已录部分** → 提示「设备已断开，已保存 X 分钟素材」 |
| 采样率不匹配 | 自动重采样并在 UI 提示；写库记录实际采样率 |
| 磁盘空间不足 | 停止录音、保住数据、明确提示需要释放多少空间 |
| 写盘速度跟不上（网络盘） | 背压机制（`04` §6）→ 必要时停止并告知 |
| 采集到全静音（设备静音/选错设备） | 录满 3 秒仍无信号 → 警告「未检测到输入信号，请检查设备」（不自动停止，但强提示） |
| 长时间削波 | 峰值持续 0 dBFS > 10 次 → 提示「输入过载，建议降低增益」并标记 take |
| 录音过程中应用崩溃 | 启动恢复（`05` §3）→ 提示已恢复的素材 |
| 定时/长度上限 | 单会话默认上限 4 小时（可配）→ 到达时自动停止并保存 |

## 13. 测试要点

| 测试 | 用例 |
|------|------|
| 采集完整性 | 录 10 分钟，对比采集样本数与写盘样本数（**必须完全相等，丢帧数 = 0**）。核对口径：主进程拿渲染侧上报的**累计** `claimedFrames` 与「已落盘 + 内存中」相减；因为数据（端口）与声称（IPC）是两条独立通道，**要求连续两次采样都缺同一段**才计丢帧 —— 单次缺口只是"数据还在途中"，不得报给用户（docs/91 §5.2.41） |
| 崩溃恢复 | 录制中强杀进程（含在写盘的瞬间），重启后恢复的音频可播放、时长正确、无爆音 |
| 崩溃恢复（丢 meta） | 手动删除 `.meta.json` 后恢复，验证按文件大小推算正确 |
| 设备热插拔 | 录制中拔出设备，验证已录素材完整 |
| 磁盘满 | 用小的虚拟盘或 mock 模拟，验证停止+保数据+提示 |
| VAD 切片 | 20 段真实朗读（含停顿、咳嗽、翻页声），验证切片边界与内容一致 |
| 切片匹配 | 切 58 段对 58 行画本，验证匹配准确率 ≥ 95% |
| 重切 | 改 VAD 参数重切，验证不丢原始会话 |
| 逐行循环 | 连录 50 行，验证每行 take 正确、state 正确、跳转正确 |
| 多 take | 同一行录 5 次，验证全部保留、A/B 可切、设为成品唯一 |
| 补录 | 在心片段中间补录，验证拼接处无爆音（波形检查 + 听感） |
| 监听 | 验证监听音量不影响录音音量；验证开启直通时的啸叫风险提示出现 |
| 快捷键 | 全部快捷键可触发；录音中 `Ctrl+W` 被拦截 |
| 性能 | 录音 30 分钟期间：UI 帧率、内存增长（应平稳）、CPU 占用 |
| 权限 | 首次授权流程、拒绝后恢复、设备 label 显示正确 |
