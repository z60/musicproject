## 1. 「对轨」的定义（必须先说清）

这个词在不同团队含义不同，本项目明确为**三件事的合集**：

| # | 子功能 | 解决的问题 | 产出 |
|---|--------|------------|------|
| 1 | **录制对齐**（Recording Alignment） | 「这段录音对应哪一行画本？」 | `voice_segments.line_id` 正确无误 |
| 2 | **多轨排布**（Arrangement） | 「每个角色的话在时间线的哪个位置？留多少白？和旁白怎么交错？」 | `arrangement_items`（每片段的位置） |
| 3 | **人工微调**（Fine-tuning） | 「自动排的不满意，我要手工挪」 | 被人工锁定的位置与裁剪点 |

**外延（1.0 只留接口）**：**AI 强制对齐** —— 用 ASR 词级时间戳校验「录音里实际说的」与「画本上写的」是否一致，检出漏读/错读/跳行。见 §8。

## 2. 数据模型

```ts
interface Arrangement {
  id: string
  chapterId: string
  name: string                  // 「标准版」「快节奏版」
  isDefault: 0 | 1
  strategy: 'serialize' | 'keep' | 'compress-pause' | 'tighten'
  totalDurationMs: number       // 计算缓存（重算后更新）
  createdAt: number; updatedAt: number
}

interface ArrangementItem {
  id: string
  arrangementId: string
  segmentId: string
  lineId: string
  trackId: string               // 'narration' 或 characterId
  timelineStartMs: number       // 章节时间线上的绝对起点
  srcInMs: number               // 源片段内起点（裁剪）
  srcOutMs: number              // 源片段内终点
  fadeInMs: number              // 默认 5
  fadeOutMs: number
  locked: 0 | 1                 // 人工锁定，自动排布不动它
  overlapWith: string | null    // 与之交叠的 item（冗余缓存，便于 UI 高亮）
  orderInTrack: number          // 轨内顺序（用于稳定排序）
}

interface ArrangementValidation {
  missingLines: string[]        // 缺录的画本行
  orphanSegments: string[]      // 无对应画本行的片段
  sameTrackOverlaps: Array<{ a: string; b: string; overlapMs: number }>
  crossTrackOverlaps: Array<{ a: string; b: string; overlapMs: number; level: 'normal' | 'warning' }>
  longGaps: Array<{ afterLineId: string; gapMs: number }>
  shortSegments: string[]
  longSegments: string[]
  totalDurationMs: number
  warnings: string[]
}
```

> **为何 `arrangement_item` 与 `voice_segment` 分离**：同一片段可以在不同方案里处于不同位置（干声版/带 BGM 版/紧凑版），且位置是可反复调整的可变参数。合并成一张表会导致「改位置 = 改素材」的耦合。

## 3. 录制对齐（子功能 1）

### 3.1 自动匹配（FR-4.2）

来源场景：
| 场景 | 匹配方式 |
|------|----------|
| 逐行录制 | 无需匹配 —— 录制时已知 `lineId`，直接绑定 |
| 连续录制 | 录制后 VAD 切片 + DP 匹配（`05` §4.4） |
| 任务包回收 | 靠 `lineId` 直接归位（无需匹配） |
| 外部导入音频文件（3.0 候选） | 只能靠顺序 + 时长 + ASR |

**匹配置信度的三种信号**
```
score = w1 * durationScore + w2 * textScore + w3 * orderScore
durationScore = 1 - |dur_actual - dur_expected| / max(dur_expected, 0.5s)   （clamp 到 0）
textScore     = 1 - CER(ASR文本, 画本文本)          （无 ASR 时为 null，权重归零）
orderScore    = 1 - |index_slice - index_line| / N
默认权重：w1=0.45, w2=0.45, w3=0.10（无 ASR 时 w1=0.8, w3=0.2）
```

### 3.2 手动匹配界面

未匹配的片段与未绑定的画本行在**同一个界面**处理（这是关键 —— 分成两个列表用户就懵了）：

```
┌───────────────────────────────────────────────────────────────┐
│ 未匹配片段 (3)          画本行 (2 行缺录)                       │
├───────────────────────────────────────────────────────────────┤
│ ▸ 切片 3  0:02.1  [?]  │  42 萧炎: 我萧炎，从来不会认输。        │
│ ▸ 切片 7  0:01.4  [?]  │  43 药老: 小子，别冲动。               │
│ ▸ 切片 12 0:00.3  [?]  │                                       │
├───────────────────────────────────────────────────────────────┤
│ 操作：拖拽匹配 | 选中后按数字键指派 | [自动匹配剩余] [全部放弃]   │
│ 试听：[▶ 选中切片] [▶ 选中画本行已有录音] [▶ 连续播放对照]        │
└───────────────────────────────────────────────────────────────┘
```

**交互要求**
- 拖拽匹配 + 键盘匹配（选中切片 → 按 `1..9` 指派到列表第 N 行）。
- 支持「一个切片匹配多行」（罕见，如连续两句被切成一段）→ 提示会拆分。
- 支持「多个切片匹配一行」（一句话被切两半）→ 合成一个 segment（按顺序 concat）。

## 4. 多轨排布（子功能 2）

### 4.1 轨道构成

```
轨道 0  旁白（narration）        —— 通常最长，是全章骨架
轨道 1  角色 A
轨道 2  角色 B
轨道 3  角色 C（…按出场顺序）
轨道 N  BGM（音乐总线，见 14/15）
轨道 N+1 音效（SFX）
```

**轨道顺序规则**：旁白固定第一轨（视觉稳定）；其余按该章出场次数降序；可手动排序（用户偏好持久化）。

### 4.2 自动排布算法（`05` §5.2）

```
cursor = 0
for line in allLines.sortBy(seq):                    # 全章按画本 seq 全局串行
    seg = segmentOf(line)
    if seg == null: continue                         # 缺录 → 记 gap，cursor 不动
    dur = (srcOut - srcIn) + fadeIn + fadeOut
    start = max(cursor + pauseAfter(prevLine), 0)
    if item.locked: start = item.timelineStartMs      # 尊重人工
    upsert item(start, srcIn, srcOut, trackId=line.trackId)   # 轨道只是车道
    cursor = start + dur
totalDuration = 最后一个 item 的结束 + tailSilenceMs
```

**留白优先级**：`line.pauseAfterMs` > 角色默认 > 章节默认（500 ms）。

### 4.3 重叠检测与消解（FR-4.5，本项目最易做错的地方）

**必须区分同轨与跨轨**（原因见 `05` §5.2）：

| 类型 | 判定 | 默认动作 |
|------|------|----------|
| 同轨重叠 | 同 `trackId` 内区间相交 | **必须消解**（同一人不能同时说两句） |
| 跨轨 · 正常对话 | 相交 ≤ `maxOverlapMs`（默认 3000 ms） | 保留 |
| 跨轨 · 疑似异常 | 相交 > `maxOverlapMs` | 列入报告（`level: 'warning'`） |
| 同角色相邻句 | 同角色相邻两行的 item 相交 | 串行化 |

**消解策略**
| 策略 | 算法 | 何时用 |
|------|------|--------|
| `serialize`（默认） | `start_b = end_a + minGapMs`（默认 50） | 通用 |
| `compress-pause` | 先把 `a` 之后的留白压到 0（`end_a` 不动，把 `b` 左移）；仍相交才后移 | 不想改变节奏 |
| `tighten` | `start_b = end_a + 20ms` 并把 `a` 的尾部静音修剪掉 | 快节奏、对话密集 |
| `keep` | 不动，只记录 | 有意做交叠（群戏、抢话） |

**逐条处理优先于全局**：报告中每条冲突都可单独选择策略（UI 上给三个按钮）。因为「哪句该让」只有人知道。

### 4.4 留白与节奏

| 来源 | 示例 |
|------|------|
| 画本行停顿 | `pauseAfterMs = 900` → 该行之后留 900 ms |
| 段落留白 | 原文段落结束 → 由画本推断的较大值（见 `11` §2.3） |
| 场景切换 | 说话人变化 + 段落结束 → 1200 ms |
| 章首 | `headSilenceMs`（设置，默认 500） |
| 章尾 | `tailSilenceMs`（设置，默认 1500） |
| 全局节奏 | 预设乘数 `紧凑 0.8 / 标准 1.0 / 舒缓 1.3` |

**「留白过长」检测**：连续静音 > 5 s（非章头章尾）→ 列入报告（多半是缺录了一行）。

### 4.6 视图能力

| 能力 | 要求 |
|------|------|
| 横向缩放 | 从「整章总览」到「样本级（~1 ms/px）」；滚轮 + `Ctrl` 缩放，`Shift`+滚轮 平移 |
| 纵向缩放 | 轨道高度可调（紧凑/标准/宽松），或单轨展开（放大波形细节） |
| 波形 LOD | 3 级（100/10/1 peaks/s），按缩放级别自动切换（缓存见 `04` §4） |
| 画本行对照 | 每轨的每个 item 上叠加行号与文本首 10 字；悬停显示完整文本 |
| 播放头 | 可拖动；`Space` 播放/暂停；点击任意位置定位 |
| 循环区间 | 框选区间循环播放（用来反复听一处重叠） |
| Solo/Mute | 每轨独立，用于听单轨与检查重叠 |
| 缩放记忆 | 每个章节记住上次的缩放与滚动位置 |
| 性能 | 1000 个 item 下拖动 ≥ 30 fps（脏矩形重绘 + 空间分区命中检测） |

### 4.7 手动微调（FR-4.7 / FR-4.8）

| 操作 | 交互 | 数据变化 |
|------|------|----------|
| 拖动整体 | 拖 item 主体 | `timelineStartMs` ± Δ |
| 拖左边缘（改起点） | 拖左边把手 | `timelineStartMs += Δ` **且** `srcInMs += Δ`（保持内容绝对位置不变） |
| 拖右边缘（改终点） | 拖右边把手 | `srcOutMs += Δ` |
| 裁剪静音 | 右键 → 自动修剪 | 扫描后设置 `srcInMs/srcOutMs` |
| 锁定 | 锁图标 / 右键 | `locked = 1` |
| 解锁并重排 | 右键 | `locked = 0` 后重跑该轨排布 |
| 重置 | 右键 | 恢复为自动排布结果 |
| 微调步进 | 选中后按 `←/→` | ±10 ms（`Shift` ±1 ms，`Ctrl` ±100 ms） |
| 吸附 | 拖动时（默认开） | 吸附到网格/相邻边界/画本行边界；`Alt` 临时关闭 |

> **拖左边缘的语义陷阱**（`05` §5.4）：只改 `timelineStartMs` 会让音频内容跟着位移；正确做法是两者反向补偿。**必须写单测**，这是最容易错的一行代码。

### 4.8 撤销/重做

对轨操作有独立 undo 栈（≥50 步）。撤销一个「批量消解重叠」= 一次撤销整批。

## 5. 校验（FR-4.11）

```ts
type AlignIssueKind =
  | 'missing_line'          // 画本行无片段（缺录）
  | 'unarranged_line'       // 有片段但不在方案条目里（渲染会丢音频；重新自动排布）
  | 'orphan_segment'        // 片段无画本行
  | 'same_track_overlap'    // 同轨重叠（必须修）
  | 'cross_track_overlap_warn'  // 跨轨重叠过大
  | 'long_gap'              // 非首尾的过长静音（> 5 s）
  | 'short_segment'         // < 200 ms
  | 'long_segment'          // > 60 s
  | 'silent_segment'        // RMS < -60 dBFS（录成了静音）
  | 'clipped_segment'       // 削波
  | 'file_missing'          // 音频文件丢失
  | 'wrong_order'           // 轨内顺序与画本顺序不一致（可能是错绑）
```

`wrong_order` 值得单独说：如果某轨的 item 时间顺序与画本 `seq` 顺序相反，几乎一定是**错绑**（把第 50 行录的内容绑到了第 20 行）。这是一个极有价值的自动检错，能抓到人工匹配的错误。

> **`missing_line` 的判定源是 `voice_segments`**（没有片段才算缺录），**不是**「方案里没有条目」。
> 后者是 `unarranged_line`（有录音但还没排进时间线，重排即可归位）。两者混同的后果
> （真机）：一章 87 行、87 个片段全录完，却因为还没有对轨方案而显示「缺录 87 行」。

**校验报告 UI**：按类型分组、点击跳转到时间线对应位置、提供「一条一条处理」的引导模式（类似待确认队列）。

## 6. 试听与预览（FR-4.10）

### 6.1 实时试听（渲染进程）

```
[片段文件 (ns-media://)] ─▶ AudioBufferSourceNode ─▶ itemGain ─▶ trackGain ─▶ master ─▶ destination
                                   ▲
                            按 arrangement 的 offset 调度启动
```
- 播放时按 `timelineStartMs` 调度每个 `AudioBufferSourceNode.start(when, offset, duration)`。
- 片段音频预加载为 `AudioBuffer`（小片段可全部载入；长章节按播放窗口懒加载）。
- **不做实时处理链**（处理链交给 ffmpeg，见 `14`）：试听时可选用 `processed_path` 或原始文件。
- 播放精度：Web Audio 的 `when` 是采样级精确，足够。

### 6.2 轻量渲染预览（主进程）

试听用的是**播放器混音**，与最终 ffmpeg 渲染结果可能有细微差异（尤其 ducking）。因此提供「渲染前 30 秒」按钮，用真实的 ffmpeg 管线渲染一小段，用于确认预设（FR-6.10）。

## 7. 多方案（FR-4.13）

- 一个章节可以有多个 `arrangement`（标准版 / 紧凑版 / 带 BGM 版）。

- 混音导出时选择方案（`15`）。
- **默认方案**：`isDefault=1`，自动对轨时写入该方案。

## 8. AI 强制对齐（FR-4.12，1.0 只留接口）

### 8.1 目标

检出三类问题（这些问题人工极难发现）：
1. **漏读**：画本行有内容，录音里没读
2. **错读**：读了但内容不符（读错、跳字）
3. **串行**：录的内容属于另一行（错绑的终极检测）

### 8.2 接口（已就绪，1.0 不实现）

```ts
interface ForcedAlignProvider {
  align(audioFile: string, expectedText: string, opts?: {
    language?: string
    wordTimestamps?: boolean
  }): Promise<{
    words: Array<{ text: string; startMs: number; endMs: number; prob: number }>
    transcript: string
    overallScore: number                       // 0..1
    verdict: 'ok' | 'partial' | 'mismatch'
  }>
}
```

### 8.3 实现要点（预先记录，避免将来踩坑）

| 要点 | 说明 |
|------|------|
| whisper 时间戳 | token 级；中文需按词边界合并（否则会出现半个字的边界） |
| 文本归一化 | 比对前必须去标点、繁简统一、数字转中文（`12` ↔ `十二`）、英文大小写统一 |
| 漏读判定 | 用「画本行的关键词命中率」而非整句相似度（整句相似度对短句不敏感） |
| 效率 | 只对 `needsReview` 或用户手选的片段跑；whisper 很慢 |
| 模型 | 需要 `ggml-base` 及以上；`tiny` 中文识别质量太差 |
| 数据 | `arrangement_items` / `takes` / `canvas_lines` 字段已足够，无需改表；新增 `asr_results` 缓存表即可 |

```
    ├── useTimelineRenderer.ts     Canvas 绘制（含 LOD 与脏矩形）
    ├── usePlaybackScheduler.ts    基于 arrangement 的调度播放
    └── useOverlapResolver.ts      重叠检测与消解
```

**渲染架构说明**：时间线**不用 DOM 元素渲染片段**（1000 个 DOM 节点 + 拖动会卡）。采用：
- Canvas 2D 绘制所有片段与波形；
- 命中检测：按轨道行分组 + 轨内按 `timelineStartMs` 二分查找；
- 交互层：Canvas 上的 pointer 事件 + 状态机（idle / dragging / resizing / panning / selecting）；
- 拖动时只重绘脏矩形区域；
- Worker + `OffscreenCanvas` 负责波形路径计算，主线程只提交绘制指令。

| `alignment.getArrangement` | 取方案（按章节） |

| `alignment.createArrangement` / `duplicate` / `delete` / `setDefault` | 方案管理 |
| `alignment.updateItem` | 更新单个 item（位置/裁剪/锁定） |
| `alignment.batchUpdateItems` | 批量更新（一个事务，用于拖动结束后提交） |
| `alignment.validate` | 校验 |
| `alignment.resolveOverlap` | 消解指定重叠（带策略） |
| `alignment.resetTrack` / `resetAll` | 重置为自动排布 |
| `alignment.autoMatchSegments` | 自动匹配片段与画本行（DP） |
| `alignment.bindSegment` / `unbindSegment` | 手动绑定/解绑 |
| `alignment.previewRender` | 轻量渲染预览（前 N 秒） |
| `alignment.forcedAlign` | AI 强制对齐（1.0 返回 `NOT_IMPLEMENTED`，接口占位） |

## 11. 异常与边界

| 场景 | 处理 |
|------|------|
| 画本改过（增删行）后重跑自动对轨 | 保留 `locked` 的 item；新增行追加到轨尾并标记「新」；删除行的 item 移到「待处理」（不自动删音频） |
| 片段文件丢失 | item 保留但标记 `file_missing`，渲染时跳过并在校验中报告 |
| 方案被混音导出引用后又改了对轨 | 提示「该方案已被用于导出，修改后需重新渲染」 |
| 章节极长（> 2000 个 item） | 时间线默认用最低 LOD；提供 MiniMap；限制批量操作的提交频率 |
| 角色被归档后仍有 item | item 保留；轨道头显示为「已归档角色」，仍可播放 |
| 同一片段被多个 item 引用（不应发生） | 校验拦截（`segment_id` 在非交叠方案内应唯一） |
