## 1. 画本是什么（一句话）

> **画本 = 把小说文本翻译成「谁、用什么情绪、什么语速、停多久、这句话怎么读」的表演脚本。**

它是全系统唯一主轴：录音、对轨、混音、任务包分发全部挂在 `canvas_line` 上。

## 2. 生成流程（主进程）

```
canvas.generate 任务
├─ Step 1  切句分页        每个章节文本 → 画本行初稿（保留 charStart/charEnd）
├─ Step 2  规则粗筛        kind（dialogue/narration/inner/sfx_note）+ 引号剥离 + 引导语提取
├─ Step 3  角色抽取        生成/更新角色表候选（首次生成时）
├─ Step 4  上下文拼装      前后 N 行 + 最近引导语 + 上一说话人
├─ Step 5  向量判定        embedding + centroid 余弦 → speaker + confidence + candidates
├─ Step 6  规则后处理      引导语覆盖、连续对白偏向、场景内角色过滤、短句保护
├─ Step 7  标记推断        情绪/语速（词表优先，可选用 LLM）
├─ Step 8  停顿推断        pauseAfterMs（句末标点 + 段落边界 + 场景切换）
├─ Step 9  落库 + 统计     事务写入；更新 centroid；返回统计报告
```

**每次生成前自动打快照**（FR-2.4.7），可回滚。

### 2.1 切句规则（Step 1）

```
主切分：句末标点 。 ！ ？ … ；(弱) 
次切分：若单句 > maxLineChars（默认 120）→ 在逗号/破折号处二次切（优先取靠中间的）
不分切：引号内部即使有逗号也不切（保持台词完整）
不断开：引号对内部、书名号内部、括号内部
段落边界：空行 → 强制断行，且该行 pauseAfterMs 加长（段落留白）
```

**为什么要有 `maxLineChars`**：一行太长会导致「录的时候忘词、对轨时波形方块过大、任务包读起来累」。超过阈值的行标 `flags:['too_long']` 并在质检里列出。

### 2.2 引号与对白解析（Step 2）

```ts
interface QuoteParseResult {
  kind: 'dialogue' | 'narration' | 'inner' | 'sfx_note'
  text: string                  // 剥离引号后的可录文本
  quoteStyle: string | null     // 使用的引号族
  cue: {                        // 引导语（若有）
    verb: string                // 说/道/问/喊...
    speakerHint: string | null  // 从引导语提取的人名
    position: 'before' | 'after' | 'middle'
  } | null
  unbalanced: boolean           // 引号不配对
}
```

处理顺序
```
1. 检测 `“ ”` / `「 」` / `『 』` / `" "` / `' '`（按嵌套深度，从内层向外配对）
2. 若无引号但匹配 `——对白` 形式 → dialogue（破折号对白）
3. 若整行以引导语结尾且无引号（如 `他说道。`）→ narration（这是叙述，不是台词）
4. 心理描写：行内含「心想/暗忖/心道/心中/暗自/默默想」且无引号 → inner
5. 音效提示：形如 `【...】` 或 `（音效：...）` → sfx_note（不作为台词，仅提示）
6. 引号不配对 → 标 `flags:['quote_unmatched']`，进质检（多半是分句切错了）
```

### 2.3 停顿推断（Step 8）

| 条件 | `pauseAfterMs` |
|------|----------------|
| 句末 `。` 且行尾 | 500（默认） |
| 句末 `！`/`？` | 450 |
| 句末 `……` 或 `—`（拖音/被打断） | 700 |
| 行尾是 `，`（分行未断句，多为二次切） | 200 |
| 段落结束（原文空行） | 900 |
| 场景切换（下一行说话人变化 + 段落结束） | 1200 |
| `kind='dialogue'` 连续对白（同一角色） | 350（对话更紧凑） |
| 显式标记覆盖 | 以标记为准 |

> 这些数值都要**可配置**且提供「全局节奏」预设：`紧凑 / 标准 / 舒缓`（对全部值乘 0.8 / 1.0 / 1.3）。

### 2.4 生成报告

```ts
interface CanvasGenerateReport {
  chapterId: string
  totalLines: number
  byKind: { dialogue: number; narration: number; inner: number; sfxNote: number }
  bySpeaker: Array<{ characterId: string | null; name: string; lines: number; chars: number }>
  byDecision: { rule: number; vector: number; llm: number; human: number }
  lowConfidence: number            // needsReview=1 的行数
  unmatchedQuote: number
  tooLong: number
  elapsedMs: number
  embeddingUsed: boolean           // 是否真的用了向量（模型缺失时为 false，要明确告知）
  llmUsed: boolean
  warnings: string[]
}
```

**UI 必须显示这个报告**，尤其 `embeddingUsed=false` 时要用醒目提示：「未启用向量判定（模型未找到），当前为规则判定，准确率较低」，否则用户会以为是 AI 不行。

## 3. 数据模型（画本行）

字段定义见 `03-数据模型与存储.md` §4。这里补充**为什么这些字段必须存在**：

| 字段 | 缺了会怎样 |
|------|------------|
| `sourceText` | 改过错别字后无法重算判定，也无法与原文对照 |
| `charStart/charEnd` | 无法做「点画本行高亮原文」；重新分句时无法定位 |
| `confidence` + `candidates` | 用户面对「判错了」无法理解原因，也无法快速改对（要一列列找角色） |
| `decidedBy` | 重算会覆盖人工修改（**这是最恼人的 bug**） |
| `needsReview` | 无法做「只处理存疑行」的工作流，用户被迫从头扫到尾 |
| `pauseAfterMs` | 对轨只能瞎猜留白，成品节奏会很怪 |
| `pronunciation` | 多音字必错（`重` `行` `还` `长` `shuí`/`shéi`） |

### 4.2 表格视图（`CanvasTable.vue`）

| 列 | 内容 | 可编辑 | 宽度 |
|----|------|--------|------|
| 序 | 行号 | 否 | 常 |
| 状态 | 图标（未录/已录/待确认/有问题） | 否 | 常 |
| 说话人 | 角色名 + 置信度色带 + 候选提示 | 是（下拉 + 快捷键） | 中 |
| 类型 | 旁白/台词/内心/音效 | 是 | 窄 |
| 文本 | 可编辑文本（多行折叠） | 是 | 弹性 |
| 情绪 | 标签 + 强度 | 是 | 中 |
| 语速 | slow/normal/fast | 是 | 窄 |
| 停顿 | ms | 是 | 窄 |
| 提示 | 发音提示图标/备注图标 | 是 | 窄 |

**性能要求**：5000 行下滚动 ≥ 30 fps（虚拟滚动 + 行内文本纯文本渲染，聚焦时才挂载编辑器）。

**置信度色带**：≥0.85 绿、0.62~0.85 黄、<0.62 红、人工确认 蓝。这是用户「一眼看出哪里要改」的关键视觉设计。

### 4.3 剧本视图（`CanvasScriptView.vue`）

- 连续阅读：旁白（灰色斜体/正常体）、台词（按角色配色，角色名前缀）、内心（虚线下划线）。
- 情绪与停顿以**行内小标签**呈现（不打断阅读）。
- 适合「通读找错」；表格适合「批量改」。
- 两视图共享同一份数据与选中行（切换视图保持位置）。

### 4.4 单行编辑抽屉（`LineEditorDrawer.vue`）

包含全部字段，尤其：
- **候选列表**：Top-3 角色及其分数，点击即改（比下拉找角色快得多）。
- **原文片段**：显示 `sourceText` 与上下文（前后各 2 行原始文本）。
- **试听**：若已录音，直接播放（不需要跳到录音页）。
- **强制标记**：`decidedBy='human'`（改过就自动设置）。
- **备注**：给配音员看。

### 4.5 待确认队列（`ReviewQueue.vue`）—— 效率关键

这是画本校对的**主工作台**，设计目标是「3 分钟清 100 行」：

```
┌────────────────────────────────────────────────────────┐
│ 待确认 37 行（第 12/37）      [一键确认高置信] [跳过]     │
├────────────────────────────────────────────────────────┤
│ 上下文：                                               │
│   11 (旁白) 他缓缓抬起头，眼中闪过一丝狠厉。             │
│   12 (?)    那我便试试。                      ← 当前行   │
│   13 (旁白) 药老叹了口气。                             │
├────────────────────────────────────────────────────────┤
│ 归属：  [1 萧炎 0.58] [2 药老 0.54] [3 旁白]  [4 其它▾] │
│        按 1/2/3 直接选择，Enter 确认并下一行，S 跳过     │
└────────────────────────────────────────────────────────┘
```

- **全键盘操作**：数字键选候选、`Enter` 下一行、`S` 跳过、`P` 播放、`Z` 撤销。
- 批量：`Ctrl+Enter` 把「当前角色」应用到下面 N 行（连续对白的常见场景）。
- 队列来源：`needsReview=1`（低置信）+ 质检标记 + 未分配。

### 4.6 角色表（`CharacterPanel.vue`）

| 功能 | 说明 |
|------|------|
| 增删改 | 名称、别名（多标签）、性别、年龄段、性格描述、备注、头像（可选） |
| 别名管理 | `萧炎` / `炎帝` / `小炎子` / `三少爷` —— 别名参与判定（拼进原型文本）与文本高亮 |
| 自动抽取 | 从文本提取候选角色名（引导语前主语、高频称谓、jieba 词性 nr），一键添加 |
| 合并 | 选择多个角色 → 合并为一个，迁移台词与别名，展示「将影响 N 行」预览 |
| 归档 | 不物理删除（保留引用），只标记 archived，UI 隐藏但可恢复 |
| 配音员绑定 | 角色 → 配音员（主/备）；一个配音员可多角色 |
| 默认表演参数 | 默认语速、默认情绪、默认音量偏移、默认停顿（画本行未指定时继承） |
| 出场统计 | 行数、字数、预估时长、在哪些章出现 |

### 4.7 批量操作（`BatchActionBar.vue`）

筛选后（例如「说话人=unknown 且 kind=dialogue」）可执行：
- 批量指派说话人（含「按候选第一位自动指派」）
- 批量设置情绪/语速/停顿
- 批量移除标记、批量加标记
- 批量合并相邻旁白行（保持语义：合并后文本用句号连接）
- 批量设置 `decidedBy='human'`（锁定，防重算覆盖）
- 批量删除（软删除）/ 恢复

### 4.8 撤销/重做（`useUndoStack.ts`）

- 命令模式，每个变更是一个命令对象（`UpdateLine`、`AssignSpeaker`、`MergeCharacters`、`BatchUpdate`）。
- 栈深 ≥ 100；`Ctrl+Z` / `Ctrl+Shift+Z`。
- 落库策略：**编辑立即进内存 + 进撤销栈，防抖 500 ms 后批量写库**；`Ctrl+S` 与切换章节时强制落库。
- 撤销一个「批量操作」= 一次性撤销整批（不是逐行）。

### 4.9 自动保存与冲突

| 项 | 策略 |
|----|------|
| 文本编辑 | 防抖 500 ms 写库（乐观 UI） |
| 标记编辑 | 立即写库（都是下拉/按钮，频率低） |
| 批量操作 | 一个事务写库 |
| 失败处理 | 写库失败 → 顶部红条「保存失败，你的修改仍在内存中」+ 重试按钮（**不能让用户以为存上了**） |
| 冲突 | 单机单窗口不会冲突；若同项目被第二个窗口打开（任务包导入场景），用 `updated_at` 乐观锁 + 提示重新加载 |

## 5. 画本质检（FR-2.4.8）

```ts
type IssueKind =
  | 'empty_text'            // 空文本
  | 'too_long'              // 超过 maxLineChars
  | 'unassigned'            // kind=dialogue 但说话人为空/unknown
  | 'quote_unmatched'       // 引号不配对
  | 'no_character_ref'      // 角色表存在但从未被引用
  | 'narration_run'         // 连续 N 行旁白（默认 15），可能漏判了对白
  | 'dialogue_run'          // 连续 N 行同一角色对白（默认 20），可能是旁白被误判
  | 'no_pause'              // 相邻同角色行 pauseAfterMs=0（会粘连）
  | 'suspicious_speaker'    // 置信度 < 0.5 且 decidedBy != human
  | 'missing_pronunciation' // 命中多音字表但未给发音提示
  | 'recorded_missing'      // 已标记 recorded 但片段文件缺失
  | 'duplicate_text'        // 相邻两行文本完全相同
```

**交互**：质检面板列出问题并按类型分组，点击跳转到对应行；提供「一键修复」的仅限安全项（如 `no_pause` 补默认停顿、`missing_pronunciation` 用字典建议）。

**多音字表**（内置，可扩展）：`行(háng/xíng)`、`重(zhòng/chóng)`、`还(hái/huán)`、`长(cháng/zhǎng)`、`乐(lè/yuè)`、`地(dì/de)`、`了(le/liǎo)`、`差(chà/chā/chāi)`、`藏(cáng/zàng)`、`率(lǜ/shuài)`、`血(xuè/xiě)`、`薄(báo/bó/bò)`、`露(lù/lòu)`、`处(chǔ/chù)`。检测策略：命中表 + 上下文中无消歧线索 → 提示；**不做自动替换**（会错得更离谱），只标记让人判断。

## 6. 协作：配音员与任务包（FR-7）

### 6.1 配音员管理

```ts
interface VoiceActor {
  id: string; projectId: string
  name: string
  contact: string | null            // 可选，明文（用户自己填）
  note: string | null               // 录音环境、设备、习惯
  voiceProfile: {
    samplePath: string | null       // 参考样本
    gender: 'male' | 'female' | 'other' | 'unknown'
    pitchRange: [number, number] | null   // Hz（可选，手工或从样本估计）
    speechRate: number | null       // 字/秒（从样本估计）
  } | null
  createdAt: number
}
```
- 一个配音员可担任多个角色；一个角色可有主配音员 + 备选。
- **分工视图**：按配音员汇总行数/字数/预估时长，用于均衡分配（避免某人 5000 字、某人 200 字）。

### 6.2 任务包导出 `.nst`（FR-7.3）

格式定义见 `03-数据模型与存储.md` §9。导出流程：

```
1. 选择目标配音员（或按角色选择）
2. 预览清单：行数、字数、预估时长、涉及章节
3. 选项：
   - [x] 包含上下文（前后各 1 行，帮助入戏）
   - [x] 包含参考音（对手戏片段，若有录音；会显著增大包体积）
   - [x] 包含发音提示与备注
   - [x] 允许该配音员看到其它角色的词（默认关，只看自己的更专注）
   - 录音建议：采样率/位深/推荐增益/文件名模板
4. 生成 .nst（zip）
5. 记录导出记录（packageId + linesHash + 时间），供回收时比对
```

**`linesHash`** 的计算：对「全部行的 `id + text + speaker + 情绪 + 停顿`」做稳定序列化后哈希。画本改动后回收能立刻发现不一致。

### 6.3 配音员侧（导入 `.nst` 后）

- 进入「任务模式」界面：只显示分配给自己的行，按章节分组。
- 只读画本（不能改文本、不能改说话人）——防误操作。**但允许**：标记「这行文本有问题」（回传给导演）。
- 使用角色模式录音（`12` §3.3），逐行或连续。
- 可离线工作，随时保存。
- 导出「录毕包」：打包 takes + `takes.json` + 原始 `task.json`（含 `linesHash`）。

### 6.4 回收合并（FR-7.5）

```
merge.taskPackage(projectId, path)
├─ 1. 读包校验：格式版本、checksums
├─ 2. 比对 linesHash
│     ├─ 一致 → 直接归位
│     └─ 不一致 → 计算差异（新增/删除/修改的行），生成差异报告；
│                 仍按 lineId 归位，无法归位的进「待处理」
├─ 3. 逐行归位：
│     ├─ lineId 存在于本项目 → 音频复制到 takes/ 并入库 take
│     ├─ lineId 不存在 → 记入 unknownLines（不入库）
│     └─ 音频损坏 → 跳过并记录
├─ 4. 冲突处理：
│     ├─ 同 line 已有 take → 新 take 追加（不覆盖），进 A/B 队列
│     └─ 同 line 同一 takeId 重复回传 → 按 mtime 或内容哈希去重
└─ 5. 生成回收报告（谁、多少行、多少被采纳、缺漏、未知、损坏）
```

**回收报告必须落到 UI 上**，并允许「一键把新 take 设为成品」（当该行原本没有录音时）。

### 6.5 画本变更后重发任务包

若 `linesHash` 不一致，UI 提供「重新导出任务包（仅含变更行）」——这是「增量下发」，避免配音员重录全部。

## 8. 异常与边界

| 场景 | 处理 |
|------|------|
| 生成时 embedding 模型缺失 | 规则判定 + 明确提示（`embeddingUsed=false`） |
| 生成时章节已被人工编辑过 | 先弹窗：「本章已有 N 行人工修改，重算会保留人工结果，其余覆盖。继续？」 |
| 角色表为空 | 自动跑抽取生成候选，提示用户确认后再判定 |
| 章节超长（> 5000 行） | 分批处理 + 进度；UI 分页加载 |
| 合并角色时有同名别名冲突 | 展示冲突列表，让用户决定保留哪个 |
| 删除角色时仍有引用 | 转为归档；提示「该角色在 N 行中被引用，已归档」 |
| 重算时正在录音 | 允许（重算不碰音频），但会更新 `needsReview`，UI 上要提示 |
| 任务包的 `linesHash` 与本地完全不同 | 报告「画本已大幅变更」并列出差异，让用户决定是否继续归位 |

## 9. 测试要点

| 测试 | 用例 |
|------|------|
| 切句 | 长句二次切、引号内不切、嵌套引号、破折号对白、省略号 |
| 判定准确率 | 回归集上 ≥ 85%（人工基准），并输出混淆矩阵 |
| 阈值敏感度 | 扫描 0.50~0.80 的准确率/覆盖率曲线 |
| 增量更新 | 改一行说话人 → 验证 centroid 正确更新且不漂移 |
| 人工保护 | 改过的行在重算后 `decidedBy` 仍为 human、内容不变 |
| 撤销 | 批量操作撤销后完全还原（含 centroid 变化） |
| 角色合并 | 合并后无孤立引用、别名迁移正确、统计数字一致 |
| 亿级文本 | 单章 5000 行：生成耗时、UI 帧率、内存峰值 |
| 任务包往返 | 导出 → 导入 → 回传 → 合并，验证 lineId 归位 100% 正确 |
| 增量下发 | 改 3 行后重新导出，验证只含这 3 行 |
| 崩溃安全 | 生成过程中杀进程，重启后无半成品章节（事务保证） |
