## 1. 数据库模块（`infra/db`）

### 1.1 连接与 PRAGMA

```ts
const db = new Database(dbPath)          // better-sqlite3，主进程单例
db.pragma('journal_mode = WAL')          // 读写并发；崩溃安全性好
db.pragma('synchronous = NORMAL')        // WAL 下的性能/安全平衡点
db.pragma('foreign_keys = ON')           // 必须显式开启
db.pragma('busy_timeout = 5000')         // 5s 后报可重试错误，而不是抛 SQLITE_BUSY
db.pragma('temp_store = MEMORY')
db.pragma('cache_size = -64000')         // 约 64 MB 页缓存
db.pragma('mmap_size = 268435456')       // 256 MB 内存映射（大库查询提速）
```

**为什么是同步 API**：主进程是单线程事件循环，`better-sqlite3` 的同步调用在**短事务**下比异步驱动更快且无竞态。代价是**绝不能执行长事务或全表扫描**——这会冻结整个主进程（含 IPC 响应）。因此有两条铁律：

> **铁律 1**：任何可能超过 50 ms 的查询必须先 `EXPLAIN QUERY PLAN` 验证走索引。
> **铁律 2**：批量写（如导入 10 万行画本）必须分批（每批 2000 行）+ 事务提交 + `setImmediate` 让出事件循环。

### 1.2 事务包装

```ts
// infra/db/tx.ts
export function tx<T>(fn: () => T): T {
  return db.transaction(fn)()          // better-sqlite3 自动 BEGIN/COMMIT/ROLLBACK
}
// 嵌套调用安全（内部用 savepoint）
export const txImmediate = db.transaction // 写事务用 IMMEDIATE 减少锁升级失败
```

批量插入使用 prepared statement + 事务：
```ts
const ins = db.prepare('INSERT INTO canvas_lines (...) VALUES (?, ?, ...)')
tx(() => { for (const row of batch) ins.run(...row) })
```

### 1.3 迁移

见 `03-数据模型与存储.md` §7。要点：版本化、单事务、发布后只增不改、跨版本先备份、失败进只读模式。

### 1.4 Repository 层约定

```ts
// features/book/repositories/canvas.repo.ts
export interface CanvasRepo {
  listByChapter(chapterId: string, opts?: { limit?: number; offset?: number }): CanvasLine[]
  countByChapter(chapterId: string): number
  getById(id: string): CanvasLine | null
  updateLine(id: string, patch: Partial<CanvasLine>, expectedRev?: number): CanvasLine
  bulkInsert(lines: NewCanvasLine[]): void
}
```

| 约定 | 说明 |
|------|------|
| 只暴露领域类型，不暴露 `Statement`/`Row` | 上层不感知 SQL |
| 全部参数化查询 | 禁止字符串拼接（防注入 + 让 SQLite 复用查询计划） |
| 行 → 领域对象的映射集中在一处（`mappers.ts`） | 避免各调用点自己解析 JSON 字段 |
| `UPDATE` 带 `rev` 乐观锁（可选） | 防连点覆盖；冲突抛 `CONFLICT` |
| 禁止跨域 join | `book` 域不查 `audio` 域的表；需要组合时由 service 层编排 |

## 2. 任务队列（`infra/queue`）

### 2.1 为什么必须要队列

以下操作全部是秒级到小时级，且可能并发触发（用户连点、批量导入后续处理、导出全书）：

| 任务类型 | 典型耗时 |
|----------|----------|
| `book.import` | 数秒 ~ 数分钟 |
| `canvas.generate` | 数秒（规则）/ 数十秒（含 embedding） |
| `embedding.batch` | 分钟级（CPU） |
| `asr.transcribe` | 实时率的 0.3~1× |
| `audio.process` | 每秒音频约 0.05~0.3 s |
| `audio.render` | 与音频时长同量级 |
| `export.book` | 分钟 ~ 小时 |
| `package.export/import` | 分钟级 |

### 2.2 设计

```ts
type TaskKind = 'book.import' | 'canvas.generate' | 'embedding.batch' | 'asr.transcribe'
              | 'audio.process' | 'audio.render' | 'export.chapter' | 'export.book'
              | 'package.export' | 'package.import' | 'db.backup' | 'cache.clean'

interface TaskRecord {
  id: string
  kind: TaskKind
  status: 'queued' | 'waiting' | 'running' | 'succeeded' | 'failed' | 'cancelled' | 'interrupted'
  priority: number                 // 越小越先；用户交互触发 = 0，后台维护 = 100
  projectId: string | null
  payload: string                  // JSON
  progress: number                 // 0..1
  stage: string | null             // 人类可读阶段名："正在解析第 42/120 章"
  result: string | null            // JSON
  error: string | null             // JSON { code, message, details }
  attempts: number
  maxAttempts: number
  concurrencyKey: string | null    // 同 key 互斥（如 'ffmpeg'、'whisper'、'db-write'）
  createdAt: number
  startedAt: number | null
  finishedAt: number | null
}
```

**核心机制**

| 机制 | 实现 |
|------|------|
| 并发控制 | 每个 `concurrencyKey` 有独立上限：`ffmpeg: min(4, cores-1)`、`whisper: 1`、`embedding: 1`（避免 OOM）、`db-write: 1` |
| 优先级 | 用户直接触发的任务优先于自动后台任务（如原型向量增量更新） |
| 进度 | 任务实现者调用 `ctx.report(progress, stage)`；节流到 ≤ 10 次/秒再推给渲染进程 |
| 取消 | `AbortController` 贯穿：`ctx.signal`。任务必须在关键点检查 `signal.aborted` 并清理临时文件 |
| 重试 | 仅对 `retryable` 错误自动重试（默认 1 次，指数退避 1s/4s）；ffmpeg 编码失败不重试 |
| 持久化 | 任务写库，启动时把 `running`/`waiting` 标记为 `interrupted`，UI 询问「重试 / 丢弃」 |
| 幂等 | 任务带 `dedupeKey`（如 `audio.process:{segmentId}:{presetHash}`），重复提交直接返回已有任务 |

### 2.3 任务实现模板

```ts
export const importBookTask: TaskSpec<ImportPayload, ImportResult> = {
  kind: 'book.import',
  concurrencyKey: 'db-write',
  maxAttempts: 1,
  async run(ctx, payload) {
    ctx.report(0.0, '读取文件')
    const raw = await readFile(payload.path)                 // 不阻塞：用 fs/promises
    ctx.throwIfAborted()

    ctx.report(0.1, '嗅探编码')
    const { text, encoding } = detectAndDecode(raw)
    ctx.throwIfAborted()

    ctx.report(0.2, '清洗文本')
    const cleaned = cleanText(text)

    ctx.report(0.3, '分章')
    const chapters = splitChapters(cleaned, payload.ruleSet)

    ctx.report(0.4, `写入 ${chapters.length} 章`)
    for (let i = 0; i < chapters.length; i += 200) {         // 分批，别冻死主进程
      tx(() => insertBatch(chapters.slice(i, i + 200)))
      ctx.report(0.4 + 0.55 * (i / chapters.length), `写入第 ${i}/${chapters.length} 章`)
      await yieldToLoop()                                     // setImmediate
      ctx.throwIfAborted()
    }
    ctx.report(1, '完成')
    return { bookId, chapterCount: chapters.length, encoding }
  },
  onCancel(ctx) { cleanupTemp(ctx.tempDir) }
}
```

### 2.4 进度上报通道

```
任务实现 → ctx.report() → 队列（节流）→ webContents.send('task.progress', {
  taskId, kind, progress, stage, etaMs, throughput
})
```
渲染进程统一用 `useTaskProgress(taskId)` 订阅，UI 用同一个 `<TaskProgressCard>` 组件渲染。**禁止**每个功能自建一套进度 UI 与轮询。

`etaMs` 估算：有历史同类任务时用「已完成量 / 已耗时 × 剩余量」；否则给 `null`（UI 显示「计算中」，不要瞎猜）。

## 3. 文件系统模块（`infra/fs`）

| 能力 | 接口 | 要点 |
|------|------|------|
| 路径解析 | `resolveProjectPath(projectId, relPath)` | **强制校验**结果落在项目目录内（防 `..` 逃逸） |
| 资源路径 | `resolveResourcePath('models/...')` | 开发/打包两种根自动切换 |
| 原子写 | `atomicWriteFile(path, data)` | 写 `.tmp` → `fsync` → `rename`（同盘 rename 才原子） |
| 流式追加写 | `openAppendWriter(path)` | 录音专用，见 `05-音频管线.md` §2 |
| 哈希 | `sha256File(path)` / `sha256Buffer(buf)` | 导入去重、缓存键、包校验 |
| 临时目录 | `withTempDir(projectId, prefix, fn)` | 保证异常时也清理；启动时清残留 |
| 磁盘空间 | `checkFreeSpace(dir, needBytes)` | 录音前与导出前检查 |
| 安全删除 | `safeRemove(path)` | 拒绝删除项目根、模型目录、数据库 |

**启动清理规则**（严格顺序，见 `01` §10）
1. 先跑**崩溃恢复**（修复 `.tmp/*.wav` 并入库），这些文件**不能**被当垃圾删。
2. 再清理「超过 24 小时且不在恢复清单内」的 `.tmp` 内容。
3. 再清理缓存（按 TTL）。

## 4. 缓存模块（`infra/cache`）

| 缓存 | 键 | 值 | 位置 | 失效条件 |
|------|----|----|------|----------|
| Embedding | `sha256(modelId + text + contextScope)` | Float32 向量 | SQLite（`line_embeddings`） | 模型变、文本变 |
| 波形峰值 | `sha256(filePath + fileSize + mtime + peakPerSec)` | Int16 min/max 对数组 | `projects/{id}/cache/peaks/*.bin` | 源文件 mtime/size 变 |
| ASR 结果 | `sha256(audioFile)` | whisper JSON | `cache/asr/*.json` | 文件变 |
| 转码中间 | `sha256(filePath + filterGraph)` | 音频文件 | `cache/tmp/` | TTL 3 天 |
| 质量测量 | `sha256(filePath + fileSize)` | LUFS/峰值/时长 | SQLite（`audio_metrics`） | 文件变 |

**波形峰值格式**（对轨与录音台共用）
```
文件头（32 字节）: magic='NSPK' | version u16 | reserved u16 | peakPerSec u32 | sampleCount u64 | channels u16 | reserved
数据体: 每 (1/peakPerSec) 秒，每声道 2 个 int16（min, max）
```
默认 `peakPerSec = 100`（每 10 ms 一对）；15 分钟音频 ≈ 90000 对 × 4 字节 ≈ 350 KB，一次读取即可绘制。

## 5. 日志模块（`infra/log`）

### 5.1 分级与输出

| 级别 | 用途 | 生产默认 |
|------|------|----------|
| `error` | 操作失败、异常 | 记录 + 上报 UI toast（去重） |
| `warn` | 降级、可恢复异常、参数异常 | 记录 |
| `info` | 关键业务动作（导入完成、导出完成、录音开始/结束） | 记录 |
| `debug` | 流程细节、IPC 参数 | 关闭 |
| `trace` | 逐帧/逐样本（仅音频排查用） | 关闭 |

输出：文件（`logs/YYYY-MM-DD.log`，保留 14 天）+ 控制台（开发）+ 渲染进程可订阅的日志流（打开「诊断面板」时）。

### 5.2 脱敏规则（必须）

| 内容 | 处理 |
|------|------|
| API Key / Token | 永不记录；`sk-***` 掩码 |
| 作品正文 | 默认不记录；debug 模式下仅记录前 20 字 + 长度 |
| 文件绝对路径 | 记录为 `{userData}/...` 相对形式（保护用户名） |
| HTTP 请求/响应体 | 只记录长度、状态码、耗时；不记 body |
| 系统用户名 | 掩码 |

### 5.3 结构化记录

```ts
log.info('canvas.generate.done', {
  projectId, chapterId, lines: 482, lowConfidence: 37, elapsedMs: 8421, model: 'bge-small-zh-v1.5'
})
```
统一事件命名 `域.动作.结果`，便于后续统计与排查。

### 5.4 崩溃捕获

- 主进程：`process.on('uncaughtException' | 'unhandledRejection')` → 记录堆栈 + 尝试优雅收尾（保存录音）→ 若不可恢复则 `app.exit(1)`。
- 渲染进程：`window.onerror` / `unhandledrejection` → 经 IPC 送到主进程日志。
- Electron：`crashReporter.start()`（本地存储，不上传；上传需用户显式开启）。
- **诊断包**（FR-8.6）：zip 含版本信息、脱敏配置、最近 3 天日志、崩溃转储清单、任务历史。一键导出，方便用户报障。

## 6. 并发与资源保护

| 资源 | 限制 | 理由 |
|------|------|------|
| ffmpeg 进程数 | `min(4, cores - 1)` | 编码很吃 CPU，占满会让 UI 卡 |
| whisper 实例 | 1（串行） | 模型常驻内存数百 MB |
| ONNX embedding | 1 个会话，batch 自适应（默认 16） | 避免 OOM；批量过大批反而慢 |
| SQLite 写 | 1（串行） | 同步 API，避免锁竞争 |
| 同时进行的录音会话 | 1 | 多路录音会互相干扰设备 |
| 同时导出任务 | 1 个 `export.book`（可叠加多个 `export.chapter`） | 磁盘 I/O 争抢 |
| 网络请求（Provider） | 默认 2 并发，超时 60 s | 防限流与雪崩 |

**背压**：录音写入路径使用有界队列（容量约 2 秒音频）。若队列将满：
1. 优先扩大队列（最多到 10 秒）
2. 仍满 → 立刻停止录音、定稿文件、**明确告知用户「因磁盘写入跟不上已停止录音，已保存 X 秒素材」**，绝不静默丢帧。

## 7. 崩溃恢复（`bootstrap/recovery.ts`）

启动时按序执行：

```
1. 扫描 projects/*/recordings/*.wav.tmp 与 *.pcm.part
2. 对每个文件：
   a. 读取伴生元数据 {sessionId}.meta.json（设备/采样率/位深/声道/写入样本数）
   b. 校验数据体长度是否与样本数一致（截断到完整帧边界）
   c. 生成合法 WAV 头（RIFF/WAVE/fmt/data，data size = 样本数 × 帧字节）
   d. 原子改名为 {sessionId}.wav
   e. 写入 recording_sessions（status='recovered'）
3. 把 tasks 中 status ∈ {running, waiting} 的记录标为 interrupted
4. 清理不在恢复清单内的过期临时文件
5. 若发生恢复，向 UI 推送「已恢复 N 段录音（共 X 分钟），可继续录制」
```

**伴生元数据**（录音开始时立即写入，之后每 5 秒与结束前更新）
```jsonc
{
  "sessionId": "uuid", "projectId": "uuid", "chapterId": "uuid",
  "sampleRate": 48000, "bitDepth": 24, "channels": 1,
  "mode": "line_by_line", "startedAt": 1770000000000,
  "framesWritten": 8640000, "peakDb": -3.2, "gainDb": 0,
  "device": { "label": "USB Condenser", "deviceId": "..." }
}
```
**这是录音安全的核心**：没有它，崩溃后的裸 PCM 无法可靠还原为音频。

## 9. 安全存储（`infra/secure`）

```ts
import { safeStorage } from 'electron'

export function encryptSecret(plain: string): string {
  if (!safeStorage.isEncryptionAvailable()) throw new AppError('SECURE_UNAVAILABLE')
  return safeStorage.encryptString(plain).toString('base64')
}
export function decryptSecret(cipher: string): string {
  return safeStorage.decryptString(Buffer.from(cipher, 'base64'))
}
```

| 情况 | 行为 |
|------|------|
| 系统不支持加密（部分 Linux） | 拒绝保存 Key，提示「当前系统不支持安全存储，请使用本地模型或 Mock Provider」 |
| 换机器/换了系统用户 | 解密失败 → 清除并提示重新输入（不要崩溃） |
| Key 泄露风险 | 日志脱敏 + 诊断包不含 Key（见 §5.2） |

## 10. 网络与 Provider 调用（`infra/http`）

| 项 | 策略 |
|----|------|
| 客户端 | `undici`（`request` + `Agent`） |
| 超时 | 连接 10 s、首字节 60 s（流式则空闲 30 s） |
| 重试 | 仅网络类错误与 429/5xx；指数退避 1s→4s；最多 2 次 |
| 代理 | 读取系统代理设置，允许设置页手动指定 |
| 并发 | `p-limit(settings.ai.maxConcurrency)` 默认 2 |
| 熔断 | 连续 5 次失败 → 暂停该 Provider 5 分钟，期间自动降级 |
| 外发确认 | 首次向云端发送作品文本时弹窗确认（含目标域名与字数）；`allowSendTextToCloud=false` 时直接拒绝 |
| 抓取（URL 导入） | 同客户端；额外做 SSRF 防护（拒绝内网/环回/链路本地地址）、限制重定向次数（≤5）、限制单页大小（≤5 MB）、限制总页数 |

## 11. 可观测性（本地）

性能埋点统一入口：
```ts
measure('canvas.generate', { chapterId }, async () => { ... })
```
