# 15 · 功能域：混音与导出

> 需求：FR-6（`00-需求规格.md`）
> 代码：`main/features/audio/mixer.ts` · `exporter.ts` · `renderer/src/features/mixing/`
> 算法细节：`05-音频管线.md` §7（混音）、§8（响度）、§9（导出）、§10（质检）

---

## 1. 定位

> **混音 = 把对轨后的多轨素材合成为一个文件。**
> **导出 = 把合成结果变成「用户能分发的成品」，并保证响度、元数据、章节信息正确。**

这是整条链的最后一公里，也是**用户唯一会拿给听众看的东西**。因此这里的容错要求最高：宁可慢，也不能出一个响度不对、章节乱掉的成品。

---

## 2. 混音模型

```ts
interface MixProject {                  // 每章一份混音配置
  id: string
  chapterId: string
  arrangementId: string                 // 引用对轨方案
  tracks: MixTrack[]
  master: {
    targetLufs: -16 | -14 | -23 | number
    truePeakDb: number                  // 默认 -1
    lra: number                         // 默认 11
    limiterEnabled: boolean
    sampleRate: 48000 | 44100
    channels: 1 | 2
  }
  headSilenceMs: number                 // 默认 500
  tailSilenceMs: number                 // 默认 1500
  titleReading: {                       // 章首标题念白（1.0 为占位）
    enabled: boolean
    lineId: string | null               // 若有人工录制的标题，绑定该画本行
    ttsText: string | null              // 3.0：TTS 生成
    tailPauseMs: number
  }
}

interface MixTrack {
  id: string
  kind: 'voice' | 'music' | 'sfx'
  refId: string                         // 角色 ID / 素材 ID
  name: string
  gainDb: number
  pan: number                           // -1..1
  mute: boolean
  solo: boolean
  presetId: string | null               // 轨道级处理链（引用 14 的预设）
  order: number
  music?: {
    filePath: string
    startMs: number
    endMs: number | null
    loop: boolean
    fadeInMs: number
    fadeOutMs: number
    ducking: { enabled: boolean; amountDb: number; thresholdDb: number; attackMs: number; releaseMs: number }
  }
}
```

**多方案**：`MixProject` 可以有多份（干声版/带 BGM 版/广播版），导出时选择。混音方案与对轨方案是两层（对轨管「位置」，混音管「音量与效果」），**不要合并**。

## 3. 渲染管线（主进程）

```
render.chapter 任务
├─ 1. 前置校验（QC 预检，见 §6.1）→ 不通过则返回清单让用户确认
├─ 2. 解析素材路径（processed > segment > take，见 03 §6）
├─ 3. 构建人声轨（每轨一个滤镜图，分批 amix）
│     for track in voiceTracks:
│         items = arrangementItems(track).sortBy(timelineStartMs)
│         batches = chunk(items, 32)
│         for batch in batches: 生成 adelay+afade+apad → amix(normalize=0)
│         trackAudio = 递归合并所有 batch
│         应用 track.presetId 的处理链（若有）与 gainDb/pan
├─ 4. 构建音乐/音效轨（含 loop / fade / apad+atrim）
├─ 5. 总线合成
│     voiceBus = amix(voice tracks)  ← 同时 asplit 出 sidechain 源
│     musicBus = amix(music tracks with ducking applied)
│     sfxBus   = amix(sfx tracks)
│     mixed    = amix([voiceBus, musicBus, sfxBus], normalize=0)
├─ 6. 补头尾静音（adelay 前置 + apad 尾部）
├─ 7. 响度（两遍法，见 05 §8）：measure → gain → alimiter
├─ 8. 输出中间 WAV（cache/tmp/{taskId}/chapter-{id}.wav）
└─ 9. 记录渲染结果（时长、峰值、LUFS 初测）
```

### 3.1 关键实现细节（每条都有踩坑史）

| 细节 | 说明 |
|------|------|
| `amix=normalize=0` | 不加会让音量大跌（默认按 1/N 衰减） |
| `apad=whole_dur={chapterDur}` | 不加会导致 `amix` 以最短输入结束（**混音只出前几秒的头号原因**） |
| `adelay={ms}\|{ms}` | 单声道也要写两个值（版本差异） |
| 分批 32 | 滤镜图过大会导致命令行超长、内存爆、启动慢 |
| 输出到同盘临时目录 | 跨盘移动极慢；临时文件与最终输出在同一盘 |
| `-threads` | 限制线程数（默认留给系统 2 个核，避免 UI 卡） |
| 中间格式统一 | 全部 `s32le @ 48k` 后再混，避免格式不一致导致 `amix` 失败 |
| 无声音输入的轨 | 若某轨没有任何 item，**不要**把它加进 `amix`（空输入会让整个图失败） |
| Solo 与侧链 | Solo 时其他轨静音，但**侧链源必须始终有效**（否则 ducking 失效） |

### 3.2 时长计算（必须与对轨一致）

```
chapterDurationMs = max over tracks (lastItem.timelineStartMs + itemDuration) + tailSilenceMs
```
- 与 `13` 的计算必须用**同一个函数**（`shared/lib/arrangement-duration.ts`），否则会出现「时间线显示 12:30，渲染出来 12:28」的不一致。
- 渲染完成后用实际文件时长校验，偏差 > 1 s → 打警告。

## 4. 响度标准化（FR-6.3）

见 `05` §8。要点复述（因为这是最影响成品质量的一步）：

```
Pass 1: ffmpeg -i mixed.wav -af loudnorm=I=-16:TP=-1:LRA=11:print_format=json -f null -
        → 解析 input_i / input_tp / input_lra
Pass 2: gainDb = target_I - input_i
        ffmpeg -i mixed.wav -af volume={gainDb}dB,alimiter=limit=0.891:attack=5:release=80 out.wav
Pass 3: 重新测量验证（偏差 > 0.5 LU 则微调一次）
```

| 决策 | 理由 |
|------|------|
| 用线性 `volume` 而非 `loudnorm` 第二遍 | `loudnorm` 两遍模式是动态归一化，会压动态、逐章不齐；有声书要线性 |
| 逐章独立归一 | 保证章间响度一致（有声书标准做法） |
| 真峰靠 `alimiter` + 测量验证 | 以第三方测量为准，不信「应该没问题」 |
| 短章特殊处理 | 章节 < 60 s 时 `input_i` 不稳 → 用相邻章的平均增益校正，并提示用户 |

**降级**：若 `loudnorm` 滤镜不可用（罕见构建），降级为 `ebur128` + 手算增益（`ebur128` 带 `metadata` 输出）。

## 5. 导出（FR-6.5 ~ FR-6.8）

### 5.1 分章导出

| 格式 | 命令要点 |
|------|----------|
| MP3 | `-c:a libmp3lame -b:a 192k -ar 44100 -write_xing 1 -id3v2_version 3` + 元数据 + 封面（`attached_pic`） |
| WAV | `-c:a pcm_s24le`（源同格式则 `-c copy`） |
| M4A | `-c:a aac -b:a 192k -movflags +faststart` |

**元数据模板**
```jsonc
{
  "title": "{chapterTitle}",          // 第1章 陨落的天才
  "artist": "{author}",               // 作者
  "album": "{bookTitle}",             // 书名
  "album_artist": "{narrator}",       // 朗读/旁白配音员
  "track": "{chapterIndex}/{total}",  // 1/120
  "genre": "Audiobook",
  "comment": "由 Novel Studio 制作",
  "date": "{year}"
}
```

### 5.2 整本合并 M4B（FR-6.6）

```
1. 生成 chapters.txt（FMMETADATA1 格式）
   └─ START/END 用累积整数毫秒，且严格连续（上一章 END = 下一章 START）
2. 生成 list.txt（concat demuxer）
   └─ 路径用正斜杠；单引号需转义
3. ffmpeg -f concat -safe 0 -i list.txt -i chapters.txt \
     -map_metadata 1 -map_chapters 1 \
     -c:a aac -b:a 96k -ar 44100 -ac 1 \
     -movflags +faststart out.m4b
4. 校验：用 ffprobe 读章节数、总时长、容器格式
```

**必须注意**
| 项 | 说明 |
|----|------|
| `-map_chapters 1` | 不加则章节信息丢失（最常见的「M4B 没章节」原因） |
| `TIMEBASE=1/1000` + 整数毫秒 | 浮点会导致章节错位 |
| 章节连续无缝 | 有缝隙时部分播放器跳转会出错 |
| 章数上限 | > 200 章建议按卷拆分为多个 M4B（UI 主动提示） |
| 总时长上限 | ≤ 24 h（超长文件 seek 索引庞大） |
| 容器 | `.m4b` 与 `.m4a` 同容器；用 `.m4b` 让播放器识别为有声书 |
| AAC 编码器 | `aac` 原生（免费）；`libfdk_aac` 质量更好但有许可问题 → 默认 `aac` |

### 5.3 命名与目录

```
{exportDir}/{bookTitle}/
├── 001_第1章 陨落的天才.mp3
├── 002_第2章 斗之气.mp3
├── ...
├── 斗破苍穹.m4b
└── export-report.json
```
- 文件名清洗：去掉 `\ / : * ? " < > |` 与控制字符；UTF-8 字节数截断到 120；冲突自动加 `_2`。
- 模板占位符：`{bookTitle}` `{author}` `{chapterIndex}` `{chapterIndex:03}` `{chapterTitle}` `{narrator}` `{date}`

### 5.4 导出任务与断点（FR-6.11）

```
export.book 任务
├─ 逐章：
│   paramsHash = hash(混音方案 + 对轨方案版本 + 处理预设 + 响度参数 + 导出参数)
│   若 export_jobs 中同章同 paramsHash 已 succeeded 且文件存在 → skip（断点续传）
│   否则：render → loudness → encode → 记录 job
├─ 全部完成 → 合并 M4B（若有章节失败且用户选择「仍然合并」则跳过失败章并报告）
└─ 生成导出报告
```
**断点价值**：120 章整本导出可能跑 1 小时。用户中途取消/断电后重跑，**已完成的章不重渲**。

### 5.5 导出向导 UI

```
Step 1  范围：当前章 / 选定章 / 全书
Step 2  输出：格式（MP3/WAV/M4A/M4B）、码率、采样率、输出目录
Step 3  混音方案：选择 MixProject（干声版/带 BGM 版）
Step 4  响度：目标 LUFS / 真峰 / 头尾静音
Step 5  元数据与封面
Step 6  预检报告（QC，见 §6）
Step 7  执行（进度：当前章 N/M、剩余时间估算、实时速率）
Step 8  完成后报告（每章实测响度、峰值、警告；打开输出目录按钮）
```

## 6. 质检（FR-6.8 / FR-6.9）

### 6.1 渲染前预检（快速，数据来自库）

| 检查 | 严重度 | 处理 |
|------|--------|------|
| 缺录行 | 阻断 | 列出缺失行，可「仅导出已录部分」 |
| 未分配说话人 | 阻断 | 提示先去画本页处理 |
| 孤儿片段 | 警告 | 列出 |
| take 削波标记 | 警告 | 可重录 |
| 片段过短/过长（<0.2s / >60s） | 警告 | 列出 |
| 章节时长异常（< 10 s 或 > 2 h） | 警告 | 可能是对轨错误 |
| 磁盘空间不足 | 阻断 | 提示需要多少空间 |
| 输出文件已存在 | 提示 | 覆盖 / 跳过 / 改名 |

### 6.2 渲染后实测质检

| 检查 | 方法 | 阈值 | 动作 |
|------|------|------|------|
| 目标响度偏差 | `loudnorm print_format=json` 或 `ebur128` | \|Δ\| ≤ 1.0 LU | 超阈值 → 自动微调一次 → 仍超则警告 |
| 真峰 | 同上 | ≤ TP 目标 | 超过 → 再降 0.5 dB 重渲一次 |
| 章间响度差 | 逐章对比 | ≤ 1.5 LU | 超出 → 警告（听感不齐） |
| 整章静音 | 全段 RMS | < -60 dBFS | **阻断**（渲染失败） |
| 异常长静音 | 扫描 | 单段 > 10 s 且非头尾 | 警告 |
| 时长一致性 | 成品 vs 预期 | 偏差 ≤ 1 s | 警告 |
| 削波 | `astats` 的 `Flat factor` / 峰值 | 连续削波 > 0 | 警告 |
| 文件可播放性 | `ffprobe` 能读出时长与编码 | 失败 | **阻断**（该章标记失败） |

## 7. 章首标题念白（FR-6.4，1.0 占位）

| 方式 | 1.0 | 3.0 |
|------|-----|-----|
| 人工录制 | 在画本里加一行「章节标题」由旁白配音员录 | 同 |
| 不念 | 直接进正文 | 同 |
| AI 生成（TTS） | 不实现 | TTS provider 接入后自动生成 |

**1.0 实现**：「念标题」时，自动在画本章首插入一个虚拟画本行（`kind='narration'`，标记 `is_title=1`），参与录音与对轨，从而无需特殊处理。

## 8. 试听与预览

| 场景 | 方式 |
|------|------|
| 混音前试听单片段 | 渲染进程 Web Audio 播放（`13` §6.1） |
| 混音后试听 | 优先用真实渲染（`process.preview` 渲染前 30 秒或指定章节），保证与成品一致 |
| 长章节预览 | 只渲前 30 秒 + 中间 15 秒 + 末尾 15 秒（拼接快速预览，每段之间提示「跳过 X」） |
| 导出后试听 | 直接播放成品文件（`ns-media://` 或系统默认播放器） |

> **必须强调**：播放器试听（Web Audio）与 ffmpeg 渲染结果**可能不一致**（尤其 ducking 与响度）。因此「渲染预览」是正确的验证手段，UI 上要把这点讲清楚，不要让用户以为试听好就万事大吉。

## 11. 异常与边界

| 场景 | 处理 |
|------|------|
| M4B 合并失败（章节数过多） | 提示按卷拆分；提供「按 N 章一卷」自动拆分 |
| 某章渲染失败 | 不中断整本；记录失败；M4B 阶段询问「跳过失败章继续 / 中止」 |
| ffmpeg 被杀（用户关机） | 临时文件留待启动清理；`export_jobs` 标记 `interrupted`；重跑时续传 |
| 输出目录只读/无权限 | 提前检测并提示更换目录 |
| 输出文件被占用（正在播放） | 提示「文件被其他程序占用，请关闭后重试」 |
| 响度测量结果异常（`input_i = -inf`） | 说明音频近乎静音 → 阻断该章，提示检查对轨 |
| 封面格式不支持 | 提示支持的格式（JPEG/PNG）并忽略封面继续 |
| 目标 LUFS 与真峰冲突（如 -14 LUFS + -1 dBTP 且素材很响） | 限幅会削峰 → 提示「可能导致轻微失真，建议降低目标响度」 |
| 磁盘空间不足（渲染中间文件很大） | 预估空间（混音中间 WAV ≈ 时长 × 288 KB/s）并提前校验 |

## 12. 测试要点

| 测试 | 用例 |
|------|------|
| 混音正确性 | 3 轨各含 5 个片段，验证输出中每个片段出现在预期时间点（用能量包络定位） |
| `normalize=0` | 对照测试：加与不加的音量差异（应为 0 dB 差异） |
